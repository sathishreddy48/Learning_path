How to use this site
  • Start with Foundations & Complexity. It is not a pattern — it is how to run the 45 minutes, what the Big-O numbers mean when you say them out loud, what every collection costs, and how to read a problem statement and know which of the six pattern pages it belongs to.
  • Then take the Patterns menu in order. Arrays and hashing carry the techniques the later pages assume.
  • Every code sample has a C# | Python tab bar. Switch tabs to see the same algorithm in the other language; Copy grabs whatever tab is showing.
  • Each section ends with a Practice box. Solve it on paper or in an editor before reading the solution — recognition is not the same as recall.
  • Interview angle boxes call out the follow-up question an interviewer reaches for once your first solution works.
  • Visited state lives in your browser only, separate from the C# and System Design sites.

Topics

Suggested order

Go in sidebar order: foundations (1) → the linear patterns (2–4) → search & sort (5) → hierarchies and graphs (6–7). If you are short on time, the highest-yield pages are Arrays/Windows, Hashing and Trees — those three cover most of what gets asked. Graphs is the one people skip and then get caught by.
