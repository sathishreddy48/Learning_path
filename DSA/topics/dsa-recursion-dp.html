From recursion to DP: the three-step conversion

Dynamic programming is not a separate skill from recursion — it is recursion with the repeated work deleted. Almost every DP problem in an interview can be reached by the same three steps, in order, out loud:

  1. Write the brute-force recursion. Define what the function means in one sentence, then write it. Do not think about efficiency yet. If you cannot state the meaning of F(i) in English, you do not have a recurrence, and no amount of table-filling will rescue that.
  2. Add a memo. Cache on the arguments that vary. This alone takes exponential to polynomial and is usually enough to pass. It is also the step you should write first in an interview, because it is the one least likely to contain a bug.
  3. Turn it into a table (only if asked, or if recursion depth is a risk). Iterate the states in an order where every dependency is already computed, then collapse the table to the one or two rows you actually read.

The whole method hangs on naming the state: the smallest set of values that fully determines the answer from here on. Get the state right and the recurrence usually writes itself; get it wrong and nothing works. "Fibonacci" is the degenerate example, but it shows the mechanics exactly.

// Step 1 — brute force. Meaning: Fib(n) is the nth Fibonacci number.
// O(2^n): Fib(n-2) is recomputed by both branches, all the way down.
static long FibSlow(int n) => n < 2 ? n : FibSlow(n - 1) + FibSlow(n - 2);

// Step 2 — memoise. One cache entry per distinct argument, so each state is
// computed once: O(n) time, O(n) space. This is the step to write first.
static long FibMemo(int n, Dictionary<int, long>? memo = null)
{
    memo ??= new Dictionary<int, long>();
    if (n < 2) return n;                                  // base case
    if (memo.TryGetValue(n, out var hit)) return hit;      // already solved
    return memo[n] = FibMemo(n - 1, memo) + FibMemo(n - 2, memo);
}

// Step 3 — tabulate. Same recurrence, computed bottom-up so no call stack.
static long FibTable(int n)
{
    if (n < 2) return n;
    var dp = new long[n + 1];
    dp[1] = 1;
    for (int i = 2; i <= n; i++) dp[i] = dp[i - 1] + dp[i - 2];
    return dp[n];
}

// Step 3b — collapse. The loop only ever reads the last two cells, so the
// array is not needed at all: O(1) space.
static long Fib(int n)
{
    long prev = 0, cur = 1;
    if (n < 2) return n;
    for (int i = 2; i <= n; i++) (prev, cur) = (cur, prev + cur);
    return cur;
}
from functools import lru_cache

# Step 1 — brute force. O(2^n).
def fib_slow(n: int) -> int:
    return n if n < 2 else fib_slow(n - 1) + fib_slow(n - 2)

# Step 2 — memoise. In Python the decorator does it for you, which is worth
# knowing but worth writing by hand at least once so you can explain it.
@lru_cache(maxsize=None)
def fib_memo(n: int) -> int:
    return n if n < 2 else fib_memo(n - 1) + fib_memo(n - 2)

def fib_memo_manual(n: int, memo: dict[int, int] | None = None) -> int:
    if memo is None:
        memo = {}
    if n < 2:
        return n
    if n in memo:
        return memo[n]
    memo[n] = fib_memo_manual(n - 1, memo) + fib_memo_manual(n - 2, memo)
    return memo[n]

# Step 3 — tabulate.
def fib_table(n: int) -> int:
    if n < 2:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

# Step 3b — collapse to O(1) space.
def fib(n: int) -> int:
    prev, cur = 0, 1
    if n < 2:
        return n
    for _ in range(2, n + 1):
        prev, cur = cur, prev + cur
    return cur
The four questions that define a DP
  • State — what do the parameters mean? Write the sentence: "dp[i][j] is the minimum cost to …".
  • Transition — how does a state depend on smaller ones? This is the recurrence.
  • Base case — the smallest states, answered without recursion. Most DP bugs live here.
  • Answer — which cell is the result? Not always dp[n]; sometimes it is the max over a whole row.

Interview angle

Say the three steps out loud as you do them — "brute force first, then I will memoise, then collapse the space if you want it" — because the interviewer is grading your method, and the method is the thing that transfers to the problem they ask next. The single highest-value sentence you can produce is the state definition; if you say "dp[i] is the best I can do considering only the first i items" and it is correct, a strong interviewer will often help you with the rest. Also be ready for "what is the complexity?" — the answer is always number of states × work per state, and saying it in that form shows you understand why memoisation helped rather than that you memorised a bound.

Practice
  • Write Fibonacci all four ways from memory, then state the complexity of each in states × work-per-state form.
  • Climbing stairs with steps of 1 or 2, then generalise to a given set of step sizes.
  • Explain why memoisation is correct — what property must the subproblems have? (Name both overlapping subproblems and optimal substructure.)

One-dimensional DP: the decision at each index

The first real family. You walk an array once; at each index you make a small decision, and the state is "the best answer considering the prefix that ends here". Everything below is the same shape with a different transition.

House robber is the archetype: you cannot take two adjacent elements. At index i you either take i (and add the best from i-2) or skip it (and keep the best from i-1). That one sentence is the recurrence.

// dp[i] = max loot considering houses 0..i-1.
// Collapsed: only dp[i-1] and dp[i-2] are ever read.
static int Rob(int[] nums)
{
    int take = 0, skip = 0;                    // best ending here / before here
    foreach (var n in nums)
        (take, skip) = (skip + n, Math.Max(skip, take));
    return Math.Max(take, skip);
}

// dp[i] = number of ways to decode s[0..i-1]. Base: dp[0] = 1, the empty
// string has exactly one decoding. The "1" here is the classic trap.
static int NumDecodings(string s)
{
    int prev2 = 1, prev1 = s[0] == '0' ? 0 : 1;
    for (int i = 1; i < s.Length; i++)
    {
        int cur = 0;
        if (s[i] != '0') cur += prev1;                       // one-digit step
        int two = (s[i - 1] - '0') * 10 + (s[i] - '0');
        if (two >= 10 && two <= 26) cur += prev2;            // two-digit step
        (prev2, prev1) = (prev1, cur);
    }
    return prev1;
}

// Maximum subarray sum (Kadane). dp[i] = best sum of a subarray ENDING at i,
// which is why it is DP and not a sliding window: the window may not shrink.
static int MaxSubArray(int[] nums)
{
    int best = nums[0], endingHere = nums[0];
    for (int i = 1; i < nums.Length; i++)
    {
        endingHere = Math.Max(nums[i], endingHere + nums[i]);   // extend or restart
        best = Math.Max(best, endingHere);
    }
    return best;
}

// Word break: dp[i] = can s[0..i-1] be segmented?
static bool WordBreak(string s, IList<string> dict)
{
    var words = new HashSet<string>(dict);
    var dp = new bool[s.Length + 1];
    dp[0] = true;
    for (int i = 1; i <= s.Length; i++)
        for (int j = 0; j < i; j++)
            if (dp[j] && words.Contains(s[j..i])) { dp[i] = true; break; }
    return dp[s.Length];
}
def rob(nums: list[int]) -> int:
    take = skip = 0                      # best ending here / before here
    for n in nums:
        take, skip = skip + n, max(skip, take)
    return max(take, skip)

def num_decodings(s: str) -> int:
    prev2, prev1 = 1, 0 if s[0] == "0" else 1
    for i in range(1, len(s)):
        cur = 0
        if s[i] != "0":
            cur += prev1                                  # one-digit step
        if 10 <= int(s[i - 1 : i + 1]) <= 26:
            cur += prev2                                  # two-digit step
        prev2, prev1 = prev1, cur
    return prev1

def max_sub_array(nums: list[int]) -> int:
    best = ending_here = nums[0]
    for n in nums[1:]:
        ending_here = max(n, ending_here + n)             # extend or restart
        best = max(best, ending_here)
    return best

def word_break(s: str, word_dict: list[str]) -> bool:
    words = set(word_dict)
    dp = [False] * (len(s) + 1)
    dp[0] = True
    for i in range(1, len(s) + 1):
        for j in range(i):
            if dp[j] and s[j:i] in words:
                dp[i] = True
                break
    return dp[len(s)]
The circular variant

"House robber II" puts the houses in a circle, so the first and last are now adjacent. Do not try to patch the recurrence — run the linear solver twice, once on nums[0..n-2] and once on nums[1..n-1], and take the better. Reducing a variant to the solved case is a stronger answer than a new recurrence, and it generalises: a lot of "circular" problems are two linear problems.

Interview angle

Kadane's algorithm is the one to be careful with, because it looks like a sliding window and is not — a window assumes shrinking from the left is valid, and here it is not, since dropping a prefix can only be decided by comparing sums. Say "dp[i] is the best subarray ending at i" and the confusion disappears. Expect two follow-ups: return the indices rather than the sum (keep a start pointer that resets whenever you restart), and handle an all-negative array (initialising best to 0 instead of nums[0] is the standard bug, and it is the case they will test). For decode-ways, be ready to explain why dp[0] = 1.

Practice
  • House robber, then the circular variant, then the binary-tree variant (which is DP on a tree — see the last section).
  • Maximum subarray, returning the indices; then maximum product subarray, where you must track the minimum too and say why.
  • Decode ways, getting every zero case right: leading zero, "30", "100", "101".
  • Word break, then word break II which returns every segmentation — note where it stops being DP and becomes backtracking.

Two sequences: LCS, edit distance and the grid

When the input is two sequences, the state is almost always a pair of prefix lengths: dp[i][j] is the answer for the first i of one and the first j of the other. That gives an (m+1) × (n+1) grid, the extra row and column being the empty-prefix base cases — which is the whole reason this family is written as a table rather than fought index-by-index.

Every problem in the family differs only in what happens at a cell. Learn the grid once and you get LCS, edit distance, longest common substring, shortest common supersequence and string interleaving for free.

// Longest common SUBSEQUENCE (not substring: gaps allowed).
// dp[i,j] = LCS length of a[0..i-1] and b[0..j-1].
static int Lcs(string a, string b)
{
    var dp = new int[a.Length + 1, b.Length + 1];      // row/col 0 = empty prefix = 0
    for (int i = 1; i <= a.Length; i++)
        for (int j = 1; j <= b.Length; j++)
            dp[i, j] = a[i - 1] == b[j - 1]
                ? dp[i - 1, j - 1] + 1                  // match: consume both
                : Math.Max(dp[i - 1, j], dp[i, j - 1]); // else: drop one, best of two
    return dp[a.Length, b.Length];
}

// Edit distance (Levenshtein): insert, delete or replace, cost 1 each.
static int EditDistance(string a, string b)
{
    var dp = new int[a.Length + 1, b.Length + 1];
    for (int i = 0; i <= a.Length; i++) dp[i, 0] = i;   // delete i chars
    for (int j = 0; j <= b.Length; j++) dp[0, j] = j;   // insert j chars
    for (int i = 1; i <= a.Length; i++)
        for (int j = 1; j <= b.Length; j++)
            dp[i, j] = a[i - 1] == b[j - 1]
                ? dp[i - 1, j - 1]                      // free match
                : 1 + Math.Min(dp[i - 1, j - 1],        // replace
                      Math.Min(dp[i - 1, j],            // delete from a
                               dp[i, j - 1]));          // insert into a
    return dp[a.Length, b.Length];
}

// Longest common SUBSTRING — contiguous, so a mismatch resets to 0 and the
// answer is the max anywhere in the table, not the corner.
static int LongestCommonSubstring(string a, string b)
{
    var dp = new int[a.Length + 1, b.Length + 1];
    int best = 0;
    for (int i = 1; i <= a.Length; i++)
        for (int j = 1; j <= b.Length; j++)
            if (a[i - 1] == b[j - 1])
                best = Math.Max(best, dp[i, j] = dp[i - 1, j - 1] + 1);
    return best;
}

// Space collapse: each row reads only the row above, so two rows suffice.
static int LcsTwoRows(string a, string b)
{
    var prev = new int[b.Length + 1];
    var cur = new int[b.Length + 1];
    for (int i = 1; i <= a.Length; i++)
    {
        for (int j = 1; j <= b.Length; j++)
            cur[j] = a[i - 1] == b[j - 1] ? prev[j - 1] + 1 : Math.Max(prev[j], cur[j - 1]);
        (prev, cur) = (cur, prev);
        Array.Clear(cur);                               // stale row must be wiped
    }
    return prev[b.Length];
}
def lcs(a: str, b: str) -> int:
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1          # match: consume both
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[len(a)][len(b)]

def edit_distance(a: str, b: str) -> int:
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(len(a) + 1):
        dp[i][0] = i                                     # delete i chars
    for j in range(len(b) + 1):
        dp[0][j] = j                                     # insert j chars
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]              # free match
            else:
                dp[i][j] = 1 + min(dp[i - 1][j - 1],     # replace
                                   dp[i - 1][j],         # delete
                                   dp[i][j - 1])         # insert
    return dp[len(a)][len(b)]

def longest_common_substring(a: str, b: str) -> int:
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    best = 0
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:                     # mismatch resets to 0
                dp[i][j] = dp[i - 1][j - 1] + 1
                best = max(best, dp[i][j])
    return best

def lcs_two_rows(a: str, b: str) -> int:
    prev = [0] * (len(b) + 1)
    for i in range(1, len(a) + 1):
        cur = [0] * (len(b) + 1)
        for j in range(1, len(b) + 1):
            cur[j] = prev[j - 1] + 1 if a[i - 1] == b[j - 1] else max(prev[j], cur[j - 1])
        prev = cur
    return prev[len(b)]

Interview angle

This is the family most likely to appear in a Google or Meta loop, and the discriminator is whether you can derive the cell rule rather than recall it. Narrate one cell: "I am looking at a[i-1] and b[j-1]; if they match I have nothing to decide, so I take the diagonal; if not, my options are …". Then expect the two standard follow-ups. Reconstruct the answer, not just its length — walk backwards from the corner, moving diagonally on a match and otherwise towards the larger neighbour, and note that this needs the full table, so it is incompatible with the two-row collapse. Reduce the space — two rows, which you should offer before being asked. If they push to O(min(m,n)) space and reconstruction, that is Hirschberg's algorithm; naming it is enough, nobody expects you to code it.

Practice
  • Edit distance, then reconstruct the actual edit script from the table.
  • Longest palindromic subsequence — solve it by calling LCS on the string and its reverse, and explain why that works.
  • Distinct subsequences (how many times does t appear as a subsequence of s) — derive the cell rule yourself.
  • Interleaving string: given a, b, c, is c an interleaving? Same grid, different meaning.

Knapsack: the one shape behind half of all DP questions

If a problem gives you a collection of items and a budget — weight, capacity, a target sum, an amount of money — it is a knapsack, and the only real question is how many times may you use each item. That single distinction decides the direction of one loop, and getting it backwards is the most common DP bug there is.

  • 0/1 knapsack — each item at most once. Iterate capacity downwards, so a cell never sees this item's own update.
  • Unbounded knapsack — each item any number of times. Iterate capacity upwards, so a cell deliberately reuses this item.

Subset-sum, partition-equal-subset and "target sum" are 0/1 knapsack with boolean or counting cells. Coin change (fewest coins) and coin change II (number of ways) are unbounded.

// --- 0/1: each item once. Note the DOWNWARD capacity loop. --------------
static int Knapsack01(int[] weights, int[] values, int capacity)
{
    var dp = new int[capacity + 1];              // dp[c] = best value at capacity c
    for (int i = 0; i < weights.Length; i++)
        for (int c = capacity; c >= weights[i]; c--)       // ← downwards
            dp[c] = Math.Max(dp[c], dp[c - weights[i]] + values[i]);
    return dp[capacity];
}

// Partition into two equal-sum halves = subset-sum for total/2, 0/1 shaped.
static bool CanPartition(int[] nums)
{
    int total = nums.Sum();
    if (total % 2 != 0) return false;                       // odd total: impossible
    int target = total / 2;
    var dp = new bool[target + 1];
    dp[0] = true;                                           // empty subset
    foreach (var n in nums)
        for (int c = target; c >= n; c--)                   // ← downwards
            dp[c] |= dp[c - n];
    return dp[target];
}

// --- Unbounded: reuse allowed. Note the UPWARD capacity loop. -----------
// Fewest coins to make the amount, or -1.
static int CoinChange(int[] coins, int amount)
{
    var dp = new int[amount + 1];
    Array.Fill(dp, int.MaxValue);
    dp[0] = 0;                                              // zero coins for zero
    foreach (var coin in coins)
        for (int c = coin; c <= amount; c++)                // ← upwards
            if (dp[c - coin] != int.MaxValue)
                dp[c] = Math.Min(dp[c], dp[c - coin] + 1);
    return dp[amount] == int.MaxValue ? -1 : dp[amount];
}

// Number of WAYS to make the amount as a combination (order irrelevant).
// Coins outside, amount inside — swap the loops and you count permutations.
static int CoinChangeWays(int[] coins, int amount)
{
    var dp = new long[amount + 1];
    dp[0] = 1;
    foreach (var coin in coins)                             // ← coins outermost
        for (int c = coin; c <= amount; c++)
            dp[c] += dp[c - coin];
    return (int)dp[amount];
}

// Same cells, loops swapped: now ORDER MATTERS, so this counts permutations
// ("combination sum IV"). The nesting is the entire difference.
static int CountPermutations(int[] nums, int target)
{
    var dp = new long[target + 1];
    dp[0] = 1;
    for (int c = 1; c <= target; c++)                       // ← target outermost
        foreach (var n in nums)
            if (c >= n) dp[c] += dp[c - n];
    return (int)dp[target];
}
# --- 0/1: each item once. DOWNWARD capacity loop. -----------------------
def knapsack_01(weights: list[int], values: list[int], capacity: int) -> int:
    dp = [0] * (capacity + 1)
    for w, v in zip(weights, values):
        for c in range(capacity, w - 1, -1):          # ← downwards
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[capacity]

def can_partition(nums: list[int]) -> bool:
    total = sum(nums)
    if total % 2:
        return False
    target = total // 2
    dp = [False] * (target + 1)
    dp[0] = True                                      # empty subset
    for n in nums:
        for c in range(target, n - 1, -1):            # ← downwards
            dp[c] = dp[c] or dp[c - n]
    return dp[target]

# --- Unbounded: reuse allowed. UPWARD capacity loop. --------------------
def coin_change(coins: list[int], amount: int) -> int:
    INF = float("inf")
    dp = [INF] * (amount + 1)
    dp[0] = 0
    for coin in coins:
        for c in range(coin, amount + 1):             # ← upwards
            dp[c] = min(dp[c], dp[c - coin] + 1)
    return -1 if dp[amount] == INF else dp[amount]

def coin_change_ways(coins: list[int], amount: int) -> int:
    dp = [0] * (amount + 1)
    dp[0] = 1
    for coin in coins:                                # ← coins outermost
        for c in range(coin, amount + 1):
            dp[c] += dp[c - coin]
    return dp[amount]

# Loops swapped: order now matters, so this counts permutations.
def count_permutations(nums: list[int], target: int) -> int:
    dp = [0] * (target + 1)
    dp[0] = 1
    for c in range(1, target + 1):                    # ← target outermost
        for n in nums:
            if c >= n:
                dp[c] += dp[c - n]
    return dp[target]
The two loop rules, and why they are the rules

In the collapsed one-array form, dp[c - w] is either "before this item was considered" or "after", and the loop direction is what decides which.

  • Capacity downwards → 0/1. dp[c - w] is still from the previous item's row, so the item is used at most once.
  • Capacity upwards → unbounded. dp[c - w] may already include this item, so it is reused freely.
  • Items outer, capacity inner → combinations (order irrelevant: 1+2 and 2+1 are one answer).
  • Capacity outer, items inner → permutations (order matters: they are two answers).

Four lines, and between them they cover coin change, coin change II, combination sum IV, partition and target sum. Memorise the two axes rather than the five problems.

Interview angle

The strongest thing you can do here is name the reduction before you write anything: "this is 0/1 knapsack with the values equal to the weights, so it is subset-sum for half the total." That one sentence usually earns the problem. Then state the complexity honestly as O(n × capacity) and say the word pseudo-polynomial — it is polynomial in the capacity's value, not in its number of bits, which is why subset-sum is NP-complete and this table is not a contradiction. Interviewers at Google and Amazon do ask that, and it separates people who understand the bound from people who recite it. If asked for the chosen items rather than the optimum, you need the full 2-D table to walk back through.

Practice
  • Partition equal subset sum, then "target sum" (assign ± to each number) — show it is the same problem after one algebraic step.
  • Coin change and coin change II back to back, and say out loud why the loop nesting differs.
  • Combination sum IV, and explain why it is not coin change II.
  • 0/1 knapsack returning the selected items, which forces the 2-D table back.

Longest increasing subsequence, and the O(n log n) upgrade

LIS earns its own section because it is asked constantly, it has a quadratic solution everybody knows and an O(n log n) solution that is a genuine discriminator, and a surprising number of problems reduce to it once you sort the input the right way.

The O(n²) version is plain 1-D DP: dp[i] is the length of the longest increasing subsequence ending at i. The O(n log n) version keeps a different thing entirely — tails[k] is the smallest possible tail of an increasing subsequence of length k+1 — and that array is sorted, so binary search applies. Be clear that tails is not itself the answer subsequence; it only has the right length.

// O(n^2): dp[i] = LIS length ending at i. Easy to explain, easy to extend.
static int LisQuadratic(int[] nums)
{
    var dp = new int[nums.Length];
    Array.Fill(dp, 1);
    int best = nums.Length == 0 ? 0 : 1;
    for (int i = 1; i < nums.Length; i++)
    {
        for (int j = 0; j < i; j++)
            if (nums[j] < nums[i]) dp[i] = Math.Max(dp[i], dp[j] + 1);
        best = Math.Max(best, dp[i]);
    }
    return best;
}

// O(n log n): tails[k] = smallest tail of an increasing subsequence of
// length k+1. Kept sorted by construction, so binary search for the slot.
static int Lis(int[] nums)
{
    var tails = new List<int>();
    foreach (var n in nums)
    {
        int lo = 0, hi = tails.Count;
        while (lo < hi)                      // lower_bound: first tail >= n
        {
            int mid = lo + (hi - lo) / 2;
            if (tails[mid] < n) lo = mid + 1; else hi = mid;
        }
        if (lo == tails.Count) tails.Add(n); // extends the longest run
        else tails[lo] = n;                  // a smaller tail for that length
    }
    return tails.Count;
}
// For a NON-DECREASING subsequence, make the probe 'tails[mid] <= n'
// (upper_bound) — a one-character change that is easy to get wrong.

// Reduction: Russian-doll envelopes. Sort by width ascending, and by height
// DESCENDING within equal widths so same-width pairs can never nest; then the
// answer is just LIS over the heights.
static int MaxEnvelopes(int[][] envelopes)
{
    Array.Sort(envelopes, (a, b) => a[0] == b[0] ? b[1] - a[1] : a[0] - b[0]);
    return Lis(envelopes.Select(e => e[1]).ToArray());
}
def lis_quadratic(nums: list[int]) -> int:
    if not nums:
        return 0
    dp = [1] * len(nums)
    for i in range(1, len(nums)):
        for j in range(i):
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)

from bisect import bisect_left, bisect_right

def lis(nums: list[int]) -> int:
    tails: list[int] = []            # tails[k] = smallest tail of length k+1
    for n in nums:
        i = bisect_left(tails, n)    # bisect_right for non-decreasing
        if i == len(tails):
            tails.append(n)          # extends the longest run
        else:
            tails[i] = n             # a smaller tail for that length
    return len(tails)

def max_envelopes(envelopes: list[list[int]]) -> int:
    # width ascending, height DESCENDING within a width so equal widths
    # cannot nest; then LIS on the heights.
    envelopes.sort(key=lambda e: (e[0], -e[1]))
    return lis([e[1] for e in envelopes])
Problems that are LIS after one sort
  • Russian doll envelopes / maximum height by stacking cuboids — sort one dimension, LIS the other.
  • Minimum number of arrows / non-overlapping intervals — the greedy complement of the same structure.
  • Longest chain of pairs — sort by second element, then greedily extend; the greedy is provably optimal here, which is worth knowing because it is faster than LIS.
  • Minimum deletions to sort — n − LIS(n), a one-line reduction that often surprises people.
Interview angle

Write the O(n²) version first and say "that is quadratic, and there is an O(n log n) method if you want it" — offering the upgrade without being asked reads much better than being pushed to it. If you do write the fast version, the thing being graded is whether you can state what tails holds; "it is the smallest tail for each length, so it stays sorted" is the sentence. Be honest about its limitation: it gives the length but not the subsequence, and recovering the actual subsequence needs a parent-index array alongside it. The follow-up to expect is count the number of longest increasing subsequences, which the fast version cannot do at all — you go back to the quadratic DP and carry a count per index.

Practice
  • Write both versions, then extend the quadratic one to return the subsequence.
  • Number of longest increasing subsequences — and explain why you had to abandon the O(n log n) form.
  • Russian doll envelopes, and justify the descending tiebreak on height.
  • Longest bitonic subsequence (increases then decreases) — run LIS forwards and backwards and combine.

Grid DP: paths, costs and the obstacle cases

A grid is already a table, so these are the easiest DP problems to set up and the easiest to get wrong at the edges. The state is the cell; the transition looks only at the neighbours you are allowed to arrive from, which for "right and down only" means the cell above and the cell to the left. The whole difficulty is the first row and first column.

Note that these are DP precisely because movement is restricted to one direction per axis, which makes the dependency graph acyclic. The moment a problem lets you move in all four directions with weights, there is no fill order and it stops being DP — that is Dijkstra, and reaching for a table there is a real mistake.

// Unique paths, moving only right and down. dp[c] = ways to reach this cell.
// One row suffices: dp[c] += dp[c-1] IS the "from above + from the left" rule.
static int UniquePaths(int m, int n)
{
    var dp = new int[n];
    Array.Fill(dp, 1);                       // first row: exactly one way each
    for (int r = 1; r < m; r++)
        for (int c = 1; c < n; c++)
            dp[c] += dp[c - 1];              // old dp[c] = above, dp[c-1] = left
    return dp[n - 1];
}

// With obstacles: a blocked cell contributes zero ways.
static int UniquePathsWithObstacles(int[][] grid)
{
    int n = grid[0].Length;
    var dp = new int[n];
    dp[0] = grid[0][0] == 1 ? 0 : 1;
    for (int r = 0; r < grid.Length; r++)
        for (int c = 0; c < n; c++)
            if (grid[r][c] == 1) dp[c] = 0;             // wall: unreachable
            else if (c > 0) dp[c] += dp[c - 1];
    return dp[n - 1];
}

// Minimum path sum. Same shape, min instead of sum, and the edges are
// cumulative rather than 1 — this is where the off-by-ones live.
static int MinPathSum(int[][] grid)
{
    int rows = grid.Length, cols = grid[0].Length;
    var dp = new int[cols];
    dp[0] = grid[0][0];
    for (int c = 1; c < cols; c++) dp[c] = dp[c - 1] + grid[0][c];   // first row
    for (int r = 1; r < rows; r++)
    {
        dp[0] += grid[r][0];                                          // first col
        for (int c = 1; c < cols; c++)
            dp[c] = Math.Min(dp[c], dp[c - 1]) + grid[r][c];
    }
    return dp[cols - 1];
}

// Largest square of 1s: dp[r,c] = side of the largest square whose
// BOTTOM-RIGHT corner is (r,c). Three neighbours, limited by the smallest.
static int MaximalSquare(char[][] m)
{
    int rows = m.Length, cols = m[0].Length, best = 0;
    var dp = new int[rows + 1, cols + 1];
    for (int r = 1; r <= rows; r++)
        for (int c = 1; c <= cols; c++)
            if (m[r - 1][c - 1] == '1')
                best = Math.Max(best, dp[r, c] =
                    1 + Math.Min(dp[r - 1, c - 1], Math.Min(dp[r - 1, c], dp[r, c - 1])));
    return best * best;
}
def unique_paths(m: int, n: int) -> int:
    dp = [1] * n                              # first row: one way each
    for _ in range(1, m):
        for c in range(1, n):
            dp[c] += dp[c - 1]                # above + left
    return dp[n - 1]

def unique_paths_with_obstacles(grid: list[list[int]]) -> int:
    n = len(grid[0])
    dp = [0] * n
    dp[0] = 0 if grid[0][0] == 1 else 1
    for row in grid:
        for c in range(n):
            if row[c] == 1:
                dp[c] = 0                     # wall: unreachable
            elif c > 0:
                dp[c] += dp[c - 1]
    return dp[n - 1]

def min_path_sum(grid: list[list[int]]) -> int:
    rows, cols = len(grid), len(grid[0])
    dp = [0] * cols
    dp[0] = grid[0][0]
    for c in range(1, cols):                  # first row
        dp[c] = dp[c - 1] + grid[0][c]
    for r in range(1, rows):
        dp[0] += grid[r][0]                   # first column
        for c in range(1, cols):
            dp[c] = min(dp[c], dp[c - 1]) + grid[r][c]
    return dp[cols - 1]

def maximal_square(m: list[list[str]]) -> int:
    rows, cols, best = len(m), len(m[0]), 0
    dp = [[0] * (cols + 1) for _ in range(rows + 1)]
    for r in range(1, rows + 1):
        for c in range(1, cols + 1):
            if m[r - 1][c - 1] == "1":
                dp[r][c] = 1 + min(dp[r - 1][c - 1], dp[r - 1][c], dp[r][c - 1])
                best = max(best, dp[r][c])
    return best * best
Interview angle

Two things get graded. First, the sentinel trick: padding the table with an extra zero row and column, as the maximal-square code does, deletes every edge case from the loop body, and saying "I will pad so the first row needs no special case" is a small, very legible signal of experience. Second, knowing when it is not DP — if the question lets you move in all four directions, the dependency graph has cycles, there is no valid fill order, and the answer is BFS (unit weights) or Dijkstra (weighted). Candidates who force a table onto a four-direction problem lose the question outright, so state the direction constraint back to the interviewer before you start filling anything.

Practice
  • Unique paths, then with obstacles, then with the grid padded so there is no special-casing in the loop.
  • Minimum path sum, then the variant where you may also move diagonally down-right.
  • Maximal square, then maximal rectangle — and notice it stops being grid DP and becomes a monotonic stack per row.
  • Triangle minimum path sum, solved bottom-up so no edge handling is needed at all.

Interval and partition DP: when the split point is the decision

The hardest common family, and the one with a recognisable signature: the state is a range dp[i][j], and the transition loops over every way to split or every element to handle last. That gives O(n²) states with O(n) work each, so O(n³), and the fill order must go by increasing range length — not by i — because a range depends on strictly shorter ranges.

The trick that unlocks burst-balloons-style problems is counter-intuitive and worth drilling: iterate over which element you deal with last, not first. Thinking first-to-last leaves the two sides coupled through a changing array; thinking last-to-first leaves two independent subranges with fixed boundaries.

// Longest palindromic subsequence: dp[i,j] over the range [i..j].
// Filled by increasing length so shorter ranges are ready.
static int LongestPalindromeSubseq(string s)
{
    int n = s.Length;
    var dp = new int[n, n];
    for (int i = 0; i < n; i++) dp[i, i] = 1;              // length 1
    for (int len = 2; len <= n; len++)                      // ← length outermost
        for (int i = 0; i + len - 1 < n; i++)
        {
            int j = i + len - 1;
            dp[i, j] = s[i] == s[j]
                ? (len == 2 ? 2 : dp[i + 1, j - 1] + 2)
                : Math.Max(dp[i + 1, j], dp[i, j - 1]);
        }
    return dp[0, n - 1];
}

// Burst balloons. dp[i,j] = best coins from the OPEN range (i, j), and k is
// the balloon burst LAST, so its neighbours are exactly i and j.
static int MaxCoins(int[] nums)
{
    var a = new int[nums.Length + 2];
    a[0] = a[^1] = 1;                                       // virtual 1s at the ends
    nums.CopyTo(a, 1);
    int n = a.Length;
    var dp = new int[n, n];
    for (int len = 2; len < n; len++)                       // open-range width
        for (int i = 0; i + len < n; i++)
        {
            int j = i + len;
            for (int k = i + 1; k < j; k++)                 // k bursts last
                dp[i, j] = Math.Max(dp[i, j],
                    dp[i, k] + a[i] * a[k] * a[j] + dp[k, j]);
        }
    return dp[0, n - 1];
}

// Matrix chain multiplication — the textbook interval DP. dims has n+1 entries
// for n matrices: matrix i is dims[i] x dims[i+1].
static int MatrixChain(int[] dims)
{
    int n = dims.Length - 1;
    var dp = new int[n, n];
    for (int len = 2; len <= n; len++)
        for (int i = 0; i + len - 1 < n; i++)
        {
            int j = i + len - 1;
            dp[i, j] = int.MaxValue;
            for (int k = i; k < j; k++)                     // split after k
                dp[i, j] = Math.Min(dp[i, j],
                    dp[i, k] + dp[k + 1, j] + dims[i] * dims[k + 1] * dims[j + 1]);
        }
    return dp[0, n - 1];
}

// Palindrome partitioning II: fewest cuts. Precompute palindromicity so the
// inner check is O(1), which is what makes the whole thing O(n^2).
static int MinCut(string s)
{
    int n = s.Length;
    var isPal = new bool[n, n];
    for (int i = n - 1; i >= 0; i--)
        for (int j = i; j < n; j++)
            isPal[i, j] = s[i] == s[j] && (j - i < 2 || isPal[i + 1, j - 1]);

    var cuts = new int[n];
    for (int j = 0; j < n; j++)
    {
        if (isPal[0, j]) { cuts[j] = 0; continue; }          // whole prefix is one
        cuts[j] = int.MaxValue;
        for (int i = 1; i <= j; i++)
            if (isPal[i, j]) cuts[j] = Math.Min(cuts[j], cuts[i - 1] + 1);
    }
    return cuts[n - 1];
}
def longest_palindrome_subseq(s: str) -> int:
    n = len(s)
    dp = [[0] * n for _ in range(n)]
    for i in range(n):
        dp[i][i] = 1
    for length in range(2, n + 1):                 # ← length outermost
        for i in range(n - length + 1):
            j = i + length - 1
            if s[i] == s[j]:
                dp[i][j] = 2 if length == 2 else dp[i + 1][j - 1] + 2
            else:
                dp[i][j] = max(dp[i + 1][j], dp[i][j - 1])
    return dp[0][n - 1]

def max_coins(nums: list[int]) -> int:
    a = [1] + nums + [1]                           # virtual 1s at the ends
    n = len(a)
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n):                     # open-range width
        for i in range(n - length):
            j = i + length
            for k in range(i + 1, j):              # k bursts LAST
                dp[i][j] = max(dp[i][j],
                               dp[i][k] + a[i] * a[k] * a[j] + dp[k][j])
    return dp[0][n - 1]

def matrix_chain(dims: list[int]) -> int:
    n = len(dims) - 1
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n + 1):
        for i in range(n - length + 1):
            j = i + length - 1
            dp[i][j] = min(
                dp[i][k] + dp[k + 1][j] + dims[i] * dims[k + 1] * dims[j + 1]
                for k in range(i, j)
            )
    return dp[0][n - 1]

def min_cut(s: str) -> int:
    n = len(s)
    is_pal = [[False] * n for _ in range(n)]
    for i in range(n - 1, -1, -1):
        for j in range(i, n):
            is_pal[i][j] = s[i] == s[j] and (j - i < 2 or is_pal[i + 1][j - 1])

    cuts = [0] * n
    for j in range(n):
        if is_pal[0][j]:
            cuts[j] = 0
            continue
        cuts[j] = min(cuts[i - 1] + 1 for i in range(1, j + 1) if is_pal[i][j])
    return cuts[n - 1]
The fill order is the bug

Range DP depends on shorter ranges, so a naive for i { for j } loop reads cells that have not been written yet and silently returns a wrong answer. Two orders are correct: iterate by increasing length (shown above — the clearest to explain), or iterate i descending and j ascending from i (shorter to write, as in the isPal precompute). Pick one and use it every time. If the recursion is easier to reason about, memoise instead — top-down gets the order right for free, which is a good reason to prefer it here specifically.

Interview angle

Interval DP is a senior-level signal; nobody expects burst balloons from a new graduate. The move that matters is saying "what if I decide which one is last?" out loud — if you reach for that reframing yourself, you have shown the insight even if the code does not finish. Be explicit about why first-to-last fails: bursting a balloon changes who is adjacent to whom, so the two halves are not independent subproblems, and DP needs them to be. State the complexity as O(n³) with O(n²) states, and if asked whether it can be improved, the honest answer is that Knuth's optimisation applies to some members of this family and not to burst balloons.

Practice
  • Longest palindromic subsequence, then minimum insertions to make a string a palindrome — one subtraction apart.
  • Palindrome partitioning II, and explain why precomputing palindromicity changes the overall complexity.
  • Burst balloons. Expect to need two attempts; the point is to internalise the last-not-first reframing.
  • Stone game / optimal strategy for a game — interval DP where the two players alternate, so the cell holds a score difference.

Bitmask DP and DP on trees

Two shapes worth recognising even if you rarely need to write them, because both are instantly identifiable from the constraints and both have a tell.

Bitmask DP: the tell is n ≤ 20-ish. A set of up to ~20 items fits in an int, so the state can be "which subset have I already used", giving O(2ⁿ · n) — fine at n = 20 (about 20 million), hopeless at n = 30. Travelling salesman, assignment problems and "partition into k equal subsets" all live here.

DP on trees: the tell is a tree input and a question about the whole structure. Each node's answer is computed from its children's answers, so the recursion is the fill order — a post-order traversal, no table needed. The standard shape returns a small tuple per node, typically "best including this node" and "best excluding it".

// --- Bitmask: travelling salesman, O(2^n · n^2). -----------------------
// dp[mask, i] = cheapest route visiting exactly '''mask''', currently at i.
static int Tsp(int[,] dist)
{
    int n = dist.GetLength(0), full = (1 << n) - 1;
    var dp = new int[1 << n, n];
    for (int m = 0; m < (1 << n); m++)
        for (int i = 0; i < n; i++) dp[m, i] = int.MaxValue / 2;
    dp[1, 0] = 0;                                     // start at city 0

    for (int mask = 1; mask <= full; mask++)
        for (int i = 0; i < n; i++)
        {
            if ((mask & (1 << i)) == 0) continue;      // i must be visited
            if (dp[mask, i] >= int.MaxValue / 2) continue;
            for (int j = 0; j < n; j++)
            {
                if ((mask & (1 << j)) != 0) continue;  // j must NOT be visited
                int next = mask | (1 << j);
                dp[next, j] = Math.Min(dp[next, j], dp[mask, i] + dist[i, j]);
            }
        }

    int best = int.MaxValue;
    for (int i = 1; i < n; i++) best = Math.Min(best, dp[full, i] + dist[i, 0]);
    return best;
}

// Useful bit idioms for these loops:
//   mask & (1 << i)        is i in the set?
//   mask | (1 << i)        add i
//   mask & (mask - 1)      drop the lowest set bit
//   BitOperations.PopCount((uint)mask)   how many are set
//   for (int s = mask; s > 0; s = (s - 1) & mask)   every submask of mask

// --- DP on a tree: house robber III. -----------------------------------
// Returns (rob this node, skip this node) for the subtree. One pass, O(n).
static int RobTree(TreeNode? root)
{
    var (rob, skip) = Solve(root);
    return Math.Max(rob, skip);

    static (int rob, int skip) Solve(TreeNode? node)
    {
        if (node is null) return (0, 0);
        var (lr, ls) = Solve(node.left);
        var (rr, rs) = Solve(node.right);
        return (node.val + ls + rs,                       // rob: children skipped
                Math.Max(lr, ls) + Math.Max(rr, rs));     // skip: children free
    }
}

// Tree diameter: the answer is a side effect of the depth computation.
static int Diameter(TreeNode? root)
{
    int best = 0;
    Depth(root);
    return best;

    int Depth(TreeNode? node)
    {
        if (node is null) return 0;
        int l = Depth(node.left), r = Depth(node.right);
        best = Math.Max(best, l + r);      // path THROUGH this node
        return 1 + Math.Max(l, r);         // depth reported UPWARDS
    }
}
# --- Bitmask: travelling salesman, O(2^n · n^2). -----------------------
def tsp(dist: list[list[int]]) -> int:
    n = len(dist)
    full = (1 << n) - 1
    INF = float("inf")
    dp = [[INF] * n for _ in range(1 << n)]
    dp[1][0] = 0                                   # start at city 0

    for mask in range(1, full + 1):
        for i in range(n):
            if not mask & (1 << i) or dp[mask][i] == INF:
                continue
            for j in range(n):
                if mask & (1 << j):                # j must not be visited
                    continue
                nxt = mask | (1 << j)
                dp[nxt][j] = min(dp[nxt][j], dp[mask][i] + dist[i][j])

    return min(dp[full][i] + dist[i][0] for i in range(1, n))

# Bit idioms:
#   mask & (1 << i)      is i in the set?
#   mask | (1 << i)      add i
#   mask & (mask - 1)    drop the lowest set bit
#   bin(mask).count("1") / int.bit_count(mask)   population count
#   submasks: s = mask
#             while s: ...; s = (s - 1) & mask

# --- DP on a tree: house robber III. -----------------------------------
def rob_tree(root) -> int:
    def solve(node) -> tuple[int, int]:           # (rob here, skip here)
        if node is None:
            return 0, 0
        lr, ls = solve(node.left)
        rr, rs = solve(node.right)
        return (node.val + ls + rs,               # rob: children skipped
                max(lr, ls) + max(rr, rs))        # skip: children free
    return max(solve(root))

def diameter(root) -> int:
    best = 0
    def depth(node) -> int:
        nonlocal best
        if node is None:
            return 0
        l, r = depth(node.left), depth(node.right)
        best = max(best, l + r)                   # path THROUGH this node
        return 1 + max(l, r)                      # depth reported UPWARDS
    depth(root)
    return best

Interview angle

Nobody will fault you for not producing a bitmask TSP, but they will notice if you miss what n ≤ 20 is telling you. Reading the constraint aloud and concluding "that is small enough for exponential, so I will think in subsets" is the entire signal — it is the same reasoning as the table above, and it is worth more than the code. For tree DP the thing to get right is the return-versus-record distinction, which the diameter code shows: you record the best path through the node into a running maximum, and you return the depth upwards. Those are two different quantities and conflating them is the classic bug. Say "I will return X and record Y" before writing the body.

Practice
  • Partition to k equal-sum subsets with n ≤ 16 — recognise the bitmask from the constraint.
  • House robber III, then binary tree maximum path sum — same return-versus-record shape.
  • Diameter of a tree, then diameter of an n-ary tree (track the best two child depths).
  • Count the number of ways to assign n tasks to n workers with a cost matrix — the assignment problem as bitmask DP.

Recognising DP — and telling it from greedy

By the time you have worked the families above, the recognition rules are short. A problem is DP when it asks for an optimum or a count over a space of choices, the choices interact (an early decision constrains a later one), and the same subproblem is reachable by more than one route. The wording gives it away: minimum cost to, maximum value of, how many ways, is it possible to, longest/shortest … such that.

It is not DP when a locally best choice is provably globally best — that is greedy, and it is faster. It is not DP when you need to enumerate all the solutions rather than count or optimise over them — that is backtracking. And it is not DP when the dependency graph has cycles, because then no fill order exists — that is a shortest-path problem.

The greedy-versus-DP line is the one interviewers probe, because candidates reach for greedy when it is wrong and for DP when it is unnecessary. Coin change is the standard illustration: with coins {1, 5, 10, 25} the greedy "take the largest that fits" is optimal, so you may be tempted to generalise it. With {1, 3, 4} and amount 6 greedy gives 4 + 1 + 1 = 3 coins and the optimum is 3 + 3 = 2. The lesson is procedural rather than factual: if you propose greedy, you owe an exchange argument; if you cannot produce one in a sentence, use DP.

A checklist for the room
  1. Say what the brute force is and what it costs. Always. Even if it is obviously terrible.
  2. Name the state in one English sentence, and write that sentence as a comment above the function.
  3. Write the recurrence, then the base cases — and sanity-check the base cases against n = 0 and n = 1.
  4. Memoise. Say "number of states times work per state" and give the complexity.
  5. Offer tabulation and the space collapse before being asked; implement whichever they want.
  6. Trace one small input by hand, out loud. This catches base-case bugs that staring at the code will not.
Interview angle

The single most common failure in a DP interview is not a wrong recurrence — it is silence. Candidates recognise "this is DP", then spend eight minutes trying to produce the final table in one shot and have nothing to show. Write the exponential recursion immediately; it is always short, it proves you understood the problem, and it is the thing you then improve in front of them. A memoised solution with a clearly stated state beats a half-finished optimal table every time. If you blank completely, fall back to the mechanical route: what is the last decision I make, and what do I need to know to make it? That question has produced the state for every problem on this page.

Practice
  • Take ten mixed problems and, without solving any of them, classify each as DP / greedy / backtracking / shortest-path and justify it in one sentence. Recognition is the bottleneck, not implementation.
  • Find a problem where greedy looks right and is not, and write the counterexample down — you will be asked for one.
  • Re-derive three solutions from this page a week from now from the state sentence alone, without rereading the code.
