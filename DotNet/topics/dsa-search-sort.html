Binary Search & Sorting

Binary search is the most-failed easy question in interviewing — not because the idea is hard but because the boundary conditions are, and people improvise them under pressure. Learn one template, prove it to yourself once, and never improvise again. The second half of the page is sorting: what the library does, when to write your own, and the two linear-time escapes.

Binary search

Halve the search space each step on anything monotonic — sorted arrays, but also “smallest x such that f(x) is true” (answer-space search). Off-by-one bugs are the whole difficulty; settle on one template. .NET has Array.BinarySearch and Python has bisect for the plain case.

// Template: lower bound (first index where a[i] >= target)
static int LowerBound(int[] a, int target)
{
    int lo = 0, hi = a.Length;              // hi is exclusive
    while (lo < hi)
    {
        int mid = lo + (hi - lo) / 2;         // avoids overflow
        if (a[mid] < target) lo = mid + 1; else hi = mid;
    }
    return lo;                              // == a.Length if none
}

// Exact search
static int Search(int[] a, int target)
{
    int i = LowerBound(a, target);
    return i < a.Length && a[i] == target ? i : -1;
}

// Rotated sorted array
static int SearchRotated(int[] a, int t)
{
    int lo = 0, hi = a.Length - 1;
    while (lo <= hi)
    {
        int mid = (lo + hi) / 2;
        if (a[mid] == t) return mid;
        if (a[lo] <= a[mid]) { if (a[lo] <= t && t < a[mid]) hi = mid - 1; else lo = mid + 1; }
        else                 { if (a[mid] < t && t <= a[hi]) lo = mid + 1; else hi = mid - 1; }
    }
    return -1;
}

// Answer-space search: minimum eating speed to finish piles in h hours
static int MinEatingSpeed(int[] piles, int h)
{
    int lo = 1, hi = piles.Max();
    while (lo < hi)
    {
        int k = lo + (hi - lo) / 2;
        long hours = piles.Sum(p => (long)Math.Ceiling(p / (double)k));
        if (hours <= h) hi = k; else lo = k + 1;
    }
    return lo;
}

Interview angle

The most common failure in the whole set is an off-by-one under pressure. Commit to one template — half-open [lo, hi) with while (lo < hi) — and use it every time rather than reasoning afresh. Always say the invariant out loud ("the answer is always in [lo, hi)") and always compute the midpoint as lo + (hi - lo) / 2; the (lo + hi) / 2 overflow is a real bug that sat in the JDK for two decades.

Lower bound, upper bound and Array.BinarySearch

Plain "find x" is the least useful form. What problems actually ask for is a boundary: the first index where a predicate becomes true, the first element ≥ x, the last element ≤ x, how many values fall in a range. Those are lower bound and upper bound, and once you have both, counting and range queries fall out.

lower_bound(x) is the first index with a[i] >= x; upper_bound(x) is the first with a[i] > x. The count of values equal to x is upper - lower, and the insertion point that keeps the array sorted is the lower bound.

// THE TEMPLATE. Half-open [lo, hi). Memorise this shape.
// Invariant: the answer, if it exists, is always in [lo, hi).
static int LowerBound(int[] a, int target)
{
    int lo = 0, hi = a.Length;                  // hi is EXCLUSIVE - a.Length, not -1
    while (lo < hi)                             // strict <, so it terminates
    {
        int mid = lo + (hi - lo) / 2;           // never (lo + hi) / 2: overflow
        if (a[mid] < target) lo = mid + 1;      // mid is too small: discard it
        else                 hi = mid;          // mid might be the answer: KEEP it
    }
    return lo;                                  // lo == hi == the first index >= target
}

static int UpperBound(int[] a, int target)
{
    int lo = 0, hi = a.Length;
    while (lo < hi)
    {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] <= target) lo = mid + 1;     // the ONLY difference: <= not <
        else                  hi = mid;
    }
    return lo;                                  // the first index > target
}
// Everything else is these two:
static bool Contains(int[] a, int x) { int i = LowerBound(a, x); return i < a.Length && a[i] == x; }
static int  CountOf (int[] a, int x) => UpperBound(a, x) - LowerBound(a, x);
static int  CountInRange(int[] a, int lo, int hi) => UpperBound(a, hi) - LowerBound(a, lo);
static int  LastAtMost(int[] a, int x) => UpperBound(a, x) - 1;      // -1 if none

// SEARCH RANGE - "first and last position of element in sorted array" is one call each
static int[] SearchRange(int[] a, int target)
{
    int first = LowerBound(a, target);
    if (first == a.Length || a[first] != target) return [-1, -1];
    return [first, UpperBound(a, target) - 1];
}

// THE PREDICATE FORM - the generalisation worth internalising. Any monotonic
// predicate (false, false, ..., false, true, ..., true) has a first-true index.
static int FirstTrue(int lo, int hi, Func<int, bool> predicate)
{
    while (lo < hi)
    {
        int mid = lo + (hi - lo) / 2;
        if (predicate(mid)) hi = mid;      // mid might be the first true
        else                lo = mid + 1;  // mid is false: discard it
    }
    return lo;                             // == hi, the first true (or hi if none)
}

Interview angle

Being asked for "the first and last position of an element in a sorted array" is really being asked whether you know lower and upper bound, and the elegant answer is one call each. The framing that impresses is the generalisation: every binary search is "find the first index where a monotonic predicate becomes true", which is why you only need one template. Know Array.BinarySearch's negative return convention (~result is the insertion point) and that with duplicates it returns an arbitrary match, not the first.

  • Use Array.BinarySearch's negative result to insert into a sorted list.

Binary search on the answer

The highest-value idea on this page, and the one that converts "hard" problems into easy ones. When a problem asks you to minimise a maximum or maximise a minimum, you often cannot compute the answer directly — but you can cheaply check "is a candidate answer feasible?", and feasibility is monotonic: if x works, everything larger works too.

That monotonicity is exactly what binary search needs. Search the answer space rather than the input, with a feasibility check as the predicate: O(log(range) × cost of the check).

The tells: "minimum largest…", "maximum smallest…", "the smallest capacity such that…", "can you finish in D days?", "split into k parts minimising the largest sum".

// KOKO EATING BANANAS - the canonical example.
// "What is the minimum eating speed k so that all piles are finished in h hours?"
// You cannot compute k directly. You CAN check a given k in O(n). And the check
// is monotonic: if speed k works, every speed above k works.
static int MinEatingSpeed(int[] piles, int h)
{
    bool CanFinish(int speed)
    {
        long hours = 0;
        foreach (var p in piles) hours += (p + speed - 1) / speed;   // ceil
        return hours <= h;
    }

    int lo = 1, hi = piles.Max();            // the answer is in [1, max pile]
    while (lo < hi)                          // the same template as always
    {
        int mid = lo + (hi - lo) / 2;
        if (CanFinish(mid)) hi = mid;        // feasible: maybe we can go slower
        else                lo = mid + 1;    // too slow
    }
    return lo;
}
// O(n log(max)) instead of O(n * max).

// SPLIT ARRAY LARGEST SUM / CAPACITY TO SHIP PACKAGES IN D DAYS - identical
static int ShipWithinDays(int[] weights, int days)
{
    bool Fits(int capacity)
    {
        int needed = 1, load = 0;
        foreach (var w in weights)
        {
            if (load + w > capacity) { needed++; load = 0; }
            load += w;
        }
        return needed <= days;
    }

    // the lower bound must be at least the largest single item, or nothing fits
    int lo = weights.Max(), hi = weights.Sum();
    while (lo < hi)
    {
        int mid = lo + (hi - lo) / 2;
        if (Fits(mid)) hi = mid; else lo = mid + 1;
    }
    return lo;
}
// Picking the right lo and hi is half the work. lo = the smallest conceivable
// answer, hi = an answer that definitely works.

// FLOATING-POINT answers: iterate a fixed number of times instead of comparing
static double SquareRoot(double x)
{
    double lo = 0, hi = Math.Max(1, x);
    for (int i = 0; i < 100; i++)            // 100 halvings: far below any epsilon
    {
        double mid = (lo + hi) / 2;
        if (mid * mid < x) lo = mid; else hi = mid;
    }
    return lo;
}
// A fixed iteration count beats `while (hi - lo > 1e-9)`, which can loop
// forever on values where the gap stops shrinking in floating point.

// INTEGER SQRT, with the overflow guard
static int MySqrt(int x)
{
    int lo = 0, hi = x;
    while (lo < hi)
    {
        int mid = lo + (hi - lo + 1) / 2;    // UPPER mid, because lo = mid below
        if ((long)mid * mid <= x) lo = mid;  // (long) or mid*mid overflows
        else                      hi = mid - 1;
    }
    return lo;
}
// Note the asymmetry: when the body does `lo = mid` you MUST round the midpoint
// up, or lo never advances and you loop forever. That is the one place the
// standard template changes, and it is worth stating when you write it.

// THE RECOGNITION CHECKLIST
//   1. Is the answer a number in a bounded range?
//   2. Can I CHECK a candidate answer more easily than computing it?
//   3. Is the check monotonic - if x works, does everything above x work?
//   If yes to all three: binary search the answer.
import bisect

def min_eating_speed(piles: list[int], h: int) -> int:
    def can_finish(speed: int) -> bool:
        return sum((p + speed - 1) // speed for p in piles) <= h

    lo, hi = 1, max(piles)
    while lo < hi:
        mid = (lo + hi) // 2
        if can_finish(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

def ship_within_days(weights: list[int], days: int) -> int:
    def fits(capacity: int) -> bool:
        needed, load = 1, 0
        for w in weights:
            if load + w > capacity:
                needed += 1
                load = 0
            load += w
        return needed <= days

    lo, hi = max(weights), sum(weights)
    while lo < hi:
        mid = (lo + hi) // 2
        if fits(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

# bisect with a key turns "binary search the answer" into one call (3.10+)
def min_eating_speed_bisect(piles: list[int], h: int) -> int:
    def hours(speed: int) -> int:
        return sum((p + speed - 1) // speed for p in piles)
    # hours() is DECREASING in speed, so search on -hours to get a sorted key
    lo, hi = 1, max(piles)
    return lo + bisect.bisect_left(range(lo, hi + 1), -h, key=lambda s: -hours(s))

Interview angle

Recognising this pattern is one of the clearest separators in a coding round, because the problems are usually labelled hard and the solution is twenty lines. Rotated arrays and 2-D search

Binary search survives when the array is partly ordered, as long as you can decide which half is sorted. In a rotated sorted array, one half always is: compare a[mid] with a[lo] to find out which, then check whether the target lies inside that sorted half.

For a 2-D matrix the trick depends on the guarantee. If each row is sorted and the first element of each row exceeds the last of the previous, the whole matrix is one sorted array — index it as [mid / cols][mid % cols]. If rows and columns are only individually sorted, start at the top-right corner and walk: left decreases, down increases, so each step eliminates a whole row or column in O(m + n).

// SEARCH IN A ROTATED SORTED ARRAY - decide which half is sorted
static int SearchRotated(int[] a, int target)
{
    int lo = 0, hi = a.Length - 1;              // inclusive here: we return an index
    while (lo <= hi)
    {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] == target) return mid;

        if (a[lo] <= a[mid])                    // the LEFT half is sorted
        {
            if (a[lo] <= target && target < a[mid]) hi = mid - 1;   // inside it
            else                                    lo = mid + 1;
        }
        else                                    // the RIGHT half is sorted
        {
            if (a[mid] < target && target <= a[hi]) lo = mid + 1;
            else                                    hi = mid - 1;
        }
    }
    return -1;
}
// The <= in `a[lo] <= a[mid]` matters: with two elements, mid == lo, and a
// strict < sends you down the wrong branch.

// FIND THE MINIMUM in a rotated sorted array - compare against the RIGHT end
static int FindMin(int[] a)
{
    int lo = 0, hi = a.Length - 1;
    while (lo < hi)
    {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] > a[hi]) lo = mid + 1;       // the minimum is to the right
        else                hi = mid;           // mid might BE the minimum
    }
    return a[lo];
}
// Comparing with a[hi] rather than a[lo] is deliberate - with a[lo] the
// non-rotated case needs a special case, and with a[hi] it does not.

// WITH DUPLICATES, the worst case degrades to O(n) and you must say so:
// [1,1,1,0,1] - a[lo] == a[mid] == a[hi] tells you nothing, so you shrink by one.
static bool SearchRotatedDup(int[] a, int target)
{
    int lo = 0, hi = a.Length - 1;
    while (lo <= hi)
    {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] == target) return true;

        if (a[lo] == a[mid] && a[mid] == a[hi]) { lo++; hi--; continue; }  // O(n)
        if (a[lo] <= a[mid])
        {
            if (a[lo] <= target && target < a[mid]) hi = mid - 1; else lo = mid + 1;
        }
        else
        {
            if (a[mid] < target && target <= a[hi]) lo = mid + 1; else hi = mid - 1;
        }
    }
    return false;
}

// PEAK ELEMENT - binary search with no sorted array at all, just a local rule
static int FindPeak(int[] a)
{
    int lo = 0, hi = a.Length - 1;
    while (lo < hi)
    {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] < a[mid + 1]) lo = mid + 1;   // ascending: a peak is to the right
        else                     hi = mid;       // descending: mid might be it
    }
    return lo;
}
// O(log n) for a problem that looks like it needs a scan. Worth knowing.

// 2-D, FULLY SORTED (row-major) - treat it as one array
static bool SearchMatrix(int[][] m, int target)
{
    int rows = m.Length, cols = m[0].Length;
    int lo = 0, hi = rows * cols - 1;
    while (lo <= hi)
    {
        int mid = lo + (hi - lo) / 2;
        int value = m[mid / cols][mid % cols];       // the only interesting line
        if (value == target) return true;
        if (value < target) lo = mid + 1; else hi = mid - 1;
    }
    return false;
}
// O(log(m*n))

// 2-D, ROWS AND COLUMNS SORTED INDEPENDENTLY - start at the top right
static bool SearchMatrixII(int[][] m, int target)
{
    int r = 0, c = m[0].Length - 1;                  // top-right corner
    while (r < m.Length && c >= 0)
    {
        if (m[r][c] == target) return true;
        if (m[r][c] > target) c--;                   // this whole COLUMN is too big
        else                  r++;                   // this whole ROW is too small
    }
    return false;
}
// O(m + n). The top-right (or bottom-left) corner is the only starting point
// where each comparison eliminates an entire row or column - from the top-left
// both moves increase, so you learn nothing.
def search_rotated(a: list[int], target: int) -> int:
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[lo] <= a[mid]:                      # left half sorted
            if a[lo] <= target < a[mid]: hi = mid - 1
            else:                        lo = mid + 1
        else:                                    # right half sorted
            if a[mid] < target <= a[hi]: lo = mid + 1
            else:                        hi = mid - 1
    return -1

def find_min(a: list[int]) -> int:
    lo, hi = 0, len(a) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] > a[hi]:
            lo = mid + 1
        else:
            hi = mid
    return a[lo]

def search_rotated_dup(a: list[int], target: int) -> bool:
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return True
        if a[lo] == a[mid] == a[hi]:             # ambiguous -> O(n) worst case
            lo, hi = lo + 1, hi - 1
        elif a[lo] <= a[mid]:
            if a[lo] <= target < a[mid]: hi = mid - 1
            else:                        lo = mid + 1
        else:
            if a[mid] < target <= a[hi]: lo = mid + 1
            else:                        hi = mid - 1
    return False

def find_peak(a: list[int]) -> int:
    lo, hi = 0, len(a) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < a[mid + 1]:
            lo = mid + 1
        else:
            hi = mid
    return lo

def search_matrix(m: list[list[int]], target: int) -> bool:
    rows, cols = len(m), len(m[0])
    lo, hi = 0, rows * cols - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        value = m[mid // cols][mid % cols]
        if value == target:  return True
        if value < target:   lo = mid + 1
        else:                hi = mid - 1
    return False

def search_matrix_ii(m: list[list[int]], target: int) -> bool:
    r, c = 0, len(m[0]) - 1                      # top-right
    while r < len(m) and c >= 0:
        if m[r][c] == target: return True
        if m[r][c] > target:  c -= 1             # eliminate the column
        else:                 r += 1             # eliminate the row
    return False
Interview angle

For the rotated array, state the insight before coding: at least one half is always sorted, so compare a[mid] with a[lo] to find which, then test whether the target lies inside it. For the two matrix variants, be sure which guarantee you were given — fully sorted row-major means one O(log mn) search; rows and columns sorted independently means the staircase walk from the top-right in O(m + n). Explaining why the top-right corner works, and the top-left does not, is the detail worth volunteering.

Sorting and comparers

Array.Sort/List.Sort are introsort (unstable, O(n log n)); LINQ OrderBy is stable. Write comparers with Comparison<T> or IComparer<T>. Know one O(n log n) algorithm well enough to write it (merge sort) and when counting/bucket sort wins.

// Custom ordering
people.Sort((a, b) => a.Age != b.Age ? a.Age.CompareTo(b.Age) : string.CompareOrdinal(a.Name, b.Name));
var sorted = people.OrderBy(p => p.Age).ThenBy(p => p.Name).ToList();     // stable

static int[] MergeSort(int[] a)
{

    while (i < l.Length) res[k++] = l[i++];
    while (j < r.Length) res[k++] = r[j++];
    return res;
}

Writing quicksort and mergesort from memory

Being asked to implement a sort is rarely about the sort — it is about whether you can write a correct recursive partition and talk about the trade-offs. Have both, and know the one-line differences: mergesort is O(n log n) always, stable, needs O(n) extra space; quicksort is O(n log n) average, O(n²) worst, unstable, sorts in place with O(log n) stack.

The follow-up is always about quicksort's worst case and how to avoid it: a random or median-of-three pivot makes adversarial input vanishingly unlikely, and falling back to heapsort at a depth limit (which is what introsort does) makes the guarantee hard.

// MERGESORT - stable, O(n log n) guaranteed, O(n) space
static void MergeSort(int[] a) => MergeSort(a, new int[a.Length], 0, a.Length - 1);

static void MergeSort(int[] a, int[] buffer, int lo, int hi)
{
    if (lo >= hi) return;
    int mid = lo + (hi - lo) / 2;
    MergeSort(a, buffer, lo, mid);
    MergeSort(a, buffer, mid + 1, hi);

    // skip the merge entirely when already ordered - this is what makes it
    // adaptive on partly-sorted input
    if (a[mid] <= a[mid + 1]) return;

    Merge(a, buffer, lo, mid, hi);
}

static void Merge(int[] a, int[] buffer, int lo, int mid, int hi)
{
    int i = lo, j = mid + 1, k = lo;
    while (i <= mid && j <= hi)
        buffer[k++] = a[i] <= a[j] ? a[i++] : a[j++];    // <= preserves STABILITY
    while (i <= mid) buffer[k++] = a[i++];
    while (j <= hi)  buffer[k++] = a[j++];
    Array.Copy(buffer, lo, a, lo, hi - lo + 1);
}
// The `<=` in the comparison is the entire reason this is stable. A `<` would
// take from the right half on ties and reorder equal elements.

// QUICKSORT - in place, O(log n) stack, unstable
static void QuickSort(int[] a, int lo, int hi)
{
    while (lo < hi)
    {
        int p = Partition(a, lo, hi);

        // recurse into the SMALLER side, loop on the larger: bounds the stack
        // at O(log n) even on a bad pivot sequence
        if (p - lo < hi - p) { QuickSort(a, lo, p - 1); lo = p + 1; }
        else                 { QuickSort(a, p + 1, hi); hi = p - 1; }
    }
}

static int Partition(int[] a, int lo, int hi)
{
    // RANDOM pivot: without this, an already-sorted array is the O(n^2) case
    int r = Random.Shared.Next(lo, hi + 1);
    (a[r], a[hi]) = (a[hi], a[r]);

    int pivot = a[hi], i = lo - 1;                // Lomuto: simpler to get right
    for (int j = lo; j < hi; j++)
        if (a[j] < pivot) { i++; (a[i], a[j]) = (a[j], a[i]); }

    (a[i + 1], a[hi]) = (a[hi], a[i + 1]);
    return i + 1;
}

// THREE-WAY PARTITION (Dutch national flag) - O(n) when there are many
// duplicates, where Lomuto degrades to O(n^2). This is also "sort colors".
static void SortColors(int[] a)
{
    int low = 0, mid = 0, high = a.Length - 1;
    while (mid <= high)
    {
        switch (a[mid])
        {
            case 0: (a[low], a[mid]) = (a[mid], a[low]); low++; mid++; break;
            case 1: mid++; break;
            default: (a[mid], a[high]) = (a[high], a[mid]); high--; break;
                     // note: do NOT advance mid here - the swapped-in value is unseen
        }
    }
}

// WHAT THE LIBRARY DOES
//   Array.Sort        introsort: quicksort -> heapsort at depth 2*log n,
//                     insertion sort under 16 elements. UNSTABLE.
//   List<T>.Sort      the same.
//   OrderBy           a stable mergesort, and LAZY - nothing sorts until you
//                     enumerate. It also allocates; Array.Sort does not.
//   Array.Sort(keys, items)   sorts a parallel array alongside - occasionally
//                             exactly what you want and nobody remembers it.

// COMPLEXITY SUMMARY, worth being able to recite
//   mergesort   O(n log n) always   stable     O(n) space
//   quicksort   O(n log n) average  unstable   O(log n) stack, O(n^2) worst
//   heapsort    O(n log n) always   unstable   O(1) space, poor cache behaviour
//   insertion   O(n^2), O(n) on nearly-sorted, stable - which is why the
//               library switches to it for small ranges
def merge_sort(a: list[int]) -> list[int]:
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    return merge(left, right)

def merge(left: list[int], right: list[int]) -> list[int]:
    result, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:            # <= keeps it STABLE
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result

import random

def quick_sort(a: list[int], lo: int = 0, hi: int | None = None) -> None:
    if hi is None:
        hi = len(a) - 1
    while lo < hi:
        p = partition(a, lo, hi)
        if p - lo < hi - p:                # recurse into the smaller side
            quick_sort(a, lo, p - 1); lo = p + 1
        else:
            quick_sort(a, p + 1, hi); hi = p - 1

def partition(a: list[int], lo: int, hi: int) -> int:
    r = random.randint(lo, hi)             # random pivot: avoids the sorted-input
    a[r], a[hi] = a[hi], a[r]              # worst case
    pivot, i = a[hi], lo - 1
    for j in range(lo, hi):
        if a[j] < pivot:
            i += 1
            a[i], a[j] = a[j], a[i]
    a[i + 1], a[hi] = a[hi], a[i + 1]
    return i + 1

def sort_colors(a: list[int]) -> None:
    """Dutch national flag: three-way partition, one pass."""
    low = mid = 0
    high = len(a) - 1
    while mid <= high:
        if a[mid] == 0:
            a[low], a[mid] = a[mid], a[low]; low += 1; mid += 1
        elif a[mid] == 1:
            mid += 1
        else:
            a[mid], a[high] = a[high], a[mid]; high -= 1   # mid does NOT advance

Counting sort, bucket sort and quickselect

The O(n log n) bound applies to comparison sorts. If you can exploit structure in the data you can beat it: counting sort is O(n + k) when values are integers in a small range k, and bucket sort is O(n) when values are roughly uniform over a known interval.

Quickselect is the other escape: when you need the k-th element rather than the whole order, partitioning only into the side containing k gives O(n) average (O(n²) worst) instead of O(n log n).

// COUNTING SORT - O(n + k). Valid only when values are integers in [0, k).
static int[] CountingSort(int[] a, int maxValue)
{
    var counts = new int[maxValue + 1];
    foreach (var x in a) counts[x]++;

    // prefix sums turn counts into END positions, which is what makes it stable
    for (int i = 1; i < counts.Length; i++) counts[i] += counts[i - 1];

    var result = new int[a.Length];
    for (int i = a.Length - 1; i >= 0; i--)        // BACKWARDS, for stability
        result[--counts[a[i]]] = a[i];
    return result;
}
// Say the constraint before you use it: "this needs integer keys in a bounded
// range, and costs O(k) space - with values up to 10^9 it is useless."

// Where it legitimately applies: "sort an array of ages", "sort by frequency"
// (frequency is bounded by n), radix sort's inner loop.

// BUCKET SORT - O(n) when the values are roughly uniform over a known range
static void BucketSort(double[] a)                  // values in [0, 1)
{
    int n = a.Length;
    var buckets = new List<double>[n];
    for (int i = 0; i < n; i++) buckets[i] = [];

    foreach (var x in a) buckets[(int)(x * n)].Add(x);
    foreach (var b in buckets) b.Sort();            // each is expected to be tiny

    int k = 0;
    foreach (var b in buckets) foreach (var x in b) a[k++] = x;
}
// O(n) expected, O(n log n) if everything lands in one bucket.

// MAXIMUM GAP is the problem bucket sort exists for: find the largest gap
// between consecutive values in O(n). With n values spanning [min, max], the
// gap is at least (max-min)/(n-1), so a bucket of that width holds at most one
// relevant pair - you only need each bucket's min and max.

// QUICKSELECT - the k-th smallest in O(n) average, without sorting
static int QuickSelect(int[] a, int k)              // k is 0-based
{
    int lo = 0, hi = a.Length - 1;
    while (true)
    {
        if (lo == hi) return a[lo];
        int p = Partition(a, lo, hi);               // the same partition as quicksort

        if      (p == k) return a[p];
        else if (p <  k) lo = p + 1;                // recurse into ONE side only
        else             hi = p - 1;
    }
}
// Average O(n): n + n/2 + n/4 + ... = 2n. Worst case O(n^2), fixed in theory by
// median-of-medians (O(n) worst) and in practice by a random pivot.
// It MUTATES the array - say so, because it is sometimes disqualifying.

// Top-k, three ways and their complexities - the comparison worth giving:
//   sort then take k        O(n log n)   simplest
//   bounded heap of size k  O(n log k)   best for streams, does not mutate
//   quickselect             O(n) average mutates, no order among the k

// RADIX SORT - counting sort per digit, least significant first. O(d * (n + b))
// for d digits in base b. Worth naming for "sort a large array of fixed-width
// integers or strings"; rarely worth writing in an interview.

// WHEN TO MENTION ANY OF THIS: when the interviewer says values are bounded.
// "The values are ages 0-120" or "the characters are lowercase letters" is an
// invitation to beat O(n log n), and noticing it is the point of the question.
def counting_sort(a: list[int], max_value: int) -> list[int]:
    counts = [0] * (max_value + 1)
    for x in a:
        counts[x] += 1

    for i in range(1, len(counts)):          # prefix sums -> end positions
        counts[i] += counts[i - 1]

    result = [0] * len(a)
    for x in reversed(a):                    # backwards keeps it stable
        counts[x] -= 1
        result[counts[x]] = x
    return result

def bucket_sort(a: list[float]) -> None:
    """Values in [0, 1)."""
    n = len(a)
    buckets: list[list[float]] = [[] for _ in range(n)]
    for x in a:
        buckets[int(x * n)].append(x)
    for b in buckets:
        b.sort()
    a[:] = [x for b in buckets for x in b]

import random

def quickselect(a: list[int], k: int) -> int:
    """k-th smallest, 0-based. Mutates `a`."""
    lo, hi = 0, len(a) - 1
    while True:
        if lo == hi:
            return a[lo]
        p = partition(a, lo, hi)
        if   p == k: return a[p]
        elif p <  k: lo = p + 1
        else:        hi = p - 1

def partition(a: list[int], lo: int, hi: int) -> int:
    r = random.randint(lo, hi)
    a[r], a[hi] = a[hi], a[r]
    pivot, i = a[hi], lo - 1
    for j in range(lo, hi):
        if a[j] < pivot:
            i += 1
            a[i], a[j] = a[j], a[i]
    a[i + 1], a[hi] = a[hi], a[i + 1]
    return i + 1
