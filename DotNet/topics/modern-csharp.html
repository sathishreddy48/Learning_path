Nullable reference types and the annotation context

The single biggest change in modern C#, and the one most likely to come up. Before C# 8 every reference type was implicitly nullable and NullReferenceException was a runtime surprise. With <Nullable>enable</Nullable> in the csproj, string means "never null" and string? means "may be null", and the compiler does flow analysis to warn you when you break your own declaration.

The critical point for an interview: this is compile-time only. Nothing is emitted to enforce it, the annotations are metadata, and a caller from an unannotated assembly — or any JSON deserialiser — can still hand you a null in a non-nullable parameter. That is why public entry points still validate.

#nullable enable

public class Order
{
    public string Id { get; init; } = "";        // non-nullable: must be initialised
    public string? CouponCode { get; init; }     // genuinely optional
}

static int CouponLength(Order o)
{
    // return o.CouponCode.Length;   // CS8602: dereference of a possibly null reference
    return o.CouponCode?.Length ?? 0;            // flow analysis is satisfied
}

static void Use(Order o)
{
    if (o.CouponCode is not null)
    {
        Console.WriteLine(o.CouponCode.Length);  // narrowed: no warning here
    }
}

// The operators that come with it
string? maybe = Find();
string definitely = maybe!;                       // null-forgiving: "trust me"
ArgumentNullException.ThrowIfNull(maybe);         // and now the compiler agrees

// Attributes tell callers what a method does to nullability
static bool TryParse(string? text, [NotNullWhen(true)] out Order? order) { /* ... */ }

// Compile-time only: this still throws at runtime
var fromJson = JsonSerializer.Deserialize<Order>("""{"id":null}""");
from __future__ import annotations

# Python's equivalent is also advisory - checked by mypy/pyright, not the runtime
class Order:
    def __init__(self, id: str, coupon_code: str | None = None) -> None:
        self.id = id
        self.coupon_code = coupon_code

def coupon_length(o: Order) -> int:
    # return len(o.coupon_code)        # error: Optional[str] has no len
    return len(o.coupon_code) if o.coupon_code is not None else 0

def use(o: Order) -> None:
    if o.coupon_code is not None:
        print(len(o.coupon_code))      # narrowed by the type checker

from typing import TypeGuard, cast
definitely = cast(str, maybe)          # the ! of the Python world

# Same caveat: annotations are erased at runtime
import json
order = Order(**json.loads('{"id": null}'))   # no complaint until something uses it
Interview angle

Expect "is string? enforced at runtime?" — no, and saying so cleanly is the whole question. Follow-ups: what ! actually does (suppresses a warning, generates no code), why a non-nullable property still needs a default or a constructor, and why deserialisers and reflection can violate every annotation on the type.

Practice
  • Turn <Nullable>enable</Nullable> on in a small project and fix the warnings without using ! anywhere.
  • Write a TryGet method annotated with [NotNullWhen(true)] and confirm the caller stops warning after the if.
  • Explain to yourself why List<string> and List<string?> are the same type at runtime.

Records, with-expressions and value equality

A record is a class (or record struct) for which the compiler generates value equality, GetHashCode, ToString, a deconstructor and a copy constructor. It exists because writing those five members by hand for a DTO was forty lines of boilerplate that nobody kept in sync.

The two things to know: records are shallow — a record holding a List<T> compares the list by reference, so two records with equal-looking lists are not equal — and with is a shallow copy, not a deep clone.

// Positional record: parameters become init-only properties
public record Money(decimal Amount, string Currency);

var a = new Money(10m, "USD");
var b = new Money(10m, "USD");
Console.WriteLine(a == b);           // True - value equality, generated
Console.WriteLine(a);                // Money { Amount = 10, Currency = USD }

var discounted = a with { Amount = 9m };     // non-destructive mutation
var (amount, ccy) = a;                       // generated Deconstruct

// record struct when you want it on the stack; readonly record struct to pin it
public readonly record struct Point(int X, int Y);

// A record can have a body, validation and computed members
public record Order(string Id, IReadOnlyList<string> Lines)
{
    public int LineCount => Lines.Count;
    public string Id { get; init; } = Id is { Length: > 0 }
        ? Id : throw new ArgumentException("Id is required");
}

// The trap: equality is shallow
var x = new Order("1", new[] { "a" });
var y = new Order("1", new[] { "a" });
Console.WriteLine(x == y);           // False - different array instances

// Inheritance works, and the compiler includes the runtime type in equality
public record Base(int Id);
public record Derived(int Id, string Name) : Base(Id);
from dataclasses import dataclass, replace, field
from decimal import Decimal

@dataclass(frozen=True)              # frozen => immutable + hashable
class Money:
    amount: Decimal
    currency: str

a = Money(Decimal("10"), "USD")
b = Money(Decimal("10"), "USD")
print(a == b)                        # True - generated __eq__
print(a)                             # Money(amount=Decimal('10'), currency='USD')

discounted = replace(a, amount=Decimal("9"))   # the `with` of Python
amount, ccy = a.amount, a.currency             # no generated deconstruct

# Same shallow-equality trap, with a twist: list fields break hashing outright
@dataclass(frozen=True)
class Order:
    id: str
    lines: tuple[str, ...] = ()      # tuple, so equality and hashing work

x = Order("1", ("a",))
y = Order("1", ("a",))
print(x == y)                        # True - tuples compare by value

# NamedTuple is the lighter-weight option
from typing import NamedTuple
class Point(NamedTuple):
    x: int
    y: int
Interview angle

The two questions that separate answers: "how does a record differ from a class?" (generated equality/hash/ToString/Deconstruct/copy-ctor, and init setters — not immutability, which you still have to arrange) and "are records deeply immutable?" (no — a record holding a mutable collection is mutable through it, and equality compares that collection by reference).

Practice
  • Write a record holding a List<int> and prove two instances with identical contents are not equal. Then fix it.
  • Implement the same type as a class and count the lines the compiler saved you.
  • Work out what record Derived : Base does to Equals when compared against a Base with the same Id.

Pattern matching: switch expressions, property, positional and list patterns

Pattern matching grew from "is this a type?" in C# 7 into a small sub-language. The payoff is that branching on the shape of data becomes an expression that returns a value, and the compiler tells you when you have missed a case.

switch expressions are exhaustive-checked: a non-exhaustive one warns and throws SwitchExpressionException at runtime, which is usually what you want over a silent default.

// switch expression: returns a value, arms are `pattern => result`
static decimal Fee(Payment p) => p switch
{
    // property patterns, with nesting and relational operators
    { Method: "card", Amount: > 1000m }        => p.Amount * 0.02m,
    { Method: "card" }                         => p.Amount * 0.03m,
    { Method: "transfer", Currency: "USD" }    => 0m,

    // type pattern + designation, with a `when` guard
    Refund r when r.Amount > 0                 => -r.Amount * 0.01m,

    // combinators: and / or / not
    { Amount: <= 0 } or null                   => throw new ArgumentException(nameof(p)),
    _                                          => p.Amount * 0.05m,
};

// Positional (deconstruction) patterns
static string Quadrant(Point pt) => pt switch
{
    (0, 0)                    => "origin",
    ( > 0, > 0)               => "I",
    ( < 0, > 0)               => "II",
    var (x, y) when x == y    => "diagonal",
    _                         => "other",
};

// List patterns (C# 11): match a sequence by shape
static string Describe(int[] xs) => xs switch
{
    []                  => "empty",
    [var only]          => $"one: {only}",
    [var first, .., var last] => $"{first}..{last}",
};

// is-patterns outside switch
if (obj is string { Length: > 0 } s) Console.WriteLine(s.ToUpper());
if (value is not null and not "") { }
# match/case (3.10+) is the closest equivalent - also shape-based
from dataclasses import dataclass

def fee(p) -> float:
    match p:
        # mapping / class patterns with attribute capture and guards
        case Payment(method="card", amount=amount) if amount > 1000:
            return amount * 0.02
        case Payment(method="card", amount=amount):
            return amount * 0.03
        case Payment(method="transfer", currency="USD"):
            return 0.0
        case Refund(amount=amount) if amount > 0:
            return -amount * 0.01
        case Payment(amount=amount) if amount <= 0:
            raise ValueError("amount")
        case _:
            return p.amount * 0.05

def quadrant(pt) -> str:
    match pt:
        case (0, 0):            return "origin"
        case (x, y) if x > 0 and y > 0: return "I"
        case (x, y) if x < 0 and y > 0: return "II"
        case (x, y) if x == y:  return "diagonal"
        case _:                 return "other"

# Sequence patterns, including the star pattern
def describe(xs: list[int]) -> str:
    match xs:
        case []:                 return "empty"
        case [only]:             return f"one: {only}"
        case [first, *_, last]:  return f"{first}..{last}"

# No exhaustiveness checking: a match with no arm falls through silently
Interview angle

A good signal is knowing switch expressions are checked for exhaustiveness and throw rather than returning a default. Be ready to rewrite a nested if/else chain as a switch expression on the spot — it is a common "tidy this up" exercise — and to say why when guards are not considered by the exhaustiveness analysis.

  • Use a list pattern to classify an array as empty / single / palindromic.
  • Find out what the compiler does with a switch expression over an enum that is missing one member.

Ranges, indices and slicing

Index and Range give a[^1] for "last" and a[2..5] for a slice. They are compiler sugar over Length arithmetic plus either a Slice method or an indexer, so any type exposing Length/Count and Slice supports them.

The performance point: slicing an array with a[2..5] copies; slicing a Span<T> or ReadOnlySpan<char> does not. That difference is the whole reason AsSpan() exists in hot paths.

int[] a = [10, 20, 30, 40, 50];

int last      = a[^1];           // 50   - ^1 means Length - 1
int[] middle  = a[1..4];         // [20,30,40]  - end is exclusive
int[] head    = a[..2];          // [10,20]
int[] tail    = a[3..];          // [40,50]
int[] copy    = a[..];           // whole-array copy

// Index and Range are real types you can pass around
Index secondFromEnd = ^2;
Range body = 1..^1;
int[] inner = a[body];           // [20,30,40]

// Strings: Substring with nicer syntax
string s = "2026-10-07";
string year = s[..4];            // "2026"
string day  = s[^2..];           // "07"

// The allocation difference that matters
string[] parts = s.Split('-');              // allocates an array + 3 strings
ReadOnlySpan<char> yearSpan = s.AsSpan(0, 4);   // allocates nothing
int y = int.Parse(s.AsSpan(..4));               // parse straight from the span

// Any type with Length/Count + Slice gets range support for free
public class Buffer
{
    public int Length => _data.Length;
    public Buffer Slice(int start, int length) => new(_data[start..(start + length)]);
}
a = [10, 20, 30, 40, 50]

last   = a[-1]        # 50   - negative indices are the ^1 equivalent
middle = a[1:4]       # [20, 30, 40]  - stop is exclusive, same as C#
head   = a[:2]        # [10, 20]
tail   = a[3:]        # [40, 50]
copy   = a[:]         # shallow copy

# slice() is the Range equivalent and can be stored
body = slice(1, -1)
inner = a[body]       # [20, 30, 40]

s = "2026-10-07"
year = s[:4]          # "2026"
day  = s[-2:]         # "07"

# Python slices always copy for list/str. memoryview is the Span analogue
raw = b"2026-10-07"
mv = memoryview(raw)[0:4]      # no copy
year_bytes = bytes(mv)         # copy only when you ask for one

# Supporting slicing on your own type
class Buffer:
    def __init__(self, data): self._data = data
    def __len__(self): return len(self._data)
    def __getitem__(self, key): return Buffer(self._data[key])   # key may be a slice
Interview angle

The question behind the question is allocation: "does array[1..4] allocate?" Yes — it is a copy. "Does span[1..4]?" No. Knowing that ^0 is Length (so a[^0] throws) is a nice detail.

Practice
  • Parse a fixed-width record (date, code, amount) using only ranges and no Substring.
  • Benchmark Split against AsSpan + ranges on a million short strings.
  • Add Length and Slice to a custom type and use range syntax on it.

init, required and object initialisation

Three features that together let you build immutable-after-construction types without a constructor per permutation. init accessors are settable only during object initialisation; required makes the compiler insist a member is set by any caller; readonly fields remain the strongest guarantee.

required solved a real problem with init: an init-only property could still be forgotten, leaving a non-nullable string as null. required is a compile-time check, and [SetsRequiredMembers] is how a constructor opts out of it.

public class Customer
{
    public required string Name { get; init; }   // caller MUST set it
    public required string Email { get; init; }
    public string? Phone { get; init; }          // optional
    public DateOnly Created { get; init; } = DateOnly.FromDateTime(DateTime.UtcNow);
}

var c = new Customer { Name = "Ada", Email = "ada@example.com" };
// var bad = new Customer { Name = "Ada" };   // CS9035: Email must be set
// c.Name = "Grace";                          // CS8852: init-only

// A constructor that sets them all opts out of the requirement
public class Order
{
    public required string Id { get; init; }

    public Order() { }

    [SetsRequiredMembers]
    public Order(string id) => Id = id;        // callers of this ctor need no initialiser
}

// init vs readonly vs set - pick deliberately
public class Three
{
    private readonly int _hardest;             // only a constructor, ever
    public int Firm { get; init; }             // constructor or object initialiser
    public int Soft { get; set; }              // anyone, any time
    public Three(int x) => _hardest = x;
}

// Structs: readonly struct makes every field readonly and every method readonly
public readonly struct Temp(double Celsius)
{
    public double Fahrenheit => Celsius * 9 / 5 + 32;
}
from dataclasses import dataclass, field
from datetime import date

# A frozen dataclass is the init-only equivalent: set at construction, then sealed
@dataclass(frozen=True)
class Customer:
    name: str                                  # no default => required
    email: str                                 # no default => required
    phone: str | None = None
    created: date = field(default_factory=date.today)

c = Customer(name="Ada", email="ada@example.com")
# Customer(name="Ada")                         # TypeError: missing 'email'
# c.name = "Grace"                             # FrozenInstanceError

# kw_only forces callers to name every argument, like C#'s object initialiser
@dataclass(frozen=True, kw_only=True)
class Order:
    id: str

Order(id="A-1")

# Without frozen=True, "required" and "settable" are the only two states:
# Python has no per-property init-only accessor. Properties get you close:
class Three:
    def __init__(self, x: int) -> None:
        self._hardest = x                      # by convention, not enforced
    @property
    def hardest(self) -> int:
        return self._hardest                   # no setter => read-only
Interview angle

"What is the difference between init and readonly?" — init also allows an object initialiser, which means a caller outside the constructor can set it, which means you cannot rely on it for an invariant that must hold. Then: "how do you guarantee a property is set?" → required, or a constructor parameter, and know that required is compile-time only so reflection and deserialisation bypass it.

Practice
  • Model a type with two mandatory and two optional members three ways: constructor, init, required. Argue for one.
  • Find out what System.Text.Json does with a required property missing from the payload.
  • Add [SetsRequiredMembers] to a constructor and watch the call-site error disappear.

Primary constructors and collection expressions

C# 12 extended primary constructors from records to all classes and structs, and added [...] as a target-typed literal for any collection type.

The gotcha interviewers like: a primary-constructor parameter on a class is a captured variable, not a property. It is mutable inside the body, it does not show up in ToString, and if you capture it in a lambda you have captured a field the compiler generated for you. On a record, the same syntax creates a public init-only property. Same spelling, different semantics.

// Class primary constructor: parameters are captured, NOT properties
public class OrderService(IRepository repo, ILogger<OrderService> log)
{
    public async Task Handle(string id)
    {
        log.LogInformation("handling {Id}", id);   // used directly, no field needed
        var order = await repo.Get(id);
    }
    // repo and log are private captured state; nothing is exposed
}

// On a record the same syntax creates public init-only properties
public record Money(decimal Amount, string Currency);   // Amount is public

// Capturing deliberately into a readonly field when you want the guarantee
public class Cache(IClock clock)
{
    private readonly IClock _clock = clock;    // explicit, immutable
}

// Collection expressions: one syntax, target-typed
int[]            arr  = [1, 2, 3];
List<int>        list = [1, 2, 3];
HashSet<int>     set  = [1, 2, 3];
Span<int>        span = [1, 2, 3];              // no heap allocation
ImmutableArray<int> imm = [1, 2, 3];
int[][]          grid = [[1, 2], [3, 4]];

// The spread element
int[] head = [1, 2];
int[] all  = [0, ..head, 3];                    // [0, 1, 2, 3]

// Empty, and in an argument position
Process([]);
static void Process(IEnumerable<int> xs) { }

// A collection type opts in with [CollectionBuilder] or an Add method + IEnumerable
# Python's __init__ is already the primary constructor; the closest thing to
# C#'s captured parameters is a closure or a dataclass
from dataclasses import dataclass

@dataclass
class OrderService:
    repo: "Repository"
    log: "Logger"

    async def handle(self, id: str) -> None:
        self.log.info("handling %s", id)
        order = await self.repo.get(id)

# Collection literals have always been target-specific rather than target-typed
arr  = [1, 2, 3]            # list
tup  = (1, 2, 3)            # tuple
st   = {1, 2, 3}            # set
frz  = frozenset([1, 2, 3])
grid = [[1, 2], [3, 4]]

# Unpacking is the spread element
head = [1, 2]
all_ = [0, *head, 3]        # [0, 1, 2, 3]
merged = {**a, **b}         # dict merge (or a | b in 3.9+)

# Empty literals need no target type
process([])
Interview angle

Have the class-vs-record distinction ready: on a class, primary-constructor parameters are captured variables (private, mutable, invisible in ToString); on a record they become public init-only properties. Also worth saying: a primary constructor is excellent for DI-heavy service classes and poor where you need validation, because there is no body to validate in until you add one.

Practice
  • Rewrite a service class with four injected dependencies using a primary constructor and count the lines removed.
  • Capture a primary-constructor parameter in a lambda, then mutate it, and explain what the compiler generated.
  • Assign the same [1, 2, 3] to five different collection types and check which ones allocate.

Default interface members and static abstract members

C# 8 allowed interfaces to carry implementations; C# 11 allowed them to declare static abstract members, which is what makes generic math possible. Both exist to let a library add to an interface without breaking every implementer.

Default interface members are not multiple inheritance of state — an interface still cannot hold instance fields. And they are resolved against the interface, not the class: calling one requires a reference typed as the interface.

// A default implementation lets you add a member without breaking implementers
public interface ILogger
{
    void Log(LogLevel level, string message);

    // new member, existing implementers keep compiling
    void LogError(string message) => Log(LogLevel.Error, message);
}

public class ConsoleLogger : ILogger
{
    public void Log(LogLevel level, string message) => Console.WriteLine($"{level}: {message}");
}

var logger = new ConsoleLogger();
// logger.LogError("boom");                  // does NOT compile - not a class member
((ILogger)logger).LogError("boom");          // resolved through the interface

// static abstract: the member is on the TYPE, so generic code can call it
public interface IParsable2<T> where T : IParsable2<T>
{
    static abstract T Parse(string s);
}

public readonly record struct Sku(string Value) : IParsable2<Sku>
{
    public static Sku Parse(string s) => new(s);
}

static T[] ParseAll<T>(string[] input) where T : IParsable2<T>
    => input.Select(T.Parse).ToArray();       // calling a static through a type parameter

// This is how generic math works in the BCL
static T Sum<T>(IEnumerable<T> xs) where T : INumber<T>
{
    T total = T.Zero;                          // static property on the type parameter
    foreach (var x in xs) total += x;          // operator from the interface
    return total;
}
Console.WriteLine(Sum(new[] { 1, 2, 3 }));     // 6
Console.WriteLine(Sum(new[] { 1.5, 2.5 }));    // 4
from abc import ABC, abstractmethod
from typing import Protocol, Self, TypeVar

# Python ABCs have always allowed concrete methods alongside abstract ones,
# and they ARE callable on the instance - no interface cast needed
class Logger(ABC):
    @abstractmethod
    def log(self, level: str, message: str) -> None: ...

    def log_error(self, message: str) -> None:      # the "default member"
        self.log("error", message)

class ConsoleLogger(Logger):
    def log(self, level: str, message: str) -> None:
        print(f"{level}: {message}")

ConsoleLogger().log_error("boom")                   # just works

# The static-abstract equivalent: a Protocol with a classmethod
class Parsable(Protocol):
    @classmethod
    def parse(cls, s: str) -> Self: ...

T = TypeVar("T", bound=Parsable)

def parse_all(cls: type[T], values: list[str]) -> list[T]:
    return [cls.parse(v) for v in values]           # the type is passed explicitly

# Generic math: Python leans on duck typing and operator protocols instead
from typing import Iterable
def total(xs: Iterable[float]) -> float:
    return sum(xs)                                   # works for anything with __add__
Interview angle

Two reliable questions. "Why would an interface have an implementation?" — versioning: adding a member to a shipped interface is otherwise a breaking change. "Why can't I call it on the class?" — default members are interface members; the class does not inherit them into its own surface. If generic math comes up, INumber<T> plus static abstract is the answer for "how do you write one Sum for int and double without boxing".

Practice
  • Add a member with a default implementation to an interface with three implementers and confirm nothing breaks.
  • Write a Sum<T>() where T : INumber<T> and call it with int, double and decimal.
  • Work out what happens when a class implements two interfaces that both default-implement the same signature.

Target-typed new, file-scoped namespaces, global usings, top-level statements

A cluster of small features that changed what idiomatic C# looks like. None are deep, all are visible: a modern file has no namespace braces, no using System; and a Program.cs with no class in it. Knowing why each exists is enough.

// Program.cs - top-level statements. The compiler generates Program.Main for you.
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddSingleton<IClock, SystemClock>();
var app = builder.Build();
app.MapGet("/health", () => Results.Ok());
app.Run();
// `args` is in scope; so is an implicit async context and a top-level `return 0;`


// Order.cs - file-scoped namespace: one less level of indentation for the file
namespace Shop.Domain;

public class Order
{
    // target-typed new: the type is already on the left, do not repeat it
    private readonly Dictionary<string, List<OrderLine>> _lines = new();
    private static readonly JsonSerializerOptions Options = new() { WriteIndented = true };

    public Order Clone() => new() { Id = Id };     // even in a return position
}

// GlobalUsings.cs - or <ImplicitUsings>enable</ImplicitUsings> in the csproj
global using System.Text.Json;
global using Shop.Domain;
global using Repo = Shop.Data.OrderRepository;     // aliases work too

// file-local types: visible only inside this one file
file class Helper { }
# Python has had all of these since forever, which is why they read as normal

# "Top-level statements": a module IS a script. The __main__ guard is the only
# ceremony, and only when the file is also importable.
import asyncio
from app import create_app

app = create_app()

if __name__ == "__main__":
    asyncio.run(app.serve())

# "File-scoped namespace": the module path is the namespace. No braces, ever.
# shop/domain/order.py  ->  shop.domain.order

    def __init__(self) -> None:

# "Global usings": there is no such thing - imports are per module by design.
# The closest equivalent is re-exporting from a package __init__.py:
#   shop/__init__.py:  from .domain.order import Order
from shop import Order

# "file-local types": a leading underscore, by convention only
class _Helper:
    pass
Interview angle

These show up as "what version of C# is this codebase on?" signals rather than as questions. The one real question is about top-level statements: the compiler still generates a Program class with a Main, which matters when a test project or WebApplicationFactory<Program> needs to reference it — and is why you sometimes see a public partial class Program { } at the bottom of the file.

Practice

  • Convert a Program.cs with an explicit Main to top-level statements and get an integration test referencing Program to compile.
  • Use a file-scoped class for a helper and confirm another file cannot see it.

IAsyncEnumerable and await foreach

Before C# 8 an async method could return one value (Task<T>) or a sequence produced all at once (Task<List<T>>). IAsyncEnumerable<T> is the missing case: a sequence where each element is awaited. It is what you want for a paged API, a database cursor or a message stream — anything you should not buffer entirely.

Two details that are nearly always the follow-up question: cancellation needs [EnumeratorCancellation] to flow from WithCancellation into the iterator, and ConfigureAwait(false) on an async stream is spelled .ConfigureAwait(false) on the enumerable, not inside it.

// Producing: async iterator - `async` + `IAsyncEnumerable<T>` + `yield return`
public async IAsyncEnumerable<Order> GetAllAsync(
    [EnumeratorCancellation] CancellationToken ct = default)
{
    string? cursor = null;
    do
    {
        var page = await _api.GetPageAsync(cursor, ct);   // one await per page
        foreach (var order in page.Items)
            yield return order;                            // one element at a time
        cursor = page.NextCursor;
    }
    while (cursor is not null);
}

// Consuming
await foreach (var order in GetAllAsync(ct))
{
    Process(order);
}

// With cancellation and no captured context
await foreach (var order in GetAllAsync()
    .WithCancellation(ct)
    .ConfigureAwait(false))
{
}

// System.Linq.Async / EF Core give you the operators
var recent = await _db.Orders.AsAsyncEnumerable()
    .Where(o => o.Total > 100)
    .Take(10)
    .ToListAsync(ct);

// Minimal API: returning one streams the response instead of buffering it
app.MapGet("/orders", (CancellationToken ct) => GetAllAsync(ct));

// IAsyncDisposable is the partner feature
await using var conn = new SqlConnection(cs);
# async generators: `async def` + `yield`. Python had these first (3.6).
from typing import AsyncIterator

async def get_all() -> AsyncIterator["Order"]:
    cursor = None
    while True:
        page = await api.get_page(cursor)      # one await per page
        for order in page.items:
            yield order                        # one element at a time
        cursor = page.next_cursor
        if cursor is None:
            break

# Consuming
async for order in get_all():
    process(order)

# Cancellation is structural rather than a token you thread through
import asyncio
async with asyncio.timeout(30):
    async for order in get_all():
        process(order)

# Comprehensions work over async iterators
recent = [o async for o in get_all() if o.total > 100][:10]

# The IAsyncDisposable equivalent
async with Connection(cs) as conn:
    ...

# aclose() matters: an abandoned async generator needs explicit cleanup
agen = get_all()
try:
    ...
finally:
    await agen.aclose()
Interview angle

Expect "when would you return IAsyncEnumerable<T> instead of Task<List<T>>?" — when the sequence is large, paged or unbounded, and you want the first element before the last one exists. The sharp follow-up is cancellation: without [EnumeratorCancellation], the token passed to WithCancellation never reaches your iterator body and the loop keeps paging after cancellation.

Practice
  • Turn a paged HTTP client into an IAsyncEnumerable<T> and consume it with await foreach.
  • Omit [EnumeratorCancellation], then cancel mid-stream, and observe that the iterator keeps going.
  • Compare peak memory streaming 100k rows with IAsyncEnumerable versus ToListAsync.

What landed in which version

You will not be quizzed on version numbers, but being able to say "that is C# 11, so .NET 7 or later" tells an interviewer you have followed the language rather than absorbed it. C# versions are tied to the SDK: net8.0 defaults to C# 12, net9.0 to C# 13, and <LangVersion> overrides it at your own risk.

Interview angle

Nobody needs the table memorised. What is worth having ready: one feature you have actually adopted and the problem it removed, and one you have deliberately not adopted and why. "We turned nullable on in new projects only, because retrofitting it across a large solution generated 4,000 warnings and tempted everyone into !" is a better answer than a feature list.
