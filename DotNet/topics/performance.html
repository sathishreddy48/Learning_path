GC generations, LOH and GC modes

The .NET GC is generational: gen 0 (new, collected often and fast), gen 1 (survivors), gen 2 (long-lived, expensive full collections). Objects ≥ 85 KB go to the Large Object Heap, which is collected with gen 2 and not compacted by default. Workstation vs Server GC and concurrent/background modes change latency vs throughput. CPython instead uses reference counting with a generational cycle collector.

// Observe the GC
Console.WriteLine($"Gen0 {GC.CollectionCount(0)}  Gen1 {GC.CollectionCount(1)}  Gen2 {GC.CollectionCount(2)}");
Console.WriteLine($"Heap {GC.GetTotalMemory(false) / 1024 / 1024} MB, allocated {GC.GetTotalAllocatedBytes() / 1024 / 1024} MB total");
Console.WriteLine($"Object generation: {GC.GetGeneration(obj)}");
var info = GC.GetGCMemoryInfo();      // pause durations, heap sizes, fragmentation

// Large object: 85,000+ bytes → LOH → gen 2 collection required to free it
var big = new byte[100_000];
Console.WriteLine(GC.GetGeneration(big));   // 2

// Compact the LOH once (after a known big drop), never in a loop
GCSettings.LargeObjectHeapCompactionMode = GCLargeObjectHeapCompactionMode.CompactOnce;
GC.Collect();

// Configure in runtimeconfig.json / csproj:
// <ServerGarbageCollection>true</ServerGarbageCollection>      one heap per core; throughput for services
// <ConcurrentGarbageCollection>true</ConcurrentGarbageCollection>  background gen2 → shorter pauses
// <TieredPGO>true</TieredPGO>                                     profile-guided JIT (default .NET 8+)
// DOTNET_GCHeapHardLimit=0x40000000  cap heap at 1 GB in containers (auto from cgroup limits)

// Latency-sensitive window (e.g. during a request burst)
GCSettings.LatencyMode = GCLatencyMode.SustainedLowLatency;

// Rules of thumb
//  • Gen0 GCs are cheap; allocation *rate* is what matters.
//  • Gen2/LOH GCs are the ones that cause P99 spikes — avoid promoting short-lived big objects.
//  • Never call GC.Collect() in production code paths.
import gc, sys, tracemalloc

# CPython: reference counting frees most objects immediately…
a = [1, 2, 3]; b = a
print(sys.getrefcount(a))           # 3 (a, b, and the argument)
del b                                # refcount drops; freed when it hits 0

# …plus a generational cycle collector for reference cycles
print(gc.get_count())                # allocations since last collection per generation
print(gc.get_threshold())            # (700, 10, 10) by default
gc.collect()                         # force full collection (rarely needed)

# Cycles keep objects alive until the collector runs
class Node:
    def __init__(self): self.other = None
x, y = Node(), Node(); x.other, y.other = y, x
del x, y                             # not freed by refcount; the cycle collector gets them

# Weak references avoid cycles for caches/observers
import weakref
cache = weakref.WeakValueDictionary()

# Track allocations
tracemalloc.start()
data = [str(i) for i in range(100_000)]
current, peak = tracemalloc.get_traced_memory()
print(f"current {current/1e6:.1f} MB, peak {peak/1e6:.1f} MB")
for stat in tracemalloc.take_snapshot().statistics("lineno")[:3]: print(stat)

# Rules of thumb
#  • Most objects die by refcount instantly; GC pauses come from cycle collection.
#  • gc.freeze() before forking workers keeps shared pages copy-on-write friendly.
#  • __slots__ shrinks per-instance memory significantly.

IDisposable, finalizers and unmanaged resources

Finalizers run on a dedicated thread after the GC finds the object unreachable — non-deterministic and expensive (the object survives one extra collection). Use them only as a safety net for unmanaged handles; prefer SafeHandle. Implement the full Dispose pattern only when you actually own unmanaged resources; otherwise a simple Dispose that disposes owned IDisposables is enough.

// Simple: you own managed disposables only
public sealed class ReportWriter(Stream output) : IDisposable
{
    private readonly StreamWriter _w = new(output);
    public void Dispose() => _w.Dispose();
}

// Full pattern: unmanaged handle + finalizer safety net
public class NativeBuffer : IDisposable
{
    private IntPtr _ptr;
    private bool _disposed;

    public NativeBuffer(int size) => _ptr = Marshal.AllocHGlobal(size);

    public void Dispose()
    {
        Dispose(disposing: true);
        GC.SuppressFinalize(this);          // no need to finalize; we cleaned up
    }

    protected virtual void Dispose(bool disposing)
    {
        if (_disposed) return;
        if (disposing) { /* dispose managed fields here */ }
        if (_ptr != IntPtr.Zero) { Marshal.FreeHGlobal(_ptr); _ptr = IntPtr.Zero; }
        _disposed = true;
    }

    ~NativeBuffer() => Dispose(disposing: false);   // runs only if Dispose was never called
}

// Better: SafeHandle does the finalizer work for you and is thread/abort safe
public sealed class HGlobalHandle : SafeHandleZeroOrMinusOneIsInvalid
{
    public HGlobalHandle(int size) : base(ownsHandle: true) => SetHandle(Marshal.AllocHGlobal(size));
    protected override bool ReleaseHandle() { Marshal.FreeHGlobal(handle); return true; }
}

// Leaks to look for: event subscriptions, timers, HttpResponseMessage, DbConnection without using,
// CancellationTokenRegistration, static caches of IDisposable.

# Deterministic cleanup: context manager

        if self._ptr: lib.free(self._ptr); self._ptr = None
    def __enter__(self): return self

Structs vs classes, boxing and readonly

Structs avoid heap allocation and GC pressure — but they are copied on every assignment and parameter pass, so keep them small (≤16 bytes rule of thumb) and immutable. Boxing (struct → object/interface) allocates; it happens silently with non-generic collections, string.Format args and interface calls on struct values. readonly struct, in parameters and ref struct (e.g. Span) give control.

// Boxing: value type → object allocates a heap copy
int n = 42;
object o = n;                    // box
int back = (int)o;               // unbox
IComparable c = n;               // box (interface)
var list = new ArrayList { n };  // box (non-generic)
Console.WriteLine("{0}", n);     // box (object param) — string interpolation with handlers does not

// Generics avoid it
var generic = new List<int> { n };   // no box
static bool Less<T>(T a, T b) where T : IComparable<T> => a.CompareTo(b) < 0;   // constrained call, no box

// Small immutable struct with readonly (defensive copies avoided)
public readonly record struct Point(double X, double Y)
{
    public double Length => Math.Sqrt(X * X + Y * Y);
}

// Pass big structs by readonly reference
public readonly struct Matrix4x4 { /* 64 bytes */ }
static float Trace(in Matrix4x4 m) => ...;     // no copy, cannot mutate

// Mutable struct pitfall: mutating a copy
struct Counter { public int N; public void Inc() => N++; }
var counters = new List<Counter> { new() };
counters[0].Inc();                                // compiles?? no — CS1612; with arrays it mutates in place, with List it's a copy
foreach (var ct in counters) ct.Inc();            // mutates a copy — silent bug

// Equality: default struct Equals uses reflection (slow) — override or use record struct
// Stack allocation
Span<int> buf = stackalloc int[16];              // no heap at all; small sizes only
# Everything is a heap object in CPython; even small ints are boxed (cached for -5..256)
import sys
print(sys.getsizeof(42))          # 28 bytes
print(sys.getsizeof((1.0, 2.0)))  # tuple of two boxed floats

# Reduce per-object overhead with __slots__ (no __dict__ per instance)
class Point:
    __slots__ = ("x", "y")
    def __init__(self, x, y): self.x, self.y = x, y
print(sys.getsizeof(Point(1, 2)))  # ~48 vs ~56 + a 100+ byte __dict__ without slots

from dataclasses import dataclass
@dataclass(frozen=True, slots=True)   # 3.10+: immutable + slots
class P: x: float; y: float

# Unboxed numeric arrays: array module / NumPy store raw values contiguously
import array, numpy as np
a = array.array("d", [1.0, 2.0])     # 8 bytes per element
v = np.zeros(1_000_000, dtype=np.float64)
print(v.nbytes / 1e6, "MB")           # 8 MB, vs ~32 MB for a list of floats

# Struct-like packed binary data
import struct
packed = struct.pack("<2d", 1.0, 2.0)  # 16 bytes
x, y = struct.unpack("<2d", packed)

Span, Memory and stackalloc

Span<T> is a ref struct that views a contiguous slice of an array, string, stack or native memory — slicing without copying and without allocation. It cannot live on the heap (no fields in classes, no async), which is what Memory<T> is for. Parsing, tokenising and buffer manipulation get dramatically cheaper. There is no Python equivalent beyond memoryview.

// Parse "key=value;key2=value2" without allocating substrings
static Dictionary<string, string> Parse(ReadOnlySpan<char> input)
{
    var result = new Dictionary<string, string>();
    while (!input.IsEmpty)
    {
        int semi = input.IndexOf(';');
        var pair = semi < 0 ? input : input[..semi];
        int eq = pair.IndexOf('=');
        if (eq > 0) result[pair[..eq].ToString()] = pair[(eq + 1)..].ToString();   // allocate only the final strings
        input = semi < 0 ? default : input[(semi + 1)..];
    }
    return result;
}

middle[0] = 99;                             // writes through to data

# memoryview: zero-copy slices of bytes-like objects

# Parsing without intermediate copies — bytes.find + slicing of memoryview
def parse(buf: bytes) -> dict[str, str]:
    mv = memoryview(buf); result = {}
    start = 0
    while start < len(mv):
        semi = buf.find(b";", start); end = len(buf) if semi < 0 else semi
        eq = buf.find(b"=", start, end)
        if eq > 0:
            result[bytes(mv[start:eq]).decode()] = bytes(mv[eq+1:end]).decode()
        start = end + 1
    return result

# For heavy numeric slicing use NumPy views (a[1:4] is a view, not a copy).
import numpy as np

# struct.unpack_from / int.from_bytes parse straight from a buffer

ArrayPool, object pooling and buffer reuse

Renting buffers from ArrayPool<T>.Shared instead of allocating keeps large temporary arrays off the LOH and out of the GC. Always return in a finally, never use the array after returning it, and remember rented arrays may be larger than requested and contain old data. ObjectPool<T> and RecyclableMemoryStream follow the same idea.

// Rent / return
async Task CopyAsync(Stream src, Stream dst)
{
    byte[] buffer = ArrayPool<byte>.Shared.Rent(81920);        // may return a bigger array
    try
    {
        int read;
        while ((read = await src.ReadAsync(buffer)) > 0)
            await dst.WriteAsync(buffer.AsMemory(0, read));     // slice to what you asked for
    }
    finally
    {
        ArrayPool<byte>.Shared.Return(buffer, clearArray: false); // clearArray: true for sensitive data
    }
}

String handling costs

Strings are immutable, so every +, Substring, ToUpper, Replace allocates. Use StringBuilder for loops, string.Create/interpolation handlers for formatting, Span for parsing, StringComparison.Ordinal for non-linguistic comparisons, and string.Intern almost never. Watch for hidden ToString() in logging — use structured logging with message templates.

// ✗ O(n²) allocations
string csv = "";
foreach (var x in items) csv += x + ",";

// ✓ StringBuilder (or string.Join)
var sb = new StringBuilder(items.Count * 8);
foreach (var x in items) sb.Append(x).Append(',');
string csv2 = string.Join(",", items);

// Ordinal comparisons are much faster than culture-aware ones
bool eq = string.Equals(a, b, StringComparison.OrdinalIgnoreCase);
var dict = new Dictionary<string, int>(StringComparer.Ordinal);
int i = s.IndexOf("x", StringComparison.Ordinal);

// Interpolation is efficient in .NET 6+ (DefaultInterpolatedStringHandler): no intermediate strings
string msg = $"Order {id} total {total:C}";

// Logging: message templates defer formatting until it's actually written
log.LogDebug("Processing {OrderId} with {Count} lines", id, lines.Count);   // ✓
log.LogDebug($"Processing {id} with {lines.Count} lines");                  // ✗ formats even if Debug is off

// Avoid substrings for checks
if (s.StartsWith("Bearer ", StringComparison.Ordinal)) token = s.AsSpan(7);   // no Substring alloc

// UTF-8 at the edges: work in bytes when the data is bytes (JSON, HTTP)
ReadOnlySpan<byte> utf8 = "hello"u8;                 // UTF-8 literal, no encoding at runtime
var json = JsonSerializer.SerializeToUtf8Bytes(obj);

// string.Concat / string.Join over LINQ Aggregate for joins; Split with StringSplitOptions.TrimEntries
# ✗ Quadratic in theory (CPython optimises += on a uniquely-referenced str, but don't rely on it)
csv = ""
for x in items: csv += f"{x},"

# ✓ Build a list and join
csv = ",".join(str(x) for x in items)

# f-strings are the fastest formatting; % and .format are slower
msg = f"Order {id} total {total:.2f}"

# Logging: let the logger format lazily
logging.debug("Processing %s with %d lines", id, len(lines))   # ✓
logging.debug(f"Processing {id} with {len(lines)} lines")      # ✗ formats even when disabled

# Case-insensitive comparison: casefold once, compare many
key = s.casefold()

# Prefix checks without slicing
if s.startswith("Bearer "): token = s[7:]

# Bytes at the edges: avoid decode/encode round-trips when the data stays bytes
payload = orjson.dumps(obj)            # bytes, faster than json.dumps().encode()

# Interning identical strings in big datasets: sys.intern()
import sys
names = [sys.intern(n) for n in raw_names]

Async performance pitfalls

Async keeps threads free but is not free itself: each async method allocates a state machine when it actually suspends. Avoid async on hot synchronous paths (return the task directly or use ValueTask), never block (.Result), batch instead of awaiting in a loop, and watch thread-pool starvation with dotnet-counters.

// ✗ Sequential awaits in a loop — N round-trips
foreach (var id in ids) results.Add(await repo.Get(id));

// ✓ One query, or bounded concurrency
var all = await repo.GetMany(ids);
await Parallel.ForEachAsync(ids, new ParallelOptions { MaxDegreeOfParallelism = 8 }, async (id, ct) => { /* ... */ });

// ✗ Blocking on async — thread-pool starvation under load
var data = FetchAsync().Result;

// ✓ ValueTask for hot paths that usually complete synchronously (cache hits)
public ValueTask<Product?> Get(int id)
{
    if (_cache.TryGetValue(id, out var p)) return ValueTask.FromResult<Product?>(p);   // no allocation
    return new ValueTask<Product?>(LoadAsync(id));
}

// ✓ Return the task directly when there's nothing to do after it (no state machine)
public Task<string> Load(string url) => _http.GetStringAsync(url);

// ✗ Async void / fire-and-forget hides exceptions and load
// ✓ Queue to a Channel + BackgroundService (see Threading page)

// ✓ ConfigureAwait(false) in library code avoids context hops (no effect in ASP.NET Core, harmless)

// Pool the timers: Task.Delay in tight loops → PeriodicTimer
using var timer = new PeriodicTimer(TimeSpan.FromSeconds(1));
while (await timer.WaitForNextTickAsync(ct)) { /* ... */ }

// Diagnose starvation:
//   dotnet-counters monitor --process-id <pid> System.Runtime
//   watch "ThreadPool Queue Length" and "ThreadPool Thread Count" climbing together
import asyncio

# ✗ Sequential awaits in a loop
for id in ids: results.append(await repo.get(id))

# ✓ One query, or bounded concurrency
results = await repo.get_many(ids)
sem = asyncio.Semaphore(8)
async def one(id):
    async with sem: return await repo.get(id)
results = await asyncio.gather(*(one(i) for i in ids))

# ✗ Blocking the event loop (CPU work or sync I/O inside async def)
async def handler(): data = requests.get(url)          # freezes every other request
# ✓ offload
async def handler(): data = await asyncio.to_thread(requests.get, url)

# ✗ Creating a coroutine per hot call when a sync path exists
async def get(id):
    if id in cache: return cache[id]                   # still pays coroutine overhead
# ✓ check the cache synchronously in the caller; only await on miss

# ✓ Fire-and-forget safely: keep a reference and log exceptions
background = set()
def spawn(coro):
    t = asyncio.create_task(coro); background.add(t)
    t.add_done_callback(background.discard)
    t.add_done_callback(lambda t: t.exception() and logging.error(t.exception()))

# Diagnose a blocked loop: PYTHONASYNCIODEBUG=1 logs callbacks slower than 100ms

Caching strategies

The cheapest operation is the one you skip. Cache-aside with IMemoryCache for per-instance hot data; IDistributedCache/Redis for shared state across instances; HybridCache (.NET 9) for both with stampede protection. Set size limits and expirations, key carefully, and measure hit ratio. Invalidation is the hard part — prefer short TTLs over clever invalidation.

builder.Services.AddMemoryCache(o => o.SizeLimit = 10_000);    // entries must declare a Size

public class ProductCache(IMemoryCache cache, IProductRepo repo)
{
    private static readonly SemaphoreSlim _gate = new(1, 1);

    public async Task<Product?> Get(int id, CancellationToken ct)
    {
        if (cache.TryGetValue($"p:{id}", out Product? p)) return p;

        await _gate.WaitAsync(ct);                     // stampede protection (coarse; HybridCache does per-key)
        try
        {
            if (cache.TryGetValue($"p:{id}", out p)) return p;
            p = await repo.Get(id, ct);
            cache.Set($"p:{id}", p, new MemoryCacheEntryOptions
            {
                Size = 1,
                AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(10),
                SlidingExpiration = TimeSpan.FromMinutes(2),
                Priority = CacheItemPriority.High
            }.RegisterPostEvictionCallback((k, v, reason, _) => Console.WriteLine($"{k} evicted: {reason}")));
            return p;
        }
        finally { _gate.Release(); }
    }

    public void Invalidate(int id) => cache.Remove($"p:{id}");
}

// HybridCache (.NET 9): L1 + L2, per-key stampede protection, tags for bulk invalidation
builder.Services.AddHybridCache();
builder.Services.AddStackExchangeRedisCache(o => o.Configuration = "localhost");
public class Catalog(HybridCache cache, IProductRepo repo)
{

        cache.GetOrCreateAsync($"p:{id}", async token => await repo.Get(id, token),
            new HybridCacheEntryOptions { Expiration = TimeSpan.FromMinutes(10) }, tags: ["products"], ct);
    public Task InvalidateAll(CancellationToken ct) => cache.RemoveByTagAsync("products", ct);
}

Measuring with BenchmarkDotNet

Never optimise on a hunch. BenchmarkDotNet runs your method thousands of times in a separate process with warm-up, reports mean/error/allocations, and handles JIT tiering. Use [MemoryDiagnoser] for allocations and [Params] for input sizes. Python has timeit and pytest-benchmark.

// dotnet add package BenchmarkDotNet — run in Release: dotnet run -c Release
[MemoryDiagnoser]
[SimpleJob(RuntimeMoniker.Net80), SimpleJob(RuntimeMoniker.Net90)]   // compare runtimes
public class JoinBenchmarks
{
    [Params(10, 1_000)] public int N;
    private string[] _items = null!;

    [GlobalSetup] public void Setup() => _items = Enumerable.Range(0, N).Select(i => i.ToString()).ToArray();

    [Benchmark(Baseline = true)]
    public string Concat() { var s = ""; foreach (var x in _items) s += x + ","; return s; }

    [Benchmark]
    public string Builder() { var sb = new StringBuilder(); foreach (var x in _items) sb.Append(x).Append(','); return sb.ToString(); }

    [Benchmark]
    public string Join() => string.Join(",", _items);
}

BenchmarkRunner.Run<JoinBenchmarks>();

Profiling and diagnostics in production

The dotnet-* global tools work against any running .NET process, including in containers: dotnet-counters for live metrics (GC, thread pool, exceptions), dotnet-trace for CPU sampling, dotnet-dump + dotnet-gcdump for memory. Wire EventCounters/System.Diagnostics.Metrics into OpenTelemetry so you can see the same numbers on a dashboard.

dotnet tool install -g dotnet-counters dotnet-trace dotnet-dump dotnet-gcdump

# Live metrics: GC heap, gen0/1/2 counts, thread pool queue, exceptions/sec
dotnet-counters monitor --process-id <pid> System.Runtime Microsoft.AspNetCore.Hosting

# CPU sampling for 30s → open in PerfView / Visual Studio / speedscope
dotnet-trace collect --process-id <pid> --duration 00:00:30 --format speedscope

# Heap snapshot: who holds the memory?
dotnet-gcdump collect --process-id <pid>          # open .gcdump in VS or PerfView

# Full dump for a hang/deadlock
dotnet-dump collect --process-id <pid>
dotnet-dump analyze core_xxx
> clrstack -all          # every managed thread's stack
> dumpheap -stat         # object counts by type
> gcroot <address>       # why is this object alive?

// Custom metrics via System.Diagnostics.Metrics → OpenTelemetry → Prometheus/App Insights
public class OrderMetrics
{
    private static readonly Meter _meter = new("Shop.Orders", "1.0");
    private static readonly Counter<long> _placed = _meter.CreateCounter<long>("orders.placed");
    private static readonly Histogram<double> _latency = _meter.CreateHistogram<double>("orders.place.duration", "ms");

    public void Record(double ms, string channel)
    {
        _placed.Add(1, new KeyValuePair<string, object?>("channel", channel));
        _latency.Record(ms);
    }
}
