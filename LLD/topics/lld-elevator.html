Design an Elevator Bank

The prompt that rewards asking first: hall calls and car calls are different things, a bank needs a dispatcher as well as a scheduler, and the sweep every real lift uses has a name. Tick-driven so it stays deterministic and testable.

Requirements: the two questions that matter

An elevator bank is the LLD prompt that most rewards asking before coding, because two questions completely change the problem and candidates routinely guess wrong on both.

  1. One elevator or a bank? One elevator is a scheduling problem inside a single state machine. A bank is also a dispatch problem — which car answers this request — and dispatch is where the interesting design lives. Assume a bank unless told otherwise; it is the more interesting answer and it degrades gracefully to one car.
  2. Who requests what? There are two genuinely different requests and conflating them is the classic modelling error. An external (hall) call comes from a floor and carries a direction but no destination — someone pressed Up on floor 3. An internal (car) call comes from inside a car and carries a destination but no direction. They are dispatched differently and they belong in different queues.

Scope it to: a bank of N cars, hall calls with a direction, car calls with a destination, a tick-driven simulation, and a pluggable dispatcher. That is a full 45 minutes.

Interview angle

Say the hall-call versus car-call distinction out loud in the first two minutes. It is the single clearest signal that you have thought about elevators rather than about queues, and it immediately gives the interviewer something to engage with. The second-best move is to propose the tick-driven simulation — "I will give the controller a Step() that advances everything one floor, so the whole thing is deterministic and testable" — because the alternative, real timers, makes the design untestable and you will not get to show it working.

Practice
  • Write the difference between a hall call and a car call in one sentence each, from memory.
  • List three things you would explicitly cut from this prompt in the first minute.

The model: a car is a state machine, the bank is a dispatcher

Each car is a small state machine with a direction and two sets of pending stops. The bank holds the cars and a dispatcher that decides which car answers a hall call. That split is the design: the car knows how to serve stops, the dispatcher knows which car should get them, and neither needs to know the other's rules.

The LOOK algorithm, which is what a real elevator does

Elevators do not serve requests first-come-first-served, and saying so earns credit. They sweep: keep going in the current direction, stopping at every pending stop on the way, and reverse only when there is nothing further ahead. That is the LOOK disk-scheduling algorithm, and it is why a lift that passes your floor going the other way does not stop. It is both more efficient and more fair than FCFS, which can starve a high floor indefinitely. Naming it — "this is essentially the elevator algorithm, LOOK" — is a nice touch because the algorithm is literally named after the problem.

Practice
  • Simulate by hand: a car at floor 1 going up with stops at 3 and 7, and a new stop at 2. Where does it go, and why not to 2 first?
  • Work out what FCFS would do with ten requests arriving from alternating ends, and convince yourself LOOK is better.

The implementation

The car first — it is self-contained and it is where the algorithm lives — then the dispatcher, then the bank. Complete and runnable, with time modelled as explicit ticks.

public enum Direction { Idle, Up, Down }

public sealed class Elevator(int id, int currentFloor, int minFloor, int maxFloor)
{
    private readonly SortedSet<int> _stops = [];

    public int Id { get; } = id;
    public int CurrentFloor { get; private set; } = currentFloor;
    public Direction Direction { get; private set; } = Direction.Idle;
    public IReadOnlyCollection<int> Stops => _stops;
    public bool IsIdle => Direction == Direction.Idle && _stops.Count == 0;

    public void AddStop(int floor)
    {
        if (floor < minFloor || floor > maxFloor)
            throw new ArgumentOutOfRangeException(nameof(floor));
        if (floor == CurrentFloor && Direction == Direction.Idle) return;  // already here
        _stops.Add(floor);
        if (Direction == Direction.Idle)
            Direction = floor > CurrentFloor ? Direction.Up : Direction.Down;
    }

    /// One tick: move a floor, or open the doors here. Returns true if it stopped.
    public bool Step()
    {
        if (_stops.Count == 0) { Direction = Direction.Idle; return false; }

        if (_stops.Remove(CurrentFloor))          // doors open at this floor
        {
            if (_stops.Count == 0) Direction = Direction.Idle;
            else ReorientIfNothingAhead();
            return true;
        }

        ReorientIfNothingAhead();
        CurrentFloor += Direction == Direction.Up ? 1 : -1;

        if (_stops.Remove(CurrentFloor))          // arrived at a stop
        {
            if (_stops.Count == 0) Direction = Direction.Idle;
            else ReorientIfNothingAhead();
            return true;
        }
        return false;
    }

    // LOOK: only reverse when there is nothing further in this direction.
    private void ReorientIfNothingAhead()
    {
        bool anyAbove = _stops.Any(f => f > CurrentFloor);
        bool anyBelow = _stops.Any(f => f < CurrentFloor);
        if (Direction == Direction.Up && !anyAbove) Direction = anyBelow ? Direction.Down : Direction.Idle;
        else if (Direction == Direction.Down && !anyBelow) Direction = anyAbove ? Direction.Up : Direction.Idle;
        else if (Direction == Direction.Idle && (anyAbove || anyBelow))
            Direction = anyAbove ? Direction.Up : Direction.Down;
    }

    /// Would this car pass 'floor' travelling 'heading' without reversing?
    public bool IsOnTheWay(int floor, Direction heading) => Direction switch
    {
        Direction.Idle => true,
        Direction.Up   => heading == Direction.Up   && floor >= CurrentFloor,
        Direction.Down => heading == Direction.Down && floor <= CurrentFloor,
        _ => false,
    };
}

// ---- the seam ----------------------------------------------------------
public readonly record struct HallCall(int Floor, Direction Heading);

public interface IDispatchStrategy
{
    Elevator? Select(IReadOnlyList<Elevator> cars, HallCall call);
}

/// Simplest defensible rule: nearest car, preferring one already heading your way.
public sealed class NearestCar : IDispatchStrategy
{
    public Elevator? Select(IReadOnlyList<Elevator> cars, HallCall call) =>
        cars.OrderBy(c => c.IsOnTheWay(call.Floor, call.Heading) ? 0 : 1)
            .ThenBy(c => Math.Abs(c.CurrentFloor - call.Floor))
            .ThenBy(c => c.Stops.Count)            // tie-break: least loaded
            .FirstOrDefault();
}

/// Alternative: spread the load. Same interface, different policy.
public sealed class LeastBusy : IDispatchStrategy
{
    public Elevator? Select(IReadOnlyList<Elevator> cars, HallCall call) =>
        cars.OrderBy(c => c.Stops.Count)
            .ThenBy(c => Math.Abs(c.CurrentFloor - call.Floor))
            .FirstOrDefault();
}

// ---- the bank ----------------------------------------------------------
public sealed class ElevatorSystem(IReadOnlyList<Elevator> cars, IDispatchStrategy dispatch)
{
    public IReadOnlyList<Elevator> Cars { get; } = cars;

    /// A landing button: direction known, destination not.
    public Elevator RequestFromFloor(int floor, Direction heading)
    {
        var car = dispatch.Select(Cars, new HallCall(floor, heading))
                  ?? throw new InvalidOperationException("No car available.");
        car.AddStop(floor);
        return car;
    }

    /// A button inside a car: destination known, direction not.
    public void RequestFromInside(int carId, int destination) =>
        Cars.Single(c => c.Id == carId).AddStop(destination);

    /// Advance every car one tick. Returns the cars that opened their doors.
    public IReadOnlyList<Elevator> Step() =>
        Cars.Where(c => c.Step()).ToList();
}
from __future__ import annotations
from dataclasses import dataclass
from enum import Enum, auto
from typing import Protocol

class Direction(Enum):
    IDLE = auto(); UP = auto(); DOWN = auto()

class Elevator:
    def __init__(self, id: int, current_floor: int, min_floor: int, max_floor: int) -> None:
        self.id = id
        self.current_floor = current_floor
        self.direction = Direction.IDLE
        self._min, self._max = min_floor, max_floor
        self._stops: set[int] = set()

    @property
    def stops(self) -> set[int]:
        return set(self._stops)

    @property
    def is_idle(self) -> bool:
        return self.direction is Direction.IDLE and not self._stops

    def add_stop(self, floor: int) -> None:
        if not self._min <= floor <= self._max:
            raise ValueError(f"floor {floor} out of range")
        if floor == self.current_floor and self.direction is Direction.IDLE:
            return                                        # already here
        self._stops.add(floor)
        if self.direction is Direction.IDLE:
            self.direction = Direction.UP if floor > self.current_floor else Direction.DOWN

    def step(self) -> bool:
        """One tick: move a floor, or open the doors here. True if it stopped."""
        if not self._stops:
            self.direction = Direction.IDLE
            return False

        if self.current_floor in self._stops:             # doors open here
            self._stops.discard(self.current_floor)
            self._reorient()
            return True

        self._reorient()
        self.current_floor += 1 if self.direction is Direction.UP else -1

        if self.current_floor in self._stops:             # arrived at a stop
            self._stops.discard(self.current_floor)
            self._reorient()
            return True
        return False

    def _reorient(self) -> None:
        """LOOK: only reverse when there is nothing further this way."""
        if not self._stops:
            self.direction = Direction.IDLE
            return
        above = any(f > self.current_floor for f in self._stops)
        below = any(f < self.current_floor for f in self._stops)
        if self.direction is Direction.UP and not above:
            self.direction = Direction.DOWN if below else Direction.IDLE
        elif self.direction is Direction.DOWN and not below:
            self.direction = Direction.UP if above else Direction.IDLE
        elif self.direction is Direction.IDLE:
            self.direction = Direction.UP if above else Direction.DOWN

    def is_on_the_way(self, floor: int, heading: Direction) -> bool:
        if self.direction is Direction.IDLE:
            return True
        if self.direction is Direction.UP:
            return heading is Direction.UP and floor >= self.current_floor
        return heading is Direction.DOWN and floor <= self.current_floor

# ---- the seam ----------------------------------------------------------
@dataclass(frozen=True)
class HallCall:
    floor: int
    heading: Direction

class DispatchStrategy(Protocol):
    def select(self, cars: list[Elevator], call: HallCall) -> Elevator | None: ...

class NearestCar:
    """Nearest car, preferring one already heading your way."""
    def select(self, cars: list[Elevator], call: HallCall) -> Elevator | None:
        if not cars:
            return None
        return min(cars, key=lambda c: (
            0 if c.is_on_the_way(call.floor, call.heading) else 1,
            abs(c.current_floor - call.floor),
            len(c.stops),
            c.id,
        ))

class LeastBusy:
    """Same interface, different policy."""
    def select(self, cars: list[Elevator], call: HallCall) -> Elevator | None:
        if not cars:
            return None
        return min(cars, key=lambda c: (len(c.stops),
                                        abs(c.current_floor - call.floor), c.id))

# ---- the bank ----------------------------------------------------------
class ElevatorSystem:
    def __init__(self, cars: list[Elevator], dispatch: DispatchStrategy) -> None:
        self.cars = cars
        self._dispatch = dispatch

    def request_from_floor(self, floor: int, heading: Direction) -> Elevator:
        """A landing button: direction known, destination not."""
        car = self._dispatch.select(self.cars, HallCall(floor, heading))
        if car is None:
            raise RuntimeError("No car available.")
        car.add_stop(floor)
        return car

    def request_from_inside(self, car_id: int, destination: int) -> None:
        """A button inside a car: destination known, direction not."""
        next(c for c in self.cars if c.id == car_id).add_stop(destination)

    def step(self) -> list[Elevator]:
        """Advance every car one tick; return the ones that opened doors."""
        return [c for c in self.cars if c.step()]
Interview angle

The method worth pointing at is IsOnTheWay. It is three lines, and it is the entire reason the dispatcher can be smart: a car travelling up past your floor is a much better answer than a closer car travelling down, and without that predicate the dispatcher can only compare distances. Candidates who dispatch purely on Math.Abs(current - floor) produce a system where pressing Up gets you a car that then takes you down first — and interviewers do test exactly that scenario. The other thing to volunteer is that time is a parameter, not a thread: Step() makes the whole system deterministic, so you can assert on an exact sequence of floors. Any design here that uses real timers cannot be demonstrated in the room.

Practice
  • Trace a car at floor 5 going up with stops {2, 8}: which floor does it reach first, and when does _reorient flip it?
  • Write the test "a car going up past floor 3 is preferred over a closer car going down".
  • Implement a third dispatcher that minimises total waiting time across all pending calls, and say why it is harder to justify.

Follow-ups and the hard parts

Follow-upThe answer
"Spread the load instead"Inject LeastBusy — one class, nothing else moves
"Add capacity limits"Elevator gains occupancy; dispatch skips full cars; a full car must still stop for its own car calls
"Express cars that only serve 10+"A served-floors predicate on the car; the dispatcher filters on it
"Fire recall / maintenance mode"A car-level mode that clears stops and overrides dispatch — a state machine on the car
"Minimise average wait, not distance"A dispatcher that simulates each candidate assignment and scores it; say it is a cost function, and that it is where real systems get complicated
"Make the hall call persist if no car can take it"The pending-calls queue, re-dispatched each tick — the piece most designs leave out

That last one is the most common gap. In the implementation above, RequestFromFloor assigns a car immediately and permanently. Real banks do better: hold the call, and re-evaluate each tick, because a better car may become available. Mentioning it is enough; implementing it is a nice extension if time allows.

// Deferred dispatch: hold hall calls and re-evaluate every tick, so a car
// that frees up can steal a call it is now better placed to serve.
public sealed class DeferredElevatorSystem(IReadOnlyList<Elevator> cars, IDispatchStrategy dispatch)
{
    private readonly HashSet<HallCall> _pending = [];

    public void RequestFromFloor(int floor, Direction heading) =>
        _pending.Add(new HallCall(floor, heading));        // set: dedupes repeats

    public IReadOnlyList<Elevator> Step()
    {
        foreach (var call in _pending.ToList())
        {
            var car = dispatch.Select(cars, call);
            // Only commit when a car can serve it without reversing.
            if (car is not null && car.IsOnTheWay(call.Floor, call.Heading))
            {
                car.AddStop(call.Floor);
                _pending.Remove(call);
            }
        }
        return cars.Where(c => c.Step()).ToList();
    }
}
class DeferredElevatorSystem:
    """Hold hall calls and re-evaluate every tick, so a car that frees up can
    steal a call it is now better placed to serve."""
    def __init__(self, cars: list[Elevator], dispatch: DispatchStrategy) -> None:
        self.cars = cars
        self._dispatch = dispatch
        self._pending: set[HallCall] = set()        # set: dedupes repeats

    def request_from_floor(self, floor: int, heading: Direction) -> None:
        self._pending.add(HallCall(floor, heading))

    def step(self) -> list[Elevator]:
        for call in list(self._pending):
            car = self._dispatch.select(self.cars, call)
            # Only commit when a car can serve it without reversing.
            if car is not None and car.is_on_the_way(call.floor, call.heading):
                car.add_stop(call.floor)
                self._pending.discard(call)
        return [c for c in self.cars if c.step()]
Starvation, the question you should raise yourself

Pure LOOK can starve. If calls keep arriving above a car, it may never reverse to serve the person waiting below. Real systems bound this — a call older than N ticks gets priority, or the sweep is forced to complete to the end of its range before reversing. Raising starvation before the interviewer does is one of the highest-value moves available in this problem, because it shows you are reasoning about the algorithm's failure mode rather than just implementing it. You do not have to solve it; naming it and proposing an ageing policy is a complete answer.

Interview angle

If you are running short on time, cut the dispatcher to "nearest car" and spend the remaining minutes on the car's state machine instead — the Step/_reorient pair is what is actually being graded, because it is where the correctness lives and where off-by-ones hide. A perfect dispatcher attached to a car that reverses at the wrong moment is a worse answer than a crude dispatcher attached to a car that provably sweeps correctly. And when you demonstrate it, print the floor sequence over ten ticks rather than describing it; a concrete trace is the fastest way to convince an interviewer that the thing works.

Practice
  • Implement ageing: a hall call older than N ticks outranks direction matching. Check that LOOK still holds for everything else.
  • Add capacity and get the subtle case right: a full car must still stop for the car calls of people already inside it.
  • Produce a ten-tick trace for three cars and six mixed calls, and check it by hand.
