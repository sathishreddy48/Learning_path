Requirements: what to ask and what to rule out

The canonical warm-up, and the one most likely to open an LLD round. It is deceptively open-ended, so the first five minutes are about closing it. Here is a realistic clarifying exchange and the scope it produces.

Interview angle

The question that separates candidates here is "can a small vehicle use a large spot?" Almost nobody asks it, and it changes the allocation algorithm from a dictionary lookup to an ordered search — which then makes the follow-up "should a motorcycle be allowed to take the last truck spot?" a design conversation rather than a bug. Ask it. The second-best question is "one entrance or several?", because it is how concurrency legitimately enters the design, and a concurrency discussion you introduced yourself scores better than one you were forced into.

The model

Nouns: lot, floor, spot, vehicle, ticket, fee. Verbs: park, leave, compute fee, find spot, occupy, release. Assigning each verb to the class that owns the data gives the model almost immediately — the only interesting decision is where occupancy lives, and the answer is on the spot itself, because that is the only place invariant I1 can be enforced atomically.

ParkingLot                 (entry point; owns the floors, holds the policies)

Why SpotSize is ordered

Making SpotSize an ordered enum (Small = 1, Medium = 2, Large = 3) rather than an unordered tag is a small decision that pays for itself twice. It makes invariant I3 a single comparison (spot.Size >= vehicle.RequiredSize), and it makes "search upwards from the smallest spot that fits" the natural allocation, which is also the one that wastes the least space. When the interviewer asks "why not just a dictionary keyed by size?", the answer is that a dictionary cannot express fits in, only equals.

Interview angle

Be ready to defend putting occupancy on ParkingSpot rather than keeping a Dictionary<Spot, Vehicle> on the lot. The argument is the invariant: if occupancy lives on the spot, then "a spot holds at most one vehicle" is enforced by one compare-and-set in one place, and no caller can get it wrong. If it lives in a dictionary on the lot, every code path that touches the dictionary has to remember the rule, and under concurrency you need a lock around the whole map rather than per-spot atomics. That is the general principle this round is testing — put the invariant where the data is — and the parking lot is a clean place to demonstrate it.

Practice
  • List every place invariant I1 could be violated if occupancy lived on the lot instead of the spot.
  • Add "electric vehicles need a charging spot". Decide whether that is a new SpotSize, a flag on the spot, or a new concept — and justify it.

The implementation

Written in the order you would write it in the room: the value objects and entities first, because they are quick and they fix the vocabulary, then the policies, then the lot that orchestrates them. This is complete and runnable.

using System.Collections.Concurrent;

public enum SpotSize { Small = 1, Medium = 2, Large = 3 }

public readonly record struct Money(decimal Amount)
{
    public static readonly Money Zero = new(0m);
    public override string ToString() => $"{Amount:0.00}";
}

public abstract class Vehicle(string plate)
{
    public string Plate { get; } = plate;
    public abstract SpotSize RequiredSize { get; }
}
public sealed class Motorcycle(string p) : Vehicle(p) { public override SpotSize RequiredSize => SpotSize.Small; }
public sealed class Car(string p)        : Vehicle(p) { public override SpotSize RequiredSize => SpotSize.Medium; }
public sealed class Truck(string p)      : Vehicle(p) { public override SpotSize RequiredSize => SpotSize.Large; }

// I1 lives here. TryOccupy is the ONLY way to take a spot, and it is atomic.
public sealed class ParkingSpot(string id, SpotSize size, int floorNumber)
{
    private readonly object _gate = new();
    public string Id { get; } = id;
    public SpotSize Size { get; } = size;
    public int FloorNumber { get; } = floorNumber;
    public Vehicle? OccupiedBy { get; private set; }

    public bool IsFree { get { lock (_gate) return OccupiedBy is null; } }

    public bool Fits(Vehicle v) => Size >= v.RequiredSize;          // I3

    public bool TryOccupy(Vehicle v)
    {
        if (!Fits(v)) return false;
        lock (_gate)
        {
            if (OccupiedBy is not null) return false;               // lost the race
            OccupiedBy = v;
            return true;
        }
    }

    public void Release()
    {
        lock (_gate) OccupiedBy = null;
    }
}

public sealed class Floor(int number, IReadOnlyList<ParkingSpot> spots)
{
    public int Number { get; } = number;
    public IReadOnlyList<ParkingSpot> Spots { get; } = spots;

    public IEnumerable<ParkingSpot> FreeSpotsFor(Vehicle v) =>
        Spots.Where(s => s.Fits(v) && s.IsFree)
             .OrderBy(s => s.Size);        // smallest that fits: least waste
}

// I2 lives here.
public sealed class Ticket(string id, ParkingSpot spot, Vehicle vehicle, DateTime entryTime)
{
    public string Id { get; } = id;
    public ParkingSpot Spot { get; } = spot;
    public Vehicle Vehicle { get; } = vehicle;
    public DateTime EntryTime { get; } = entryTime;
    public DateTime? ExitTime { get; private set; }
    public Money? Fee { get; private set; }

    public bool IsClosed => ExitTime is not null;
    public TimeSpan Duration(DateTime now) => (ExitTime ?? now) - EntryTime;

    public void Close(DateTime exitTime, Money fee)
    {
        if (IsClosed) throw new InvalidOperationException($"Ticket {Id} already closed.");
        if (exitTime < EntryTime) throw new ArgumentException("Exit precedes entry.");
        ExitTime = exitTime;
        Fee = fee;
    }
}

// ---- the two seams -----------------------------------------------------
public interface ISpotAllocationStrategy
{
    ParkingSpot? Find(IReadOnlyList<Floor> floors, Vehicle vehicle);
}

public sealed class FirstAvailable : ISpotAllocationStrategy
{
    public ParkingSpot? Find(IReadOnlyList<Floor> floors, Vehicle v) =>
        floors.SelectMany(f => f.FreeSpotsFor(v)).FirstOrDefault();
}

public sealed class NearestToEntrance : ISpotAllocationStrategy
{
    public ParkingSpot? Find(IReadOnlyList<Floor> floors, Vehicle v) =>
        floors.SelectMany(f => f.FreeSpotsFor(v))
              .OrderBy(s => s.FloorNumber).ThenBy(s => s.Id)
              .FirstOrDefault();
}

public interface IPricingStrategy { Money Price(Ticket ticket, DateTime now); }

public sealed class FlatHourlyPricing(decimal perHour) : IPricingStrategy
{
    public Money Price(Ticket t, DateTime now)
    {
        var hours = Math.Max(1, (int)Math.Ceiling(t.Duration(now).TotalHours));
        return new Money(perHour * hours);
    }
}

public sealed class PerSizePricing(IReadOnlyDictionary<SpotSize, decimal> rates) : IPricingStrategy
{
    public Money Price(Ticket t, DateTime now)
    {
        var hours = Math.Max(1, (int)Math.Ceiling(t.Duration(now).TotalHours));
        return new Money(rates[t.Vehicle.RequiredSize] * hours);
    }
}

public interface IClock { DateTime Now { get; } }
public sealed class SystemClock : IClock { public DateTime Now => DateTime.UtcNow; }

// ---- the orchestrator --------------------------------------------------
public sealed class ParkingLot(
    IReadOnlyList<Floor> floors,
    ISpotAllocationStrategy allocation,
    IPricingStrategy pricing,
    IClock clock)
{
    private readonly ConcurrentDictionary<string, Ticket> _open = new();
    private int _nextTicket;

    public Ticket Park(Vehicle vehicle)
    {
        // Retry: between Find and TryOccupy another entrance may have taken it.
        for (int attempt = 0; attempt < 10; attempt++)
        {
            var spot = allocation.Find(floors, vehicle);
            if (spot is null) throw new InvalidOperationException("Lot full.");
            if (!spot.TryOccupy(vehicle)) continue;                 // lost: try again

            var id = $"T{Interlocked.Increment(ref _nextTicket)}";
            var ticket = new Ticket(id, spot, vehicle, clock.Now);
            _open[id] = ticket;
            return ticket;
        }
        throw new InvalidOperationException("Could not allocate a spot; too much contention.");
    }

    public Money Leave(string ticketId, DateTime now)
    {
        if (!_open.TryRemove(ticketId, out var ticket))             // I2, atomically
            throw new InvalidOperationException($"Unknown or already-closed ticket {ticketId}.");

        var fee = pricing.Price(ticket, now);
        ticket.Close(now, fee);
        ticket.Spot.Release();
        return fee;
    }

    public IReadOnlyDictionary<SpotSize, int> Availability() =>
        floors.SelectMany(f => f.Spots)
              .Where(s => s.IsFree)
              .GroupBy(s => s.Size)
              .ToDictionary(g => g.Key, g => g.Count());
}
from __future__ import annotations
import threading
from abc import ABC, abstractmethod
from collections import Counter
from dataclasses import dataclass
from datetime import datetime, timedelta
from enum import IntEnum
from math import ceil
from typing import Iterable, Protocol

class SpotSize(IntEnum):                 # ordered, so "fits in" is a comparison
    SMALL = 1
    MEDIUM = 2
    LARGE = 3

@dataclass(frozen=True)
class Money:
    amount: float
    def __str__(self) -> str: return f"{self.amount:.2f}"

ZERO = Money(0.0)

class Vehicle(ABC):
    def __init__(self, plate: str) -> None:
        self.plate = plate
    @property
    @abstractmethod
    def required_size(self) -> SpotSize: ...

class Motorcycle(Vehicle):
    @property
    def required_size(self) -> SpotSize: return SpotSize.SMALL
class Car(Vehicle):
    @property
    def required_size(self) -> SpotSize: return SpotSize.MEDIUM
class Truck(Vehicle):
    @property
    def required_size(self) -> SpotSize: return SpotSize.LARGE

class ParkingSpot:
    """I1 lives here: try_occupy is the only way in, and it is atomic."""
    def __init__(self, id: str, size: SpotSize, floor_number: int) -> None:
        self.id = id
        self.size = size
        self.floor_number = floor_number
        self._occupied_by: Vehicle | None = None
        self._lock = threading.Lock()

    @property
    def is_free(self) -> bool:
        with self._lock:
            return self._occupied_by is None

    @property
    def occupied_by(self) -> Vehicle | None:
        with self._lock:
            return self._occupied_by

    def fits(self, v: Vehicle) -> bool:
        return self.size >= v.required_size              # I3

    def try_occupy(self, v: Vehicle) -> bool:
        if not self.fits(v):
            return False
        with self._lock:
            if self._occupied_by is not None:
                return False                             # lost the race
            self._occupied_by = v
            return True

    def release(self) -> None:
        with self._lock:
            self._occupied_by = None

class Floor:
    def __init__(self, number: int, spots: list[ParkingSpot]) -> None:
        self.number = number
        self.spots = spots

    def free_spots_for(self, v: Vehicle) -> Iterable[ParkingSpot]:
        return sorted((s for s in self.spots if s.fits(v) and s.is_free),
                      key=lambda s: s.size)              # smallest that fits

class Ticket:
    """I2 lives here."""
    def __init__(self, id: str, spot: ParkingSpot, vehicle: Vehicle,
                 entry_time: datetime) -> None:
        self.id = id
        self.spot = spot
        self.vehicle = vehicle
        self.entry_time = entry_time
        self.exit_time: datetime | None = None
        self.fee: Money | None = None

    @property
    def is_closed(self) -> bool:
        return self.exit_time is not None

    def duration(self, now: datetime) -> timedelta:
        return (self.exit_time or now) - self.entry_time

    def close(self, exit_time: datetime, fee: Money) -> None:
        if self.is_closed:
            raise RuntimeError(f"Ticket {self.id} already closed.")
        if exit_time < self.entry_time:
            raise ValueError("Exit precedes entry.")
        self.exit_time = exit_time
        self.fee = fee

# ---- the two seams -----------------------------------------------------
class SpotAllocationStrategy(Protocol):
    def find(self, floors: list[Floor], vehicle: Vehicle) -> ParkingSpot | None: ...

class FirstAvailable:
    def find(self, floors: list[Floor], v: Vehicle) -> ParkingSpot | None:
        return next((s for f in floors for s in f.free_spots_for(v)), None)

class NearestToEntrance:
    def find(self, floors: list[Floor], v: Vehicle) -> ParkingSpot | None:
        candidates = [s for f in floors for s in f.free_spots_for(v)]
        return min(candidates, key=lambda s: (s.floor_number, s.id), default=None)

class PricingStrategy(Protocol):
    def price(self, ticket: Ticket, now: datetime) -> Money: ...

def _hours(t: Ticket, now: datetime) -> int:
    return max(1, ceil(t.duration(now).total_seconds() / 3600))

class FlatHourlyPricing:
    def __init__(self, per_hour: float) -> None:
        self._per_hour = per_hour
    def price(self, t: Ticket, now: datetime) -> Money:
        return Money(self._per_hour * _hours(t, now))

class PerSizePricing:
    def __init__(self, rates: dict[SpotSize, float]) -> None:
        self._rates = rates
    def price(self, t: Ticket, now: datetime) -> Money:
        return Money(self._rates[t.vehicle.required_size] * _hours(t, now))

class Clock(Protocol):
    def now(self) -> datetime: ...

class SystemClock:
    def now(self) -> datetime: return datetime.utcnow()

# ---- the orchestrator --------------------------------------------------
class ParkingLot:
    def __init__(self, floors: list[Floor], allocation: SpotAllocationStrategy,
                 pricing: PricingStrategy, clock: Clock) -> None:
        self._floors = floors
        self._allocation = allocation
        self._pricing = pricing
        self._clock = clock
        self._open: dict[str, Ticket] = {}
        self._next = 0
        self._lock = threading.Lock()

    def park(self, vehicle: Vehicle) -> Ticket:
        # Retry: between find and try_occupy another entrance may have taken it.
        for _ in range(10):
            spot = self._allocation.find(self._floors, vehicle)
            if spot is None:
                raise RuntimeError("Lot full.")
            if not spot.try_occupy(vehicle):
                continue                                  # lost: try again
            with self._lock:
                self._next += 1
                ticket = Ticket(f"T{self._next}", spot, vehicle, self._clock.now())
                self._open[ticket.id] = ticket
            return ticket
        raise RuntimeError("Could not allocate a spot; too much contention.")

    def leave(self, ticket_id: str, now: datetime) -> Money:
        with self._lock:
            ticket = self._open.pop(ticket_id, None)      # I2, atomically
        if ticket is None:
            raise RuntimeError(f"Unknown or already-closed ticket {ticket_id}.")
        fee = self._pricing.price(ticket, now)
        ticket.close(now, fee)
        ticket.spot.release()
        return fee

    def availability(self) -> dict[SpotSize, int]:
        return dict(Counter(s.size for f in self._floors
                            for s in f.spots if s.is_free))
Interview angle

Two details in that code are worth pointing at explicitly, because they are the difference between a design that looks thread-safe and one that is. First, the retry loop in Park: finding a free spot and taking it are two steps, so between them another entrance can win, and TryOccupy returning false is a normal outcome rather than an error. Candidates who lock the whole lot around both steps are correct but have serialised every entrance; candidates who ignore the gap have a double-booking bug. Second, TryRemove in Leave makes "close this ticket" atomic — the ticket is removed from the open map by exactly one caller, so a double exit fails cleanly without needing a lock. Say both of these out loud; they are cheap and they are exactly what the round rewards.

Practice
  • Write the park/leave flow and then the three invariant tests (I1, I2, I3) before adding any feature.
  • Replace the retry loop with a lock around the whole lot. Measure how many concurrent entrances it supports, and say when you would still prefer it.

Concurrency: where the races actually are

"Multiple entrances" is the prompt's invitation to talk about threading, and there are exactly three races worth naming. Being able to list them and say how each is handled is the single strongest thing you can do in the last ten minutes.

RaceWhat goes wrongHandled by
Two vehicles, one spotBoth see it free and both parkTryOccupy compare-and-set per spot, plus the retry loop
Double exitA ticket is paid twice, or a spot is released twiceAtomic remove from the open-ticket map; Close also throws
Availability is staleThe count is out of date the moment it is returnedAccepted deliberately — say so
Release then re-parkA spot is handed out before the leaver finishedRelease happens last, after the ticket is closed

The third row is the interesting one. Availability() walks the spots without a global lock, so it can return a number that was never simultaneously true. That is almost always the right trade — a parking display does not need linearisability — but you should say that you chose it rather than leave the interviewer wondering whether you noticed.

// The test that proves I1 holds under contention. Worth writing in the
// room if there is time, and worth describing if there is not.
[Fact]
public void Only_one_vehicle_wins_the_last_spot()
{
    var spot  = new ParkingSpot("S1", SpotSize.Medium, 0);
    var floor = new Floor(0, [spot]);
    var lot   = new ParkingLot([floor], new FirstAvailable(),
                               new FlatHourlyPricing(10m), new SystemClock());

    int parked = 0, rejected = 0;
    Parallel.For(0, 64, i =>
    {
        try { lot.Park(new Car($"KA-{i}")); Interlocked.Increment(ref parked); }
        catch (InvalidOperationException) { Interlocked.Increment(ref rejected); }
    });

    Assert.Equal(1, parked);          // exactly one winner
    Assert.Equal(63, rejected);
    Assert.False(spot.IsFree);
}

// ---- Granularity: three options, worth comparing out loud --------------
//
// A. One lock on the whole lot.
//    + trivially correct, easy to reason about
//    - every entrance serialises; a 10-floor lot behaves like a 1-car gate
//
// B. One lock per spot  (what the code above does)
//    + entrances contend only when they pick the SAME spot
//    - find-then-take is not atomic, so you need the retry loop
//
// C. A lock-free free-list per (floor, size)
//    + no scan at all: pop a spot in O(1)
//    - more state to keep consistent on release; harder to get right
//
// B is the right default for an interview: it is correct, it is genuinely
// concurrent, and the retry loop is three lines you can defend.
import threading

def test_only_one_vehicle_wins_the_last_spot():
    """Proves I1 under contention."""
    spot = ParkingSpot("S1", SpotSize.MEDIUM, 0)
    lot = ParkingLot([Floor(0, [spot])], FirstAvailable(),
                     FlatHourlyPricing(10.0), SystemClock())

    parked, rejected = [], []
    barrier = threading.Barrier(64)          # make them start together

    def attempt(i: int) -> None:
        barrier.wait()
        try:
            lot.park(Car(f"KA-{i}"))
            parked.append(i)
        except RuntimeError:
            rejected.append(i)

    threads = [threading.Thread(target=attempt, args=(i,)) for i in range(64)]
    for t in threads: t.start()
    for t in threads: t.join()

    assert len(parked) == 1                  # exactly one winner
    assert len(rejected) == 63
    assert not spot.is_free

The GIL does not make Python code thread-safe

A common wrong answer: "Python has a GIL so I do not need locks." The GIL serialises bytecode execution, not logical operations. if self._occupied_by is None: self._occupied_by = v is two bytecode sequences with a switch point between them, so two threads can both pass the check. The lock in try_occupy is genuinely required. The GIL means you will not corrupt the interpreter's own structures; it says nothing about your invariants. If the interviewer is a Python person, knowing this distinction is a real differentiator — and the same reasoning applies to asyncio, where an await inside a check-then-act is exactly the same bug.

Interview angle

If you only have time for one concurrency sentence, make it: "find-a-spot and take-a-spot are two operations, so I made taking it a compare-and-set and retry when I lose." That names the check-then-act race, gives the fix, and shows you understand why the naive version is wrong — all in one line. If you have longer, compare the three lock granularities above; interviewers like the comparison more than the implementation because it shows you chose rather than defaulted. The follow-up to be ready for is "what if this is distributed across processes?", and the answer is that the per-spot CAS becomes a conditional write in a shared store — the structure of the design does not change, only the mechanism.

Practice
  • Run the contention test a thousand times. If it ever passes with two winners, your CAS is wrong.
  • Remove the lock from try_occupy and get the test to fail — it may take many runs, which is itself the lesson about race bugs.
  • Design option C (free-lists) and work out what must happen on release to keep it consistent.

        Size >= v.RequiredSize && (!v.NeedsCharging || HasCharger);
}

public abstract class Vehicle(string plate)
{
    public string Plate { get; } = plate;
    public abstract SpotSize RequiredSize { get; }
    public virtual bool NeedsCharging => false;           // default: no
}

public sealed class ElectricCar(string p) : Vehicle(p)
{
    public override SpotSize RequiredSize => SpotSize.Medium;
    public override bool NeedsCharging => true;
}

// And when a THIRD requirement arrives (disabled bays, valet-only, oversize),
// the predicate is the thing that is now varying — so it becomes the seam:
public interface ISpotRequirement { bool IsSatisfiedBy(ParkingSpot spot); }
// ParkingSpot.Fits(v) => v.Requirements.All(r => r.IsSatisfiedBy(this));
# WRONG — size and capability are different axes.
class SpotSize(IntEnum):
    SMALL = 1; MEDIUM = 2; LARGE = 3; ELECTRIC = 4          # ✗

# RIGHT — capability is orthogonal to size.
class ParkingSpot:
    def __init__(self, id: str, size: SpotSize, floor_number: int,
                 has_charger: bool = False) -> None:
        self.id = id
        self.size = size
        self.floor_number = floor_number
        self.has_charger = has_charger
        ...

    def fits(self, v: "Vehicle") -> bool:
        return self.size >= v.required_size and (not v.needs_charging or self.has_charger)

class Vehicle(ABC):
    @property
    @abstractmethod
    def required_size(self) -> SpotSize: ...
    @property
    def needs_charging(self) -> bool:
        return False                                        # default: no

class ElectricCar(Vehicle):
    @property
    def required_size(self) -> SpotSize: return SpotSize.MEDIUM
    @property
    def needs_charging(self) -> bool: return True

# When a THIRD requirement arrives (disabled bays, valet-only, oversize),
# the predicate itself is what varies — so it becomes the seam:
class SpotRequirement(Protocol):
    def is_satisfied_by(self, spot: ParkingSpot) -> bool: ...
# ParkingSpot.fits(v) -> all(r.is_satisfied_by(self) for r in v.requirements)
The rule of three

Notice the progression in that last example. One requirement (size) is a comparison. Two (size and charging) is a boolean field and a compound predicate — still fine, and over-abstracting here would be a mistake. Three is when the predicate itself is clearly the thing varying, and extracting ISpotRequirement pays for itself. Saying this out loud — "I would keep it a field for now and extract an interface when a third one arrives" — is a better answer than either extreme, because it shows you can tell premature abstraction from necessary abstraction. Interviewers are testing for that judgement as much as for the abstraction itself.

Interview angle

When a follow-up arrives, say where it lands before you write anything: "that is a pricing change, so it is a new strategy and nothing else moves." Thirty seconds of placement is worth more than two minutes of code, and if your placement is wrong the interviewer will correct you before you have wasted the time. The one follow-up that should make you pause is reservations — it genuinely does not fit cleanly into the model above, because a reserved spot is neither free nor occupied, and the honest answer is that ParkingSpot gains a small state machine (Free → Reserved → Occupied). Recognising that a requirement does not fit your abstraction is a better signal than forcing it in.
