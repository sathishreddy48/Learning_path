App Service

PaaS hosting for web apps and APIs: deploy code or a container, get TLS, custom domains, deployment slots (blue/green with swap), autoscale, built-in auth (“Easy Auth”), and health-check-based instance replacement. The decision that matters: Linux vs Windows plan, and plan tier for scale-out and VNet integration. Use slots for zero-downtime deploys and WEBSITE_RUN_FROM_PACKAGE for atomic deployments.

Azure Functions

Event-driven compute: a function runs when a trigger fires (HTTP, timer, queue, Service Bus, Event Hubs, Cosmos change feed, blob). Bindings inject inputs and outputs so you write almost no plumbing. .NET uses the isolated worker model (your process, any .NET version). Consumption plan scales to zero; Premium/Dedicated/Flex for VNet, no cold start, longer runs. Durable Functions add orchestrations (fan-out/fan-in, human interaction, sagas) on top.

// Durable orchestration: fan-out/fan-in with retries
[Function(nameof(ProcessBatch))]
public static async Task<int> ProcessBatch([OrchestrationTrigger] TaskOrchestrationContext ctx)
{
    var ids = await ctx.CallActivityAsync<int[]>("GetIds");
    var tasks = ids.Select(id => ctx.CallActivityAsync<bool>("ProcessOne", id,
        new TaskOptions(new TaskRetryOptions(new RetryPolicy(3, TimeSpan.FromSeconds(5))))));
    var results = await Task.WhenAll(tasks);
    return results.Count(r => r);
}

Azure Storage: Blobs, Queues, Tables

One storage account, several services. Blob: objects (files, images, backups) with hot/cool/archive tiers, SAS tokens for delegated access, lifecycle policies. Queue: simple at-least-once messaging (64 KB messages, 7-day TTL) — cheaper and simpler than Service Bus when you don't need topics/sessions/ordering. Table: cheap key-value NoSQL (PartitionKey + RowKey) — largely superseded by Cosmos DB's Table API for scale.

Service Bus

Enterprise messaging: queues (point-to-point, competing consumers) and topics/subscriptions (pub/sub with SQL/correlation filters). Features that justify it over Storage Queues: dead-letter queues, sessions (ordered, stateful streams per key), duplicate detection, scheduled delivery, transactions, auto-forwarding, and up to 100 MB messages on Premium. Peek-lock delivery = at-least-once; make consumers idempotent.

// Azure.Messaging.ServiceBus
var client = new ServiceBusClient("shop-bus.servicebus.windows.net", new DefaultAzureCredential());

// Send with metadata; sessions for ordering per customer
await using var sender = client.CreateSender("order-placed");
await sender.SendMessageAsync(new ServiceBusMessage(BinaryData.FromObjectAsJson(evt))
{
    MessageId = $"order-{evt.OrderId}",                 // duplicate detection window (e.g. 10 min)
    SessionId = evt.CustomerId,                           // ordered per customer (session-enabled entity)
    Subject = "OrderPlaced",
    ApplicationProperties = { ["region"] = "eu", ["traceparent"] = Activity.Current?.Id },
    ScheduledEnqueueTime = DateTimeOffset.UtcNow.AddMinutes(5),   // optional delay
    TimeToLive = TimeSpan.FromDays(1)
});

// Batch for throughput
using var batch = await sender.CreateMessageBatchAsync();
foreach (var e in events) if (!batch.TryAddMessage(new ServiceBusMessage(BinaryData.FromObjectAsJson(e)))) { await sender.SendMessagesAsync(batch); /* new batch */ }

// Processor with peek-lock, concurrency and explicit settlement
var processor = client.CreateProcessor("order-placed", "invoicing", new ServiceBusProcessorOptions
{
    MaxConcurrentCalls = 16, AutoCompleteMessages = false, PrefetchCount = 32,
    MaxAutoLockRenewalDuration = TimeSpan.FromMinutes(5)
});
processor.ProcessMessageAsync += async args =>
{
    try
    {
        var e = args.Message.Body.ToObjectFromJson<OrderPlaced>();
        await Handle(e);                                       // idempotent on MessageId

    catch (Exception ex) { await args.DeadLetterMessageAsync(args.Message, "ProcessingFailed", ex.Message); }
};
processor.ProcessErrorAsync += args => { Console.WriteLine(args.Exception); return Task.CompletedTask; };
await processor.StartProcessingAsync();

Event Hubs

High-throughput event streaming (Kafka-compatible): millions of events per second into partitions, retained for 1–90 days, read by consumer groups with checkpointed offsets. This is telemetry, click streams, IoT and change data — not commands. Producers pick a partition key for ordering; consumers use the EventProcessorClient with Blob Storage checkpoints so a crashed reader resumes where it left off.

// Azure.Messaging.EventHubs + Azure.Messaging.EventHubs.Processor
var cred = new DefaultAzureCredential();

// Producer: batch by partition key for ordering per device
await using var producer = new EventHubProducerClient("shop-hub.servicebus.windows.net", "telemetry", cred);
using var batch = await producer.CreateBatchAsync(new CreateBatchOptions { PartitionKey = deviceId });
foreach (var reading in readings)
    if (!batch.TryAdd(new EventData(BinaryData.FromObjectAsJson(reading)) { ContentType = "application/json" }))
        throw new InvalidOperationException("event too large for batch");
await producer.SendAsync(batch);

// Consumer: processor with checkpoints in Blob Storage, one instance per partition across your replicas
var checkpoints = new BlobContainerClient(new Uri("https://shopstorage.blob.core.windows.net/checkpoints"), cred);
var processor = new EventProcessorClient(checkpoints, "$Default", "shop-hub.servicebus.windows.net", "telemetry", cred);

processor.ProcessEventAsync += async args =>
{
    if (args.Data is null) return;
    var reading = args.Data.EventBody.ToObjectFromJson<Reading>();
    await Aggregate(reading, args.Partition.PartitionId);
    if (args.Data.SequenceNumber % 100 == 0)               // checkpoint periodically, not per event
        await args.UpdateCheckpointAsync(args.CancellationToken);
};
processor.ProcessErrorAsync += args => { Console.WriteLine($"{args.PartitionId}: {args.Exception}"); return Task.CompletedTask; };
await processor.StartProcessingAsync();

Cosmos DB

Globally distributed, multi-model NoSQL with single-digit-millisecond latency and five consistency levels. The partition key is the whole design: choose a high-cardinality key that appears in most queries so reads are single-partition, and keep hot partitions under the 20 GB / 10k RU/s logical limit. Model for the access pattern (embed vs reference), budget in Request Units, and use the change feed for downstream processing.

public record Order(string id, string customerId, decimal total, string status, List<Line> lines, int? ttl = null);

// Create / upsert with optimistic concurrency (ETag)
var created = await orders.CreateItemAsync(new Order(Guid.NewGuid().ToString(), "c-42", 99m, "open", lines), new PartitionKey("c-42"));
Console.WriteLine($"{created.RequestCharge} RU");

}
catch (CosmosException ex) when (ex.StatusCode == HttpStatusCode.PreconditionFailed) { /* someone else changed it */ }

// Patch (partial update) — avoids read-modify-write

Key Vault

Central store for secrets (connection strings, API keys), keys (encryption, signing — the key never leaves the HSM) and certificates (with auto-renewal). Access via RBAC and managed identity; every access is audited. Reference secrets from App Service settings, load them into IConfiguration at startup, and cache — Key Vault is not built for per-request reads.

Managed Identity and DefaultAzureCredential

A managed identity is an Entra ID identity that Azure manages for a resource (system-assigned: tied to one resource; user-assigned: shared, survives resource deletion). Grant it RBAC roles, and the SDKs get tokens from the platform's IMDS endpoint — no secrets in config, nothing to rotate. DefaultAzureCredential tries environment → workload identity → managed identity → Azure CLI/VS/PowerShell, so the same code works locally and deployed.

Application Insights and Azure Monitor

Application Insights collects requests, dependencies, exceptions, traces, custom events/metrics and live metrics, and correlates them across services (application map, end-to-end transaction view). It sits on Log Analytics, queried with KQL. In .NET 8+ the recommended path is the OpenTelemetry-based Azure.Monitor.OpenTelemetry.AspNetCore distro; the classic SDK still works. AKS and Azure Container Apps

Two ways to run containers. Azure Container Apps: serverless containers on managed Kubernetes you never see — revisions, traffic splitting, KEDA scale-to-zero on HTTP/queue depth, Dapr sidecars. AKS: full Kubernetes when you need custom networking, operators, GPU nodes, or the whole ecosystem. Default to Container Apps for microservices; go to AKS when you hit its limits.
