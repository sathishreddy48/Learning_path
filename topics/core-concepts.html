Types, variables and type inference

C# is statically typed: every variable has a compile-time type. var asks the compiler to infer it — the variable is still strongly typed. Python variables are names bound to objects; the object has a type, the name does not. Knowing the default values and literal suffixes is a common warm-up question.

int count = 42;            // 32-bit signed integer
long big = 9_000_000_000L; // digit separators, L suffix
double ratio = 0.75;       // 64-bit float (default for literals)
decimal price = 19.99m;    // 128-bit, base-10 — use for money
bool ok = true;
char c = 'A';
string name = "Ada";

var inferred = 3.5;        // compiler infers double
const int MaxRetries = 3;  // compile-time constant

// Conversions
int i = (int)ratio;                 // explicit cast: 0
double d = count;                   // implicit widening
int parsed = int.Parse("123");
bool worked = int.TryParse("x", out int result); // false, result = 0

Console.WriteLine($"{name} has {count} items costing {price:C}");
count = 42                 # int (arbitrary precision)
big = 9_000_000_000        # same int type; no overflow
ratio = 0.75               # float (64-bit)
from decimal import Decimal
price = Decimal("19.99")   # base-10 decimal — use for money
ok = True
c = "A"                    # no char type; a 1-length str
name = "Ada"

inferred = 3.5             # names are untyped; objects are typed
MAX_RETRIES = 3            # convention only — no const keyword

# Conversions
i = int(ratio)             # truncates: 0
d = float(count)
parsed = int("123")
try:
    result = int("x")
except ValueError:
    result = 0             # no TryParse; use try/except

print(f"{name} has {count} items costing ${price:,.2f}")

Value types vs reference types

Value types (int, struct, enum, tuples) hold their data directly and are copied on assignment. Reference types (class, string, arrays, delegates) hold a reference to an object on the heap; assignment copies the reference, so two variables point at the same object. Python has only references — but immutable objects (ints, strings, tuples) behave like values because they cannot change in place.

struct Point { public int X; public int Y; }
class Person { public string Name = ""; }

var p1 = new Point { X = 1, Y = 2 };
var p2 = p1;          // copy
p2.X = 99;
Console.WriteLine(p1.X); // 1 — p1 untouched

var a = new Person { Name = "Ada" };
var b = a;            // same object
b.Name = "Grace";
Console.WriteLine(a.Name); // Grace

// Strings are reference types but immutable
string s1 = "hi";
string s2 = s1;
s2 += "!";            // creates a new string
Console.WriteLine(s1); // hi

// Passing by reference explicitly
static void Bump(ref int n) => n++;
int x = 1; Bump(ref x); // x == 2
from dataclasses import dataclass

@dataclass
class Point:      # mutable → reference semantics
    x: int
    y: int

p1 = Point(1, 2)
p2 = p1           # same object!
p2.x = 99
print(p1.x)       # 99 — unlike a C# struct

import copy
p3 = copy.copy(p1)   # explicit copy if you want value semantics
p3.x = 5
print(p1.x)       # 99

# Immutable objects act like values
s1 = "hi"
s2 = s1
s2 += "!"         # rebinds s2 to a new str
print(s1)         # hi

# No ref parameters — return the new value or mutate a container
def bump(n): return n + 1
x = bump(1)
Interview angle

Expect “where does a struct live?” The honest answer: it depends on where it is declared — a local struct is on the stack, a struct field inside a class is on the heap with its owner. Boxing copies a value type into a heap object; see the Performance page.

Strings and StringBuilder

Strings are immutable in both languages. Repeated concatenation in a loop allocates a new string each time — use StringBuilder (C#) or build a list and "".join() (Python). Interpolation, common methods and Span-free slicing are shown below.

string s = "  Hello, World  ";
s = s.Trim();                        // "Hello, World"
bool starts = s.StartsWith("Hello");
int idx = s.IndexOf("World");        // 7
string upper = s.ToUpperInvariant();
string sub = s.Substring(0, 5);      // "Hello"
string sliced = s[^5..];             // "World" (ranges, C# 8)
string[] parts = s.Split(", ");      // ["Hello", "World"]
string joined = string.Join("-", parts);
bool eq = string.Equals("a", "A", StringComparison.OrdinalIgnoreCase);

// Build efficiently
var sb = new StringBuilder();
for (int i = 0; i < 5; i++) sb.Append(i).Append(',');
string csv = sb.ToString().TrimEnd(',');   // "0,1,2,3,4"

// Interpolation with format specifiers
double pi = Math.PI;
Console.WriteLine($"{pi:F2} | {42,6} | {DateTime.Now:yyyy-MM-dd}");

// Verbatim + raw strings
string path = @"C:\temp\file.txt";
string json = """
    { "name": "Ada" }
    """;
s = "  Hello, World  "
s = s.strip()                        # "Hello, World"

sub = s[0:5]                         # "Hello"

# Raw + multi-line strings

Control flow

Loops and branches are near-identical. Differences worth knowing: C# switch supports pattern matching and a switch expression; Python 3.10 added match. C# foreach works over anything implementing IEnumerable<T>, just as Python for works over any iterable.

int[] nums = { 3, 8, 1, 9 };

foreach (var n in nums)
    if (n % 2 == 0) Console.WriteLine($"{n} even");
    else Console.WriteLine($"{n} odd");

for (int i = 0; i < nums.Length; i++) { /* index-based */ }

int attempts = 0;
while (attempts < 3) attempts++;
do { attempts--; } while (attempts > 0);

// switch statement with patterns
object value = 42;
switch (value)
{
    case int i when i > 40: Console.WriteLine("big int"); break;
    case int i:             Console.WriteLine("int"); break;
    case string s:          Console.WriteLine($"string {s}"); break;
    default:                Console.WriteLine("other"); break;
}

// switch expression (C# 8)
string Grade(int score) => score switch
{
    >= 90 => "A",
    >= 80 => "B",
    _     => "C"
};

// ternary and null-coalescing
string label = nums.Length > 3 ? "many" : "few";
string? maybe = null;
string sure = maybe ?? "default";
nums = [3, 8, 1, 9]

for n in nums:
    if n % 2 == 0:
        print(f"{n} even")
    else:
        print(f"{n} odd")

for i, n in enumerate(nums):
    pass  # index-based

attempts = 0
while attempts < 3:
    attempts += 1
# no do/while — use while True + break

# match statement (3.10+)
value = 42
match value:
    case int(i) if i > 40:
        print("big int")
    case int():
        print("int")
    case str(s):
        print(f"string {s}")
    case _:
        print("other")

def grade(score):
    if score >= 90: return "A"
    if score >= 80: return "B"
    return "C"

# conditional expression and "or" default
label = "many" if len(nums) > 3 else "few"
maybe = None
sure = maybe or "default"     # careful: "" and 0 are also falsy

Collections: List, Dictionary, HashSet, Queue, Stack

The generic collections in System.Collections.Generic map cleanly to Python built-ins. Know the big-O of each operation: List<T> index O(1), insert-at-front O(n); Dictionary/HashSet average O(1); Queue/Stack O(1) at the ends. Prefer interfaces (IList<T>, IReadOnlyList<T>, IEnumerable<T>) in method signatures.

var list = new List<int> { 3, 1, 2 };
list.Add(4); list.Insert(0, 9); list.Remove(1);
list.Sort();                          // in place
bool has = list.Contains(2);
int last = list[^1];

var ages = new Dictionary<string, int> { ["ada"] = 36 };
ages["grace"] = 45;
if (ages.TryGetValue("ada", out var age)) Console.WriteLine(age);
ages.TryAdd("ada", 0);                // no throw if exists
foreach (var (name, a) in ages) Console.WriteLine($"{name}={a}");

var seen = new HashSet<string> { "a", "b" };
bool added = seen.Add("a");           // false — already there
seen.UnionWith(new[] { "c" });

var queue = new Queue<string>();
queue.Enqueue("first"); queue.Enqueue("second");

var stack = new Stack<int>();
stack.Push(1); stack.Push(2);

Classes, structs and records

class = reference type with identity. struct = value type, keep small and immutable. record (C# 9) = reference type with value-based equality, ToString, deconstruction and with expressions — perfect for DTOs. record struct combines both. Python's @dataclass gives the same generated members; frozen=True makes it immutable like a positional record.

public class Account
{
    private decimal _balance;                 // field
    public string Owner { get; }              // read-only property
    public decimal Balance => _balance;       // expression-bodied getter

    public Account(string owner, decimal opening = 0)
    {
        Owner = owner ?? throw new ArgumentNullException(nameof(owner));
        _balance = opening;
    }

    public void Deposit(decimal amount)
    {
        if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
        _balance += amount;
    }

    public override string ToString() => $"{Owner}: {Balance:C}";
}

public readonly struct Point(int X, int Y)   // primary ctor, C# 12
{
    public int X { get; } = X;
    public int Y { get; } = Y;
    public double Length => Math.Sqrt(X * X + Y * Y);
}

public record Person(string First, string Last)
{
    public string Full => $"{First} {Last}";
}

var p1 = new Person("Ada", "Lovelace");
var p2 = p1 with { Last = "Byron" };       // non-destructive copy
Console.WriteLine(p1 == new Person("Ada", "Lovelace")); // True — value equality
var (first, last) = p1;                    // deconstruction
class Account:
    def __init__(self, owner: str, opening: float = 0):
        if owner is None:
            raise ValueError("owner")
        self._owner = owner          # "_" = private by convention
        self._balance = opening

    @property
    def owner(self) -> str:          # read-only property
        return self._owner

    @property
    def balance(self) -> float:
        return self._balance

    def deposit(self, amount: float) -> None:
        if amount <= 0:
            raise ValueError("amount")
        self._balance += amount

    def __str__(self) -> str:
        return f"{self.owner}: ${self.balance:,.2f}"


from dataclasses import dataclass, replace
import math

@dataclass(frozen=True)          # immutable, hashable — like a struct/record
class Point:
    x: int
    y: int
    @property
    def length(self) -> float:
        return math.hypot(self.x, self.y)

@dataclass(frozen=True)
class Person:
    first: str
    last: str
    @property
    def full(self) -> str:
        return f"{self.first} {self.last}"

p1 = Person("Ada", "Lovelace")
p2 = replace(p1, last="Byron")   # like `with`
print(p1 == Person("Ada", "Lovelace"))   # True — value equality
first, last = p1.first, p1.last

Properties, indexers and init-only setters

Properties are the public face of a class: auto-properties, computed getters, init setters for immutable-after-construction objects, and required members (C# 11) that force initialisation. Indexers let a type be used with []. Python uses @property and the __getitem__ / __setitem__ dunder methods.

public class Settings
{
    public required string Name { get; init; }   // must be set in initializer
    public int Retries { get; set; } = 3;        // auto-property with default
    public bool IsValid => Retries >= 0;         // computed, no backing field

    private int _timeout;
    public int Timeout
    {
        get => _timeout;
        set => _timeout = value < 0 ? throw new ArgumentOutOfRangeException() : value;
    }
}

public class Matrix
{
    private readonly double[,] _data = new double[3, 3];
    public double this[int row, int col]            // indexer
    {
        get => _data[row, col];
        set => _data[row, col] = value;
    }
}

var s = new Settings { Name = "prod", Retries = 5 };
// s.Name = "x";   // error: init-only
var m = new Matrix(); m[0, 0] = 1.5;
class Settings:
    def __init__(self, name: str, retries: int = 3):
        self._name = name
        self.retries = retries       # plain attribute
        self._timeout = 0

    @property
    def name(self) -> str:           # read-only after construction
        return self._name

    @property
    def is_valid(self) -> bool:      # computed
        return self.retries >= 0

    @property
    def timeout(self) -> int:
        return self._timeout

    @timeout.setter
    def timeout(self, value: int) -> None:
        if value < 0:
            raise ValueError("timeout")
        self._timeout = value


class Matrix:
    def __init__(self):
        self._data = [[0.0] * 3 for _ in range(3)]
    def __getitem__(self, idx):      # m[row, col]
        r, c = idx
        return self._data[r][c]
    def __setitem__(self, idx, value):
        r, c = idx
        self._data[r][c] = value

s = Settings("prod", retries=5)
m = Matrix(); m[0, 0] = 1.5

Interfaces and abstract classes

An interface is a contract with no state (C# 8 allows default implementations). An abstract class can hold state and partial implementation, but a class can inherit only one. Rule of thumb: interface for “can do” capabilities, abstract class for shared “is a” skeletons. Python uses abc.ABC and typing.Protocol (structural typing — no explicit inheritance needed).

public interface IShape
{
    double Area();
    string Describe() => $"{GetType().Name} with area {Area():F2}"; // default impl
}

public abstract class Shape : IShape
{
    public string Colour { get; init; } = "black";     // shared state
    public abstract double Area();                     // must override
    public virtual string Describe() => $"{Colour} {GetType().Name}";
}

public class Circle : Shape
{
    public double R { get; init; }
    public override double Area() => Math.PI * R * R;
}

public class Square : Shape
{
    public double Side { get; init; }
    public override double Area() => Side * Side;
    public override string Describe() => base.Describe() + " (four equal sides)";
}

IShape[] shapes = { new Circle { R = 1 }, new Square { Side = 2, Colour = "red" } };
foreach (var s in shapes) Console.WriteLine(s.Describe());

// Multiple interfaces are fine
public interface IPersist { void Save(); }
public class Document : IPersist, IDisposable
{
    public void Save() { }
    public void Dispose() { }
}
from abc import ABC, abstractmethod
from typing import Protocol
import math

class Shape(ABC):                        # abstract base class
    def __init__(self, colour: str = "black"):
        self.colour = colour             # shared state

    @abstractmethod
    def area(self) -> float: ...

    def describe(self) -> str:           # virtual by default
        return f"{self.colour} {type(self).__name__}"

class Circle(Shape):
    def __init__(self, r: float, **kw):
        super().__init__(**kw); self.r = r
    def area(self) -> float:
        return math.pi * self.r ** 2

class Square(Shape):
    def __init__(self, side: float, **kw):
        super().__init__(**kw); self.side = side
    def area(self) -> float:
        return self.side ** 2
    def describe(self) -> str:
        return super().describe() + " (four equal sides)"

for s in (Circle(1), Square(2, colour="red")):
    print(s.describe())

# Protocol = structural interface: any object with save() satisfies it
class Persistable(Protocol):
    def save(self) -> None: ...

class Document:                          # no inheritance needed
    def save(self) -> None: ...

def persist(p: Persistable) -> None:
    p.save()
persist(Document())

Inheritance and polymorphism

virtual marks a method that can be overridden; override replaces it; sealed stops further overriding; new hides instead of overriding (almost always a bug). The runtime type decides which override runs — that is polymorphism. Python methods are always virtual; use super() to call up the chain.

public class Animal
{
    public virtual string Speak() => "...";
    public string Intro() => $"I say {Speak()}";   // calls the override
}
public class Dog : Animal
{
    public override string Speak() => "Woof";
}
public class Puppy : Dog
{
    public sealed override string Speak() => "Yip";  // no further overrides
}
public class Cat : Animal
{
    public new string Speak() => "Meow";              // HIDES — avoid
}

Animal a = new Dog();
Console.WriteLine(a.Intro());     // I say Woof   (runtime dispatch)
Animal c = new Cat();
Console.WriteLine(c.Speak());     // ...          (static type wins for `new`)
Console.WriteLine(((Cat)c).Speak()); // Meow

// Type tests
if (a is Dog d) Console.WriteLine(d.Speak());
var maybeCat = a as Cat;          // null, no exception
class Animal:
    def speak(self) -> str:
        return "..."
    def intro(self) -> str:
        return f"I say {self.speak()}"     # dynamic dispatch

class Dog(Animal):
    def speak(self) -> str:
        return "Woof"

class Puppy(Dog):
    def speak(self) -> str:
        return "Yip"                       # no sealed; convention only

class Cat(Animal):
    def speak(self) -> str:                # always overrides; no "hiding"
        return "Meow"

a: Animal = Dog()
print(a.intro())            # I say Woof
c: Animal = Cat()
print(c.speak())            # Meow

# Type tests
if isinstance(a, Dog):
    print(a.speak())
maybe_cat = a if isinstance(a, Cat) else None

# Multiple inheritance exists — MRO resolves the order
class Loud:
    def speak(self): return super().speak().upper()
class LoudDog(Loud, Dog): pass
print(LoudDog().speak())    # WOOF
print(LoudDog.__mro__)

Generics and constraints

Generics give type-safe reuse without boxing: List<T>, Dictionary<TKey,TValue>, your own Repository<T>. Constraints (where T : class, new(), IComparable<T>) tell the compiler what you can do with T. Python's typing.Generic/TypeVar is for static checkers only — the runtime does not enforce it.

public class Stack<T>
{
    private readonly List<T> _items = new();
    public void Push(T item) => _items.Add(item);
    public T Pop()
    {
        if (_items.Count == 0) throw new InvalidOperationException("empty");
        var last = _items[^1]; _items.RemoveAt(_items.Count - 1); return last;
    }
    public bool TryPeek(out T? item)
    {
        item = _items.Count > 0 ? _items[^1] : default;
        return _items.Count > 0;
    }
}

// Generic method with constraints
public static T Max<T>(IEnumerable<T> xs) where T : IComparable<T>
{
    T best = xs.First();
    foreach (var x in xs) if (x.CompareTo(best) > 0) best = x;
    return best;
}

public interface IEntity { int Id { get; } }
public class Repository<T> where T : class, IEntity, new()
{
    private readonly Dictionary<int, T> _store = new();
    public void Add(T e) => _store[e.Id] = e;
    public T? Get(int id) => _store.GetValueOrDefault(id);
    public T Create() => new T();
}

var s = new Stack<string>(); s.Push("a");
Console.WriteLine(Max(new[] { 3, 9, 2 }));   // 9 — T inferred as int

// Variance: IEnumerable<out T> is covariant
IEnumerable<object> objs = new List<string> { "x" };
from typing import Generic, TypeVar, Iterable, Protocol, Optional

T = TypeVar("T")

class Stack(Generic[T]):
    def __init__(self) -> None:
        self._items: list[T] = []
    def push(self, item: T) -> None:
        self._items.append(item)
    def pop(self) -> T:
        if not self._items:
            raise IndexError("empty")
        return self._items.pop()
    def peek(self) -> Optional[T]:
        return self._items[-1] if self._items else None

# "Constraint" via a Protocol bound
class Comparable(Protocol):
    def __lt__(self, other) -> bool: ...
C = TypeVar("C", bound=Comparable)

def max_of(xs: Iterable[C]) -> C:
    it = iter(xs); best = next(it)
    for x in it:
        if best < x: best = x
    return best

class Entity(Protocol):
    id: int
E = TypeVar("E", bound=Entity)

class Repository(Generic[E]):
    def __init__(self) -> None:
        self._store: dict[int, E] = {}
    def add(self, e: E) -> None:
        self._store[e.id] = e
    def get(self, id: int) -> Optional[E]:
        return self._store.get(id)

s: Stack[str] = Stack(); s.push("a")
print(max_of([3, 9, 2]))     # 9

# Python 3.12 syntax: class Stack[T]: ...  def max_of[C: Comparable](xs: Iterable[C]) -> C: ...

Delegates, events and lambdas

A delegate is a type-safe function reference. You rarely declare your own — use Func<…> (returns a value), Action<…> (returns void) and Predicate<T>. Lambdas create delegate instances and can capture variables (closures). An event is a delegate field that outsiders can only subscribe to (+=/-=), not invoke. Python functions are first-class objects, so a “delegate” is just a function or lambda.

// Built-in delegate types
Func<int, int, int> add = (a, b) => a + b;
Action<string> log = msg => Console.WriteLine($"[log] {msg}");
Predicate<int> isEven = n => n % 2 == 0;

Console.WriteLine(add(2, 3));         // 5
log("hello");

// Closures capture variables, not values
int counter = 0;
Action increment = () => counter++;
increment(); increment();
Console.WriteLine(counter);          // 2

// Custom delegate + multicast
public delegate void Notify(string message);
Notify n = m => Console.WriteLine("A " + m);
n += m => Console.WriteLine("B " + m);
n("hi");                             // both run

// Events
public class Button
{
    public event EventHandler<string>? Clicked;      // null when no subscribers
    public void Click() => Clicked?.Invoke(this, "clicked at " + DateTime.Now);
}
var b = new Button();
b.Clicked += (sender, arg) => Console.WriteLine(arg);
b.Click();

// Higher-order function
static IEnumerable<T> Where<T>(IEnumerable<T> xs, Func<T, bool> pred)
{
    foreach (var x in xs) if (pred(x)) yield return x;
}
# Functions are first-class; lambdas are single-expression
add = lambda a, b: a + b
def log(msg: str) -> None:
    print(f"[log] {msg}")
is_even = lambda n: n % 2 == 0

print(add(2, 3))       # 5
log("hello")

# Closures capture variables (need nonlocal to rebind)
def make_counter():
    counter = 0
    def increment():
        nonlocal counter
        counter += 1
        return counter
    return increment
inc = make_counter(); inc(); print(inc())    # 2

# "Multicast": keep a list of callables
handlers = [lambda m: print("A " + m), lambda m: print("B " + m)]
for h in handlers: h("hi")

# Events: a simple observer pattern
from typing import Callable
class Button:
    def __init__(self):
        self._clicked: list[Callable[[object, str], None]] = []
    def on_clicked(self, handler):        # like +=
        self._clicked.append(handler)
    def click(self):
        import datetime
        for h in self._clicked:
            h(self, f"clicked at {datetime.datetime.now()}")

b = Button()
b.on_clicked(lambda sender, arg: print(arg))
b.click()

# Higher-order function
def where(xs, pred):
    for x in xs:
        if pred(x):
            yield x
Interview angle

Why event instead of a public delegate field? Encapsulation — subscribers cannot clear the list or raise the event. Also: the classic “closure in a loop” bug (C# for variable vs foreach).

LINQ — query and method syntax

LINQ is the single most-used C# feature in day-to-day code: Where, Select, OrderBy, GroupBy, Join, Aggregate, all lazily evaluated over IEnumerable<T>. Deferred execution means the query runs when you enumerate it — call ToList() to materialise. Python's comprehensions, generators and itertools cover the same ground.

record Order(int Id, string Customer, decimal Total, DateTime Placed);
var orders = new List<Order>
{
    new(1, "ada", 120m, new(2024, 1, 5)),
    new(2, "grace", 80m, new(2024, 1, 7)),
    new(3, "ada", 45m, new(2024, 2, 1)),
};

// Method syntax (most common)
var bigOrders = orders
    .Where(o => o.Total > 50)
    .OrderByDescending(o => o.Total)
    .Select(o => new { o.Customer, o.Total })
    .ToList();

// Query syntax — same thing
var q = from o in orders
        where o.Total > 50
        orderby o.Total descending
        select new { o.Customer, o.Total };

// Grouping and aggregation
var byCustomer = orders
    .GroupBy(o => o.Customer)
    .Select(g => new { Customer = g.Key, Count = g.Count(), Spend = g.Sum(o => o.Total) });

decimal total = orders.Sum(o => o.Total);
var first = orders.FirstOrDefault(o => o.Customer == "nobody");   // null
bool any = orders.Any(o => o.Total > 100);
var top2 = orders.OrderBy(o => o.Placed).Take(2);
var ids = orders.Select(o => o.Id).ToHashSet();
var lookup = orders.ToDictionary(o => o.Id);
var flat = new[] { new[] { 1, 2 }, new[] { 3 } }.SelectMany(x => x);   // 1,2,3
var running = orders.Aggregate(0m, (acc, o) => acc + o.Total);

// Deferred execution pitfall
var lazy = orders.Where(o => o.Total > 50);
orders.Add(new(4, "x", 999m, DateTime.Now));
Console.WriteLine(lazy.Count());       // 3 — sees the new item

lazy = (o for o in orders if o.total > 50)
orders.append(Order(4, "x", 999, datetime.now()))
print(sum(1 for _ in lazy))      # 3 — sees the new item

Exceptions

Throw specific exception types; catch only what you can handle; finally (or using) for cleanup. throw; preserves the stack trace, throw ex; resets it. Exception filters (when) avoid catch-and-rethrow. Custom exceptions derive from Exception and add context. Python follows the same shape with try/except/else/finally.

public class InsufficientFundsException : Exception
{
    public decimal Shortfall { get; }
    public InsufficientFundsException(decimal shortfall)
        : base($"Short by {shortfall:C}") => Shortfall = shortfall;
}

decimal Withdraw(decimal balance, decimal amount)
{
    if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
    if (amount > balance) throw new InsufficientFundsException(amount - balance);
    return balance - amount;
}

try
{
    Withdraw(10, 50);
}
catch (InsufficientFundsException ex) when (ex.Shortfall > 100)   // filter
{
    Console.WriteLine("way too short");
}
catch (InsufficientFundsException ex)
{
    Console.WriteLine(ex.Message);
}
catch (Exception ex)
{
    Console.WriteLine($"unexpected: {ex}");
    throw;                 // rethrow, keep stack trace
}
finally
{
    Console.WriteLine("always runs");
}

// Wrapping with context
try { File.ReadAllText("missing.txt"); }
catch (IOException ex) { throw new InvalidOperationException("Config load failed", ex); }

// Cleanup without try/finally
using var reader = new StreamReader("data.txt");   // Dispose() at scope end
class InsufficientFundsError(Exception):
    def __init__(self, shortfall: float):
        super().__init__(f"Short by ${shortfall:,.2f}")
        self.shortfall = shortfall

def withdraw(balance: float, amount: float) -> float:
    if amount <= 0:
        raise ValueError("amount must be positive")
    if amount > balance:
        raise InsufficientFundsError(amount - balance)
    return balance - amount

try:
    withdraw(10, 50)
except InsufficientFundsError as ex:
    if ex.shortfall > 100:          # no filter syntax; branch inside
        print("way too short")
    else:
        print(ex)
except Exception as ex:
    print(f"unexpected: {ex!r}")
    raise                           # rethrow, keep traceback
else:
    print("runs only if no exception")
finally:
    print("always runs")

# Wrapping with context (exception chaining)
try:
    open("missing.txt").read()
except OSError as ex:
    raise RuntimeError("Config load failed") from ex

# Cleanup without try/finally
with open("data.txt") as reader:    # closed at block end
    ...
Interview angle

Exceptions are for exceptional paths — they are expensive (stack unwinding). For expected failures return a result type or use the Try pattern. Never swallow with an empty catch.

Nullable types and pattern matching

Nullable reference types (string?) make the compiler warn when you might dereference null. Nullable<T> / int? adds null to value types. Operators: ?., ??, ??=, !. Pattern matching (is, switch, property/tuple/list patterns) replaces long if chains. Python's Optional[T] is checker-only; match covers the patterns.

#nullable enable
string? maybe = GetName();               // may be null
int len = maybe?.Length ?? 0;            // safe navigation + default
maybe ??= "anonymous";                   // assign if null
string definitely = maybe!;              // "I know better" — use sparingly

int? age = null;
if (age.HasValue) Console.WriteLine(age.Value);
int a = age.GetValueOrDefault(18);

// Patterns
object o = new Point(3, 4);
if (o is Point { X: > 0, Y: > 0 } p)           // property pattern + declaration
    Console.WriteLine($"first quadrant {p}");

};

    match x:
        case None:                  return "null"
        case int(n) if n < 0:       return "negative int"
        case int():                 return "int"
        case "":                    return "empty string"

        case [int(), *_]:           return "list of ints"

        case (_, 0): return "horizontal"
        case (0, _): return "vertical"

Extension methods

An extension method is a static method in a static class whose first parameter is marked this. It lets you “add” methods to types you do not own — LINQ is built this way. They are resolved at compile time and cannot access private members. Python lets you monkey-patch a class attribute at runtime, but the idiomatic equivalent is a plain helper function.

public static class StringExtensions
{
    public static bool IsNullOrBlank(this string? s) => string.IsNullOrWhiteSpace(s);

    public static string Truncate(this string s, int max, string suffix = "…")
        => s.Length <= max ? s : s[..max] + suffix;

    public static string ToSlug(this string s)
        => string.Join("-", s.ToLowerInvariant().Split(' ', StringSplitOptions.RemoveEmptyEntries));
}

public static class EnumerableExtensions
{
    public static IEnumerable<IEnumerable<T>> Batch<T>(this IEnumerable<T> xs, int size)
    {
        var bucket = new List<T>(size);
        foreach (var x in xs)
        {
            bucket.Add(x);
            if (bucket.Count == size) { yield return bucket; bucket = new List<T>(size); }
        }
        if (bucket.Count > 0) yield return bucket;
    }
}

Console.WriteLine("Hello World Again".ToSlug());          // hello-world-again
Console.WriteLine("a long sentence".Truncate(6));        // a long…
foreach (var b in Enumerable.Range(1, 7).Batch(3))
    Console.WriteLine(string.Join(",", b));              // 1,2,3 / 4,5,6 / 7
# Idiomatic Python: plain helper functions
def is_blank(s: str | None) -> bool:
    return s is None or not s.strip()

def truncate(s: str, max_len: int, suffix: str = "…") -> str:
    return s if len(s) <= max_len else s[:max_len] + suffix

def to_slug(s: str) -> str:
    return "-".join(s.lower().split())

def batch(xs, size: int):
    bucket = []
    for x in xs:
        bucket.append(x)
        if len(bucket) == size:
            yield bucket; bucket = []
    if bucket:
        yield bucket

print(to_slug("Hello World Again"))       # hello-world-again
print(truncate("a long sentence", 6))    # a long…
for b in batch(range(1, 8), 3):
    print(",".join(map(str, b)))          # 1,2,3 / 4,5,6 / 7

class Text(str): pass
Text.to_slug = to_slug

IDisposable and the using statement

The GC reclaims memory, not file handles, sockets or DB connections. Types that own such resources implement IDisposable; callers wrap them in using so Dispose() runs even on exceptions. IAsyncDisposable + await using for async cleanup. Python's context managers (with, __enter__/__exit__, contextlib) are the exact analogue.

public sealed class TempFile : IDisposable
{
    public string Path { get; } = System.IO.Path.GetTempFileName();
    private bool _disposed;

    public void Write(string text)
    {
        ObjectDisposedException.ThrowIf(_disposed, this);
        File.WriteAllText(Path, text);
    }

    public void Dispose()
    {
        if (_disposed) return;
        File.Delete(Path);
        _disposed = true;
        GC.SuppressFinalize(this);   // only matters if you also have a finalizer
    }
}

// Block scoped
using (var tf = new TempFile())
{
    tf.Write("hello");
}   // Dispose() here, even if Write throws

// Declaration form (C# 8) — disposed at end of enclosing scope
using var conn = new SqlConnection(cs);
await conn.OpenAsync();

// Async disposal
await using var stream = new FileStream("x.bin", FileMode.Create);

// Multiple resources
using var a = new TempFile();
using var b = new TempFile();     // disposed in reverse order: b, then a
import os, tempfile
from contextlib import contextmanager

class TempFile:
    def __init__(self):
        fd, self.path = tempfile.mkstemp(); os.close(fd)
        self._closed = False

    def write(self, text: str) -> None:
        if self._closed:
            raise ValueError("closed")
        with open(self.path, "w") as f:
            f.write(text)

    def __enter__(self):
        return self
    def __exit__(self, exc_type, exc, tb):
        self.close()
        return False            # don't swallow exceptions

    def close(self):
        if not self._closed:
            os.remove(self.path); self._closed = True

with TempFile() as tf:
    tf.write("hello")
# close() ran here, even if write raised

# Generator-based context manager
@contextmanager
def temp_dir():
    d = tempfile.mkdtemp()
    try:
        yield d
    finally:
        import shutil; shutil.rmtree(d)

# Multiple resources; exited in reverse order

    pass

async / await — the basics

async lets a method await a Task without blocking the thread — the method returns to its caller and resumes when the task completes. Return Task or Task<T> (never async void except event handlers). Do not block with .Result/.Wait(). Python's asyncio has the same shape with coroutines and an event loop. The Threading page goes much deeper.

using var http = new HttpClient();

async Task<int> GetLengthAsync(string url)
{
    string body = await http.GetStringAsync(url);   // thread is released here
    return body.Length;
}

// Sequential vs concurrent
int a = await GetLengthAsync("https://example.com");
int b = await GetLengthAsync("https://example.org");     // waits for a first

var tasks = new[] { "https://example.com", "https://example.org" }
    .Select(GetLengthAsync);
int[] lengths = await Task.WhenAll(tasks);              // both in flight

// Timeout / cancellation
using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(5));
try
{
    var resp = await http.GetAsync("https://example.com", cts.Token);
}
catch (OperationCanceledException) { Console.WriteLine("timed out"); }

// CPU-bound work: offload to the thread pool
int result = await Task.Run(() => Enumerable.Range(1, 1_000_000).Sum());

// Entry point
static async Task Main() { await Task.Delay(100); }
import asyncio, httpx

async def get_length(client: httpx.AsyncClient, url: str) -> int:
    resp = await client.get(url)        # event loop runs other tasks here
    return len(resp.text)

async def main():
    async with httpx.AsyncClient() as client:
        # Sequential vs concurrent
        a = await get_length(client, "https://example.com")
        b = await get_length(client, "https://example.org")

        lengths = await asyncio.gather(
            get_length(client, "https://example.com"),
            get_length(client, "https://example.org"),
        )

        # Timeout / cancellation
        try:
            resp = await asyncio.wait_for(client.get("https://example.com"), timeout=5)
        except asyncio.TimeoutError:
            print("timed out")

    # CPU-bound work: offload to a thread/process
    result = await asyncio.to_thread(lambda: sum(range(1, 1_000_001)))

asyncio.run(main())
Watch out

async void cannot be awaited and its exceptions crash the process. .Result on a UI/ASP.NET-classic synchronisation context deadlocks. Both are top interview questions — see the Threading page.
