Characteristics and service boundaries

A microservice owns its data, deploys independently, and communicates over the network. The hard part is the boundary: draw it around a business capability / bounded context (DDD), not a table or a layer. Too small = distributed monolith with chatty calls; too big = the monolith you left. Start with a modular monolith and extract when you have a reason (independent scaling, team ownership, different tech).

// Modular monolith first: modules with public contracts, private everything else
// src/Ordering/            src/Catalog/            src/Shared.Contracts/
//   OrderingModule.cs        CatalogModule.cs         IProductLookup.cs

public static class OrderingModule
{
    public static IServiceCollection AddOrdering(this IServiceCollection s, IConfiguration cfg)
    {
        s.AddDbContext<OrderingDb>(o => o.UseSqlServer(cfg.GetConnectionString("Ordering")));   // own schema/database
        s.AddScoped<IOrderService, OrderService>();
        return s;
    }
    public static IEndpointRouteBuilder MapOrdering(this IEndpointRouteBuilder e)
    {
        e.MapGroup("/orders").MapOrderEndpoints();
        return e;
    }
}

// Cross-module calls go through a narrow contract, never through the other module's DbContext
public interface IProductLookup { Task<ProductSnapshot?> Get(int id, CancellationToken ct); }

// When you extract Catalog into its own service, only the IProductLookup implementation changes:
public class HttpProductLookup(HttpClient http) : IProductLookup
{
    public Task<ProductSnapshot?> Get(int id, CancellationToken ct) => http.GetFromJsonAsync<ProductSnapshot>($"/products/{id}", ct);
}

API gateway and BFF

A gateway is the single entry point: routing, TLS termination, auth, rate limiting, request aggregation. YARP (Yet Another Reverse Proxy) is Microsoft's library for building one in ASP.NET Core; Azure API Management or an ingress controller are managed alternatives. A Backend-for-Frontend is a gateway shaped for one client (web vs mobile).

builder.Services.AddRateLimiter(o => o.AddFixedWindowLimiter("per-ip", l => { l.PermitLimit = 100; l.Window = TimeSpan.FromMinutes(1); }));

from fastapi import Request
from fastapi.responses import StreamingResponse

@app.api_route("/api/orders/{path:path}", methods=["GET", "POST", "PUT", "DELETE"])
async def proxy_orders(path: str, request: Request):
    url = f"http://orders:8080/orders/{path}"
    async with httpx.AsyncClient() as c:
        req = c.build_request(request.method, url, headers=dict(request.headers), content=await request.body())
        resp = await c.send(req, stream=True)
        return StreamingResponse(resp.aiter_raw(), status_code=resp.status_code, headers=dict(resp.headers))

Sync vs async communication: REST, gRPC, messaging

Synchronous (REST/gRPC) is simple and gives an immediate answer but couples availability: if the callee is down, you are down. Asynchronous messaging (Service Bus, RabbitMQ, Kafka) decouples in time — publish an event, let consumers catch up. Use sync for queries the user is waiting on; async for anything that can be eventually consistent. gRPC for internal high-throughput/typed calls.

// gRPC: contract in .proto, typed client/server, HTTP/2
// orders.proto:  service Orders { rpc Get (GetOrderRequest) returns (OrderReply); }
builder.Services.AddGrpc();
app.MapGrpcService<OrdersService>();

{
    public override async Task<OrderReply> Get(GetOrderRequest req, ServerCallContext ctx)

                                                                    : throw new RpcException(new Status(StatusCode.NotFound, "no order"));
}
builder.Services.AddGrpcClient<Orders.OrdersClient>(o => o.Address = new Uri("https://orders:5001"));

// Messaging with Azure Service Bus: publish an event after commit
public record OrderPlaced(int OrderId, decimal Total, DateTime At);

public class OrderPlacedPublisher(ServiceBusClient client)
{
    private readonly ServiceBusSender _sender = client.CreateSender("order-placed");   // topic
    public Task Publish(OrderPlaced e, CancellationToken ct) =>
        _sender.SendMessageAsync(new ServiceBusMessage(BinaryData.FromObjectAsJson(e))
        {
            MessageId = $"order-{e.OrderId}",              // enables duplicate detection
            ContentType = "application/json",
            Subject = nameof(OrderPlaced)
        }, ct);
}

// Consumer as a BackgroundService (idempotent!)
public class InvoiceWorker(ServiceBusClient client, IServiceScopeFactory scopes) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        var processor = client.CreateProcessor("order-placed", "invoicing", new ServiceBusProcessorOptions { MaxConcurrentCalls = 8 });
        processor.ProcessMessageAsync += async args =>
        {
            var e = args.Message.Body.ToObjectFromJson<OrderPlaced>();
            using var scope = scopes.CreateScope();
            var svc = scope.ServiceProvider.GetRequiredService<IInvoiceService>();
            if (!await svc.AlreadyInvoiced(e.OrderId)) await svc.Create(e);     // idempotency check
            await args.CompleteMessageAsync(args.Message);
        };
        processor.ProcessErrorAsync += args => { /* log */ return Task.CompletedTask; };
        await processor.StartProcessingAsync(ct);
        await Task.Delay(Timeout.Infinite, ct);
    }
}

Resilience: retry, circuit breaker, timeout, bulkhead

Networks fail; design for it. Retry with exponential backoff and jitter for transient errors. Circuit breaker stops hammering a failing dependency and fails fast. Timeout bounds every call. Bulkhead isolates resource pools so one slow dependency cannot exhaust everything. Polly v8 / Microsoft.Extensions.Resilience compose these as a pipeline, and AddStandardResilienceHandler gives a sensible default for HttpClient.

// dotnet add package Microsoft.Extensions.Http.Resilience
builder.Services.AddHttpClient<CatalogClient>(c => c.BaseAddress = new Uri("http://catalog"))
    .AddStandardResilienceHandler(o =>
    {
        o.Retry.MaxRetryAttempts = 3;
        o.Retry.BackoffType = DelayBackoffType.Exponential;
        o.Retry.UseJitter = true;
        o.CircuitBreaker.FailureRatio = 0.5;
        o.CircuitBreaker.SamplingDuration = TimeSpan.FromSeconds(30);
        o.CircuitBreaker.MinimumThroughput = 20;
        o.CircuitBreaker.BreakDuration = TimeSpan.FromSeconds(15);
        o.AttemptTimeout.Timeout = TimeSpan.FromSeconds(2);        // per try
        o.TotalRequestTimeout.Timeout = TimeSpan.FromSeconds(10);  // overall
    });

// Custom pipeline for anything (not just HTTP)
builder.Services.AddResiliencePipeline("db", p => p
    .AddRetry(new RetryStrategyOptions
    {
        ShouldHandle = new PredicateBuilder().Handle<SqlException>(e => e.IsTransient),
        MaxRetryAttempts = 3, Delay = TimeSpan.FromMilliseconds(200), BackoffType = DelayBackoffType.Exponential, UseJitter = true,
        OnRetry = a => { Console.WriteLine($"retry {a.AttemptNumber} after {a.RetryDelay}"); return default; }
    })
    .AddCircuitBreaker(new CircuitBreakerStrategyOptions { FailureRatio = 0.3, MinimumThroughput = 10, BreakDuration = TimeSpan.FromSeconds(30) })
    .AddTimeout(TimeSpan.FromSeconds(5)));

// Rules: retry only idempotent operations; never retry on 4xx; cap total time; log circuit state changes.
# pip install tenacity  (retries)   pip install pybreaker (circuit breaker)   httpx timeouts built in
import httpx, asyncio, random
from tenacity import retry, stop_after_attempt, wait_exponential_jitter, retry_if_exception_type, before_sleep_log
import pybreaker, logging

TRANSIENT = (httpx.ConnectError, httpx.ReadTimeout, httpx.RemoteProtocolError)

catalog_breaker = pybreaker.CircuitBreaker(fail_max=10, reset_timeout=15)   # open after 10 failures, retry after 15s

@retry(retry=retry_if_exception_type(TRANSIENT + (httpx.HTTPStatusError,)),
       stop=stop_after_attempt(3), wait=wait_exponential_jitter(initial=0.2, max=2),
       before_sleep=before_sleep_log(logging.getLogger(), logging.WARNING), reraise=True)
@catalog_breaker
async def get_product(client: httpx.AsyncClient, id: int):
    r = await client.get(f"/products/{id}", timeout=httpx.Timeout(2.0))     # per-try timeout
    if r.status_code >= 500: r.raise_for_status()                            # retry 5xx only
    return r.json()

async def get_product_with_total_timeout(client, id):
    try:
        return await asyncio.wait_for(get_product(client, id), timeout=10)  # overall budget
    except (asyncio.TimeoutError, pybreaker.CircuitBreakerError):
        return None                                                          # fallback

# Bulkhead: semaphore per dependency
catalog_slots = asyncio.Semaphore(20)
async def bounded_get(client, id):
    async with catalog_slots:
        return await get_product(client, id)

Sagas and the transactional outbox

No distributed transactions. A saga is a sequence of local transactions with compensating actions for rollback — choreographed by events or orchestrated by a coordinator. The outbox pattern solves “save to DB and publish an event atomically”: write the event to an outbox table in the same transaction, and a relay publishes it afterwards. Together they give reliable, eventually-consistent workflows.

// Outbox: event saved in the same transaction as the business change
public class OutboxMessage { public Guid Id { get; set; } public string Type { get; set; } = ""; public string Payload { get; set; } = ""; public DateTime Created { get; set; } public DateTime? Processed { get; set; } }

public class PlaceOrderHandler(AppDb db)
{
    public async Task Handle(PlaceOrder cmd, CancellationToken ct)
    {
        var order = Order.Create(cmd);
        db.Orders.Add(order);
        db.Outbox.Add(new OutboxMessage
        {
            Id = Guid.NewGuid(), Type = nameof(OrderPlaced), Created = DateTime.UtcNow,
            Payload = JsonSerializer.Serialize(new OrderPlaced(order.Id, order.Total, DateTime.UtcNow))
        });
        await db.SaveChangesAsync(ct);      // ONE transaction: order + outbox row
    }
}

// Relay: polls the outbox and publishes (at-least-once → consumers idempotent)
public class OutboxRelay(IServiceScopeFactory scopes, IEventPublisher bus) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        using var timer = new PeriodicTimer(TimeSpan.FromSeconds(2));
        while (await timer.WaitForNextTickAsync(ct))
        {
            using var scope = scopes.CreateScope();
            var db = scope.ServiceProvider.GetRequiredService<AppDb>();
            var batch = await db.Outbox.Where(m => m.Processed == null).OrderBy(m => m.Created).Take(50).ToListAsync(ct);
            foreach (var m in batch)
            {
                await bus.Publish(m.Type, m.Payload, m.Id, ct);   // messageId = m.Id for dedupe
                m.Processed = DateTime.UtcNow;
            }
            await db.SaveChangesAsync(ct);
        }
    }
}

// Orchestrated saga (MassTransit state machine, sketch)
public class OrderSaga : MassTransitStateMachine<OrderState>
{
    public State AwaitingPayment { get; private set; } = null!;
    public Event<OrderPlaced> Placed { get; private set; } = null!;
    public Event<PaymentFailed> Failed { get; private set; } = null!;
    public OrderSaga()
    {
        InstanceState(x => x.CurrentState);
        Initially(When(Placed).Publish(ctx => new ReserveInventory(ctx.Message.OrderId)).TransitionTo(AwaitingPayment));
        During(AwaitingPayment, When(Failed).Publish(ctx => new ReleaseInventory(ctx.Message.OrderId)).Finalize());   // compensation
    }
}
# Outbox with SQLAlchemy: same transaction for order + outbox row
import json, uuid, asyncio
from datetime import datetime, timezone

class OutboxMessage(Base):
    __tablename__ = "outbox"
    id: Mapped[uuid.UUID] = mapped_column(primary_key=True)
    type: Mapped[str]; payload: Mapped[str]
    created: Mapped[datetime]; processed: Mapped[datetime | None]

def place_order(cmd, session):
    with session.begin():
        order = Order.create(cmd); session.add(order); session.flush()
        session.add(OutboxMessage(id=uuid.uuid4(), type="OrderPlaced", created=datetime.now(timezone.utc),
                                  payload=json.dumps({"order_id": order.id, "total": float(order.total)})))
    # committed atomically

async def outbox_relay(session_factory, publish):
    while True:
        with session_factory() as s, s.begin():
            batch = s.scalars(select(OutboxMessage).where(OutboxMessage.processed == None)
                              .order_by(OutboxMessage.created).limit(50).with_for_update(skip_locked=True)).all()
            for m in batch:
                await publish(m.type, m.payload, message_id=str(m.id))
                m.processed = datetime.now(timezone.utc)
        await asyncio.sleep(2)

# Choreographed saga: each service reacts to events and emits its own
async def on_order_placed(event):            # inventory service
    if await reserve(event["order_id"]): await publish("InventoryReserved", event)
    else: await publish("InventoryFailed", event)

async def on_payment_failed(event):          # inventory service — compensation
    await release(event["order_id"])

Health checks

Liveness (“is the process alive?”) and readiness (“can it serve traffic?”) endpoints let orchestrators restart or drain instances. ASP.NET Core's health-check middleware composes checks for the DB, message broker, downstream APIs and disk. Keep liveness trivial so a slow dependency does not cause restart loops.

builder.Services.AddHealthChecks()
    .AddCheck("self", () => HealthCheckResult.Healthy(), tags: ["live"])
    .AddSqlServer(cs, name: "sql", tags: ["ready"])                         // AspNetCore.HealthChecks.SqlServer
    .AddAzureServiceBusTopic(sbConn, "order-placed", name: "bus", tags: ["ready"])
    .AddUrlGroup(new Uri("http://catalog/health/live"), name: "catalog", tags: ["ready"])
    .AddCheck<QueueDepthCheck>("queue-depth", tags: ["ready"]);

public class QueueDepthCheck(Channel<Job> ch) : IHealthCheck
{
    public Task<HealthCheckResult> CheckHealthAsync(HealthCheckContext ctx, CancellationToken ct)
    {
        var depth = ch.Reader.Count;
        return Task.FromResult(depth > 10_000 ? HealthCheckResult.Degraded($"queue {depth}") : HealthCheckResult.Healthy());
    }
}

from fastapi import FastAPI, Response
import asyncio, httpx
from sqlalchemy import text

app = FastAPI()

@app.get("/health/live")
def live():
    return {"status": "Healthy"}                     # trivial: process is up

async def check_sql():
    with engine.connect() as c: c.execute(text("SELECT 1"))
    return "Healthy"

async def check_catalog():
    async with httpx.AsyncClient(timeout=2) as c:
        r = await c.get("http://catalog/health/live")
        return "Healthy" if r.status_code == 200 else "Unhealthy"

async def check_queue_depth():
    return "Degraded" if jobs.qsize() > 10_000 else "Healthy"

@app.get("/health/ready")
async def ready(response: Response):
    names = ["sql", "catalog", "queue-depth"]
    results = await asyncio.gather(check_sql(), check_catalog(), check_queue_depth(), return_exceptions=True)
    entries = {n: ("Unhealthy" if isinstance(r, Exception) else r) for n, r in zip(names, results)}
    status = "Unhealthy" if "Unhealthy" in entries.values() else ("Degraded" if "Degraded" in entries.values() else "Healthy")
    response.status_code = 503 if status == "Unhealthy" else 200
    return {"status": status, "entries": entries}

        span.set_attribute("order.total", cmd.total)
        structlog.contextvars.bind_contextvars(order_id=cmd.order_id)    # ≈ BeginScope
        log.info("placing order", customer=cmd.customer, line_count=len(cmd.lines))
        try:
            ...
        except Exception as ex:
            span.record_exception(ex); span.set_status(trace.StatusCode.ERROR)
            log.exception("order failed"); raise
        finally:
            structlog.contextvars.unbind_contextvars("order_id")

Docker and docker-compose for local development

Multi-stage Dockerfiles keep images small: build with the SDK image, run on the ASP.NET runtime image as a non-root user. Compose runs the service plus its dependencies (SQL Server, Redis, Service Bus emulator, Jaeger) with one command. .NET Aspire is the newer alternative for orchestrating local dev without YAML.

Configuration across environments

One image, many environments: configuration comes from the environment, not from the build. Layer appsettings.json (defaults) → appsettings.{Environment}.json → environment variables → Key Vault / App Configuration. Bind to typed options with validation so a missing setting fails at startup, not at 3 a.m. Feature flags let you ship dark.

// Layering is automatic with WebApplication.CreateBuilder; add centralised config for services
builder.Configuration.AddAzureAppConfiguration(o => o
    .Connect(new Uri(appConfigUri), new DefaultAzureCredential())
    .Select("Orders:*", labelFilter: builder.Environment.EnvironmentName)
    .ConfigureRefresh(r => r.Register("Orders:Sentinel", refreshAll: true).SetRefreshInterval(TimeSpan.FromSeconds(30)))
    .UseFeatureFlags());
builder.Services.AddAzureAppConfiguration().AddFeatureManagement();
