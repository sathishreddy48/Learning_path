Thread and ThreadPool

A Thread is an OS thread: ~1 MB of stack, expensive to create, and you own its lifetime. The ThreadPool keeps a set of worker threads warm and hands them work items; nearly everything (Tasks, timers, async continuations) runs on it. Create raw threads only for long-running dedicated work. In Python, threading.Thread maps to an OS thread too — but the GIL means only one thread runs Python bytecode at a time.

// Dedicated thread — long-running, you control it
var worker = new Thread(() =>
{
    Console.WriteLine($"worker on thread {Environment.CurrentManagedThreadId}");
    Thread.Sleep(500);
})
{ IsBackground = true, Name = "worker-1" };   // background: doesn't keep process alive
worker.Start();
worker.Join();                                 // wait for it

// Thread pool — short work items, no lifetime management
ThreadPool.QueueUserWorkItem(_ => Console.WriteLine("pool work"));

ThreadPool.GetAvailableThreads(out int workers, out int io);
Console.WriteLine($"pool: {workers} worker, {io} IO threads free");

// Thread-local state
var local = new ThreadLocal<int>(() => Environment.CurrentManagedThreadId);
[ThreadStatic] static int _perThread;         // static per thread

// Passing data and getting a result back needs your own plumbing —
// this is exactly what Task<T> wraps for you.
import threading, time

def work():
    print(f"worker on thread {threading.current_thread().name}")
    time.sleep(0.5)

worker = threading.Thread(target=work, name="worker-1", daemon=True)  # daemon ≈ IsBackground
worker.start()
worker.join()

# Thread pool — short work items
from concurrent.futures import ThreadPoolExecutor
with ThreadPoolExecutor(max_workers=4) as pool:
    pool.submit(lambda: print("pool work"))

# Thread-local state
local = threading.local()
local.value = threading.get_ident()

# GIL: threads help for I/O-bound work (network, disk) because the GIL is
# released while waiting. For CPU-bound work use multiprocessing instead.
from multiprocessing import Pool
def square(n): return n * n
if __name__ == "__main__":
    with Pool() as p:
        print(p.map(square, range(5)))

Task and the Task Parallel Library

A Task represents an asynchronous operation and its eventual result/exception. Task.Run queues CPU work to the pool; I/O APIs return Tasks without using a thread at all. Compose with WhenAll, WhenAny, ContinueWith (prefer await). Python's closest match is asyncio.Task (single-threaded) or concurrent.futures.Future (thread/process pool).

// CPU-bound work on the pool
Task<long> sumTask = Task.Run(() =>
{
    long s = 0;
    for (int i = 0; i < 10_000_000; i++) s += i;
    return s;
});
long sum = await sumTask;

// Fan-out / fan-in
Task<string>[] downloads = urls.Select(u => http.GetStringAsync(u)).ToArray();
string[] pages = await Task.WhenAll(downloads);

// First one wins (e.g. hedged requests)
Task<string> fastest = await Task.WhenAny(downloads);
Console.WriteLine((await fastest).Length);

// Exceptions: WhenAll wraps all failures in an AggregateException on the task,
// but `await` rethrows just the first one. Inspect the rest if you need them:
var all = Task.WhenAll(downloads);
try { await all; }
catch { foreach (var ex in all.Exception!.InnerExceptions) Console.WriteLine(ex.Message); }

// Task states and status
Console.WriteLine(sumTask.Status);            // RanToCompletion
Console.WriteLine(sumTask.IsCompletedSuccessfully);

// Already-completed tasks (cheap, no allocation for common values)
Task<int> ready = Task.FromResult(42);
Task done = Task.CompletedTask;

// TaskCompletionSource: bridge callback APIs into Tasks
var tcs = new TaskCompletionSource<string>();
someEvent += (s, e) => tcs.TrySetResult(e.Data);
string data = await tcs.Task;
import asyncio
from concurrent.futures import ProcessPoolExecutor, ThreadPoolExecutor, as_completed

    return sum(range(10_000_000))

async def main():

    with ProcessPoolExecutor() as pool:
        total = await loop.run_in_executor(pool, big_sum)

    # Fan-out / fan-in with coroutines
    async with httpx.AsyncClient() as client:
        pages = await asyncio.gather(*(client.get(u) for u in urls))

        # First one wins
        tasks = [asyncio.create_task(client.get(u)) for u in urls]
        done, pending = await asyncio.wait(tasks, return_when=asyncio.FIRST_COMPLETED)
        for t in pending: t.cancel()

    # gather with return_exceptions keeps all failures
    results = await asyncio.gather(*coros, return_exceptions=True)
    for r in results:
        if isinstance(r, Exception): print(r)

    # Future you complete yourself (like TaskCompletionSource)
    fut = loop.create_future()
    loop.call_later(0.1, fut.set_result, "data")
    print(await fut)

    futs = [pool.submit(requests.get, u) for u in urls]

        print(f.result().status_code)

async / await — how it really works

The compiler rewrites an async method into a state machine. At each await on an incomplete task it captures the current context, registers a continuation and returns — no thread is blocked. When the awaited task completes, the continuation is scheduled (on the captured SynchronizationContext if any, otherwise the thread pool). ValueTask avoids a heap allocation for hot paths that usually complete synchronously. Python coroutines work the same way on a single-threaded event loop.

// What the compiler does with this…
async Task<int> CountAsync(Stream s)
{
    var buf = new byte[4096];
    int total = 0, read;
    while ((read = await s.ReadAsync(buf)) > 0)   // ← suspension point
        total += read;
    return total;
}
// …is roughly: a struct with a MoveNext() that switches on a state field,
// an AsyncTaskMethodBuilder to produce the Task, and awaiter.OnCompleted(MoveNext).

// Return types
async Task DoAsync() { await Task.Delay(10); }             // no result
async Task<int> GetAsync() => 42;                          // completes synchronously — still allocates a Task
async ValueTask<int> GetFastAsync() => 42;                 // no allocation on the sync path
async void Button_Click(object s, EventArgs e) { }         // ONLY for event handlers

// Eliding async/await: return the task directly if you don't need to await it
Task<string> Load() => http.GetStringAsync(url);           // fine, but exceptions/using behave differently

// Async streams (C# 8)
async IAsyncEnumerable<int> Ticks(CancellationToken ct = default)
{
    for (int i = 0; ; i++) { await Task.Delay(1000, ct); yield return i; }
}
await foreach (var t in Ticks().WithCancellation(cts.Token)) Console.WriteLine(t);

// Exceptions surface where you await, not where you call
Task faulted = ThrowsAsync();       // no exception yet
try { await faulted; } catch (InvalidOperationException) { }
import asyncio

# A coroutine is a generator-like object driven by the event loop
async def count(stream) -> int:
    total = 0
    while chunk := await stream.read(4096):   # ← suspension point
        total += len(chunk)
    return total

# Return types: every `async def` returns a coroutine; wrap in a Task to schedule
async def do(): await asyncio.sleep(0.01)
async def get() -> int: return 42

# Async generators (like IAsyncEnumerable)
async def ticks():
    i = 0
    while True:
        await asyncio.sleep(1); yield i; i += 1

async def main():
    async for t in ticks():
        print(t)
        if t > 3: break

    # Exceptions surface where you await
    task = asyncio.create_task(throws())     # scheduled, not raised yet
    try:
        await task
    except RuntimeError:
        pass

asyncio.run(main())

# Under the hood: `await` yields control to the loop; the loop resumes the
# coroutine (via coro.send()) when the awaited future completes. One thread,
# no locks needed for coroutine-to-coroutine state — but a blocking call
# (time.sleep, requests.get) stalls the entire loop.

lock and Monitor

lock (obj) { … } compiles to Monitor.Enter/Exit in a try/finally. It is re-entrant (the same thread can re-acquire), works only within one process, and should guard a private object — never this, a string, or a type. .NET 9 adds a dedicated System.Threading.Lock type. Monitor.Wait/Pulse implement condition variables. Python's threading.Lock/RLock/Condition match one-to-one.

public class Counter
{
    private readonly object _gate = new();     // private, dedicated lock object
    private int _count;

    public void Increment()
    {
        lock (_gate) { _count++; }            // Monitor.Enter/Exit + try/finally
    }
    public int Value { get { lock (_gate) return _count; } }
}

// .NET 9: System.Threading.Lock — faster, cannot be misused with Monitor
private readonly Lock _lock = new();
void Work() { using (_lock.EnterScope()) { /* critical section */ } }

// Monitor with timeout — avoid waiting forever
if (Monitor.TryEnter(_gate, TimeSpan.FromSeconds(1)))
{
    try { /* work */ } finally { Monitor.Exit(_gate); }
}

// Condition variable: bounded buffer
private readonly Queue<int> _q = new();
public void Produce(int x)
{
    lock (_gate)
    {
        while (_q.Count >= 10) Monitor.Wait(_gate);   // releases lock while waiting
        _q.Enqueue(x);
        Monitor.PulseAll(_gate);
    }
}
public int Consume()
{
    lock (_gate)
    {
        while (_q.Count == 0) Monitor.Wait(_gate);
        var x = _q.Dequeue();
        Monitor.PulseAll(_gate);
        return x;
    }
}

// NEVER: lock(this), lock(typeof(X)), lock("string"), or await inside lock
import threading
from collections import deque

class Counter:
    def __init__(self):
        self._gate = threading.Lock()     # RLock() if re-entrancy is needed
        self._count = 0

    def increment(self):
        with self._gate:                  # acquire/release, exception-safe
            self._count += 1

    @property
    def value(self):
        with self._gate:
            return self._count

# Timeout on acquire
gate = threading.Lock()
if gate.acquire(timeout=1.0):
    try:
        pass  # work
    finally:
        gate.release()

# Condition variable: bounded buffer
class BoundedBuffer:
    def __init__(self, cap=10):
        self._q = deque(); self._cap = cap
        self._cv = threading.Condition()   # wraps an RLock

    def produce(self, x):
        with self._cv:
            self._cv.wait_for(lambda: len(self._q) < self._cap)
            self._q.append(x)
            self._cv.notify_all()

    def consume(self):
        with self._cv:
            self._cv.wait_for(lambda: len(self._q) > 0)
            x = self._q.popleft()
            self._cv.notify_all()
            return x

# Note: `x += 1` is NOT atomic in Python either — the GIL does not save you.

Mutex, Semaphore and SemaphoreSlim

Mutex is a kernel object — slower than lock, but it works across processes (single-instance apps). Semaphore/SemaphoreSlim allow N concurrent holders — throttling. SemaphoreSlim is the one to use in-process and it has WaitAsync, making it the standard async-compatible lock. Python's threading.Semaphore and asyncio.Semaphore mirror these; cross-process locks use file locks.

// Cross-process single instance
using var mutex = new Mutex(initiallyOwned: false, name: @"Global\MyApp.SingleInstance");
if (!mutex.WaitOne(TimeSpan.Zero))
{
    Console.WriteLine("already running"); return;
}
try { RunApp(); } finally { mutex.ReleaseMutex(); }

// Throttle concurrent async work to 4
private static readonly SemaphoreSlim _throttle = new(4, 4);

async Task<string> FetchAsync(string url)
{
    await _throttle.WaitAsync();
    try { return await http.GetStringAsync(url); }
    finally { _throttle.Release(); }
}
var results = await Task.WhenAll(urls.Select(FetchAsync));   // never more than 4 in flight

// Async "lock"
private readonly SemaphoreSlim _asyncLock = new(1, 1);
async Task UpdateAsync()
{
    await _asyncLock.WaitAsync();
    try { await SaveAsync(); }              // awaiting inside is fine here
    finally { _asyncLock.Release(); }
}

Interlocked, volatile and memory model

Interlocked gives lock-free atomic operations (increment, add, exchange, compare-and-swap) using CPU instructions — far cheaper than a lock for a single variable. volatile only prevents caching/reordering of a single read or write; it does not make x++ atomic. The compare-and-swap loop is the building block of every lock-free structure. Python has no equivalent: use a lock, or itertools.count/queue-based designs.

private int _hits;
private long _bytes;
private object? _cache;

void Hit() => Interlocked.Increment(ref _hits);              // atomic ++
void Add(long n) => Interlocked.Add(ref _bytes, n);
int Read() => Volatile.Read(ref _hits);                      // fresh read

// Compare-and-swap loop: lock-free "set max"
private int _max;
void RecordSample(int value)
{
    int current;
    do
    {
        current = _max;
        if (value <= current) return;
    } while (Interlocked.CompareExchange(ref _max, value, current) != current);
}

// Lazy init without a lock (idempotent factory)
object GetCache()
{
    var c = Volatile.Read(ref _cache);
    if (c != null) return c;
    var fresh = new object();
    return Interlocked.CompareExchange(ref _cache, fresh, null) ?? fresh;
}

// Exchange: swap out a buffer atomically
List<string> Drain() => Interlocked.Exchange(ref _buffer, new List<string>());

// volatile: visibility only, NOT atomicity
private volatile bool _stop;        // ok: a flag another thread polls
private volatile int _counter;      // _counter++ is STILL a race
import threading, itertools

# No Interlocked in Python. Options:

# 1) A lock (simple, correct)
class Hits:
    def __init__(self):
        self._n = 0; self._lock = threading.Lock()
    def hit(self):
        with self._lock: self._n += 1

# 2) itertools.count is atomic under the GIL for next()
counter = itertools.count()
def hit(): return next(counter)

# 3) Compare-and-swap emulated with a lock
class MaxTracker:
    def __init__(self):
        self._max = 0; self._lock = threading.Lock()
    def record(self, value):
        with self._lock:
            if value > self._max: self._max = value

# Visibility: the GIL makes simple attribute reads/writes visible across
# threads, so there is no `volatile`. Compound operations still need a lock.

# For truly parallel counters use multiprocessing.Value
from multiprocessing import Value
shared = Value("i", 0)
with shared.get_lock():
    shared.value += 1

Concurrent collections

ConcurrentDictionary, ConcurrentQueue, ConcurrentBag, BlockingCollection are safe for multi-threaded access without external locks. Watch for compound operations: GetOrAdd's factory can run more than once; use Lazy<T> if it must run exactly once. Python's queue.Queue is thread-safe; dict operations are atomic under the GIL but compound updates still race.

var cache = new ConcurrentDictionary<string, int>();
cache["a"] = 1;
int v = cache.GetOrAdd("b", key => Compute(key));      // factory may run twice under contention
cache.AddOrUpdate("a", 1, (key, old) => old + 1);      // atomic update
cache.TryRemove("a", out _);
cache.TryUpdate("b", newValue: 5, comparisonValue: 2); // CAS-style

// Exactly-once expensive factory
var lazyCache = new ConcurrentDictionary<string, Lazy<int>>();
int once = lazyCache.GetOrAdd("k", k => new Lazy<int>(() => Compute(k))).Value;

// Producer / consumer with BlockingCollection
using var jobs = new BlockingCollection<string>(boundedCapacity: 100);
var consumer = Task.Run(() =>
{
    foreach (var job in jobs.GetConsumingEnumerable())   // blocks until item or completion
        Process(job);
});
foreach (var f in files) jobs.Add(f);
jobs.CompleteAdding();
await consumer;

// Queue / Bag
var q = new ConcurrentQueue<int>(); q.Enqueue(1); q.TryDequeue(out int head);
var bag = new ConcurrentBag<int>();  // unordered, optimised for same-thread add/take

// Immutable collections: safe by construction, copy-on-write
var list = ImmutableList<int>.Empty.Add(1).Add(2);

CancellationToken

Cancellation in .NET is cooperative: a CancellationTokenSource owns the state, hands out a CancellationToken, and callees check IsCancellationRequested / call ThrowIfCancellationRequested() / pass the token to async APIs. Always accept a token as the last parameter of async methods and pass it all the way down. Python's asyncio.Task.cancel() injects CancelledError at the next await; threads have no cancellation and use a flag/Event.

async Task ProcessAsync(IEnumerable<string> items, CancellationToken ct = default)
{
    foreach (var item in items)
    {
        ct.ThrowIfCancellationRequested();          // cheap check in loops
        await http.GetAsync(item, ct);              // pass it down
        await Task.Delay(100, ct);
    }
}

// Timeout
using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(30));
try { await ProcessAsync(items, cts.Token); }
catch (OperationCanceledException) { Console.WriteLine("cancelled or timed out"); }

// Link a caller's token with your own timeout
using var linked = CancellationTokenSource.CreateLinkedTokenSource(callerToken);
linked.CancelAfter(TimeSpan.FromSeconds(5));

// Register a callback on cancel
using var reg = cts.Token.Register(() => Console.WriteLine("cancel requested"));

// Cancel from elsewhere (e.g. UI button or Ctrl+C)
Console.CancelKeyPress += (s, e) => { e.Cancel = true; cts.Cancel(); };

// In ASP.NET Core the framework gives you one per request
app.MapGet("/report", async (CancellationToken ct) => await BuildReportAsync(ct));

// Making a non-cancellable API cancellable (abandons it, doesn't stop it)
var work = LegacyLongRunning();
await work.WaitAsync(cts.Token);              // .NET 6+

Parallel.For, Parallel.ForEachAsync and PLINQ

Data parallelism for CPU-bound work: Parallel.For/ForEach partition a collection across cores; Parallel.ForEachAsync (.NET 6) does the same for async work with a degree-of-parallelism limit; PLINQ (.AsParallel()) parallelises a LINQ query. None of these help I/O-bound work — use Tasks for that. In Python, true CPU parallelism means multiprocessing/ProcessPoolExecutor.

// CPU-bound over an array
double[] data = Enumerable.Range(0, 1_000_000).Select(i => (double)i).ToArray();
double[] results = new double[data.Length];
Parallel.For(0, data.Length, i => results[i] = Math.Sqrt(data[i]));

Parallel.ForEach(files, new ParallelOptions { MaxDegreeOfParallelism = 4 },
    file => Compress(file));

// Async-friendly (.NET 6+) — the right tool for "N concurrent API calls"
await Parallel.ForEachAsync(urls,
    new ParallelOptions { MaxDegreeOfParallelism = 8, CancellationToken = ct },
    async (url, token) => await DownloadAsync(url, token));

// PLINQ
var primes = Enumerable.Range(2, 1_000_000)
    .AsParallel()
    .WithDegreeOfParallelism(Environment.ProcessorCount)
    .Where(IsPrime)
    .ToArray();                   // order not preserved unless .AsOrdered()

// Thread-local accumulation avoids a shared lock
long total = 0;
Parallel.For(0, data.Length,
    () => 0L,                                  // per-thread init
    (i, state, local) => local + (long)data[i], // body
    local => Interlocked.Add(ref total, local)); // merge

// Break early
Parallel.ForEach(items, (item, state) => { if (item.IsBad) state.Stop(); });

def chunks(xs, n): return [xs[i::n] for i in range(n)]

if __name__ == "__main__":
    with ProcessPoolExecutor() as pool:
        parts = pool.map(sqrt_chunk, chunks(data, 8))
    # note: pickling overhead — chunk the work, don't send one item at a time

    # I/O-bound with a thread pool (GIL released during I/O)
    with ThreadPoolExecutor(max_workers=4) as pool:
        list(pool.map(compress, files))

# Async-friendly with concurrency limit (≈ Parallel.ForEachAsync)
async def download_all(urls, limit=8):
    sem = asyncio.Semaphore(limit)
    async def one(u):
        async with sem: return await download(u)
    return await asyncio.gather(*(one(u) for u in urls))

# "PLINQ": map over a process pool
def is_prime(n): return n > 1 and all(n % d for d in range(2, int(n ** 0.5) + 1))
if __name__ == "__main__":
    with ProcessPoolExecutor() as pool:
        flags = pool.map(is_prime, range(2, 200_000), chunksize=5000)
        primes = [n for n, ok in zip(range(2, 200_000), flags) if ok]

Deadlocks, ConfigureAwait and sync-over-async

The classic .NET deadlock: code with a SynchronizationContext (UI, classic ASP.NET) blocks on .Result; the awaited continuation needs that same context to resume; nobody yields. ASP.NET Core has no sync context so this specific deadlock is gone — but thread-pool starvation from blocking is not. ConfigureAwait(false) says “don't resume on the captured context”; use it in libraries. Lock-ordering deadlocks are language-agnostic and Python has them too.

// THE deadlock (WinForms / WPF / old ASP.NET):
void Button_Click(object s, EventArgs e)
{
    var data = LoadAsync().Result;      // blocks UI thread, waiting…
}
async Task<string> LoadAsync()
{
    var x = await http.GetStringAsync(url);   // …continuation needs the UI thread. Deadlock.
    return x;
}
// Fix 1: async all the way
async void Button_Click(object s, EventArgs e) { var data = await LoadAsync(); }
// Fix 2 (library code): don't capture the context
async Task<string> LoadAsync()
{
    var x = await http.GetStringAsync(url).ConfigureAwait(false);
    return x;
}

// Lock-ordering deadlock
object a = new(), b = new();
Task.Run(() => { lock (a) { Thread.Sleep(10); lock (b) { } } });
Task.Run(() => { lock (b) { Thread.Sleep(10); lock (a) { } } });   // ← can deadlock
// Fix: always acquire in the same global order, or use Monitor.TryEnter with timeout

// Thread-pool starvation in ASP.NET Core
app.MapGet("/bad", () => http.GetStringAsync(url).Result);   // ties up a pool thread per request
app.MapGet("/good", async () => await http.GetStringAsync(url));

// If you truly must call async from sync (legacy), at least avoid the context:
var result = Task.Run(() => LoadAsync()).GetAwaiter().GetResult();

// Diagnosing: dotnet-counters (ThreadPool Queue Length), dotnet-dump + `clrstack -all`
import asyncio, threading, time

# Event-loop "deadlock": blocking the loop thread stalls everything
async def bad():
    time.sleep(5)               # whole loop frozen; nothing else runs
async def good():
    await asyncio.sleep(5)      # loop keeps serving other tasks

# Calling blocking code from async: offload it
async def call_blocking():
    return await asyncio.to_thread(legacy_blocking_call)

# Calling async code from sync: asyncio.run() — but NOT from inside a running loop
def sync_caller():
    return asyncio.run(load())       # RuntimeError if a loop is already running

# Lock-ordering deadlock with threads
a, b = threading.Lock(), threading.Lock()
def t1():
    with a:
        time.sleep(0.01)
        with b: pass
def t2():
    with b:
        time.sleep(0.01)
        with a: pass            # ← can deadlock
# Fix: acquire in a consistent order, or use acquire(timeout=...)

# Diagnosing hung threads
import faulthandler, sys
faulthandler.dump_traceback(all_threads=True)      # prints every thread's stack
# or: python -X dev / py-spy dump --pid <pid>

Channels and producer / consumer pipelines

System.Threading.Channels is the modern async producer/consumer primitive: a bounded or unbounded queue with ChannelWriter/ChannelReader, async WriteAsync/ReadAllAsync, backpressure and completion. Use it for pipelines and background processing in ASP.NET Core (with BackgroundService). Python's asyncio.Queue is the equivalent.

var channel = Channel.CreateBounded<string>(new BoundedChannelOptions(100)
{
    FullMode = BoundedChannelFullMode.Wait,     // backpressure: producer awaits when full
    SingleReader = false, SingleWriter = true
});

// Producer
var producer = Task.Run(async () =>
{
    foreach (var line in File.ReadLines("big.log"))
        await channel.Writer.WriteAsync(line);
    channel.Writer.Complete();                  // signal end
});

// Consumers (fan-out)
var consumers = Enumerable.Range(0, 4).Select(_ => Task.Run(async () =>
{
    await foreach (var line in channel.Reader.ReadAllAsync())
        Process(line);
}));

await Task.WhenAll(consumers.Append(producer));

// ASP.NET Core: queue work from a request, process in a BackgroundService
builder.Services.AddSingleton(Channel.CreateUnbounded<EmailJob>());
builder.Services.AddHostedService<EmailWorker>();

app.MapPost("/email", async (EmailJob job, Channel<EmailJob> ch) =>
{
    await ch.Writer.WriteAsync(job);
    return Results.Accepted();
});

public class EmailWorker(Channel<EmailJob> ch, ILogger<EmailWorker> log) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        await foreach (var job in ch.Reader.ReadAllAsync(ct))
        {
            try { await SendAsync(job, ct); }
            catch (Exception ex) { log.LogError(ex, "email failed"); }
        }
    }
}
import asyncio

async def producer(q: asyncio.Queue):
    with open("big.log") as f:
        for line in f:
            await q.put(line)          # awaits when the queue is full (backpressure)
    await q.put(None)                  # sentinel = complete

async def consumer(q: asyncio.Queue, cid: int):
    while True:
        line = await q.get()
        if line is None:
            await q.put(None)          # let the other consumers see it
            break
        process(line)
        q.task_done()

async def main():
    q: asyncio.Queue = asyncio.Queue(maxsize=100)
    await asyncio.gather(producer(q), *(consumer(q, i) for i in range(4)))

asyncio.run(main())

The Python GIL — what it changes

CPython's Global Interpreter Lock lets only one thread execute Python bytecode at a time. Threads still help for I/O-bound work (the GIL is released during blocking I/O and in many C extensions), but CPU-bound parallelism needs multiprocessing. Python 3.13 ships an experimental free-threaded build. If a .NET interviewer asks about Python, this is the point they want you to make; if a Python interviewer asks about .NET, the answer is “no GIL — threads run truly in parallel, so you must lock shared state.”

// .NET: all cores, real parallelism, so shared state MUST be protected.
var sw = Stopwatch.StartNew();
long total = 0;
Parallel.For(0, 8, _ =>
{
    long local = 0;
    for (int i = 0; i < 50_000_000; i++) local += i % 7;
    Interlocked.Add(ref total, local);
});
Console.WriteLine($"{sw.ElapsedMilliseconds} ms on {Environment.ProcessorCount} cores");
// scales roughly with core count
import time, threading
from multiprocessing import Pool

def burn(_):
    local = 0
    for i in range(50_000_000):
        local += i % 7
    return local

if __name__ == "__main__":
    # Threads: no speedup for CPU-bound work (GIL)
    t0 = time.perf_counter()
    ts = [threading.Thread(target=burn, args=(0,)) for _ in range(8)]
    for t in ts: t.start()
    for t in ts: t.join()
    print(f"threads: {time.perf_counter() - t0:.1f}s")

    # Processes: scales with cores
    t0 = time.perf_counter()
    with Pool(8) as p:
        total = sum(p.map(burn, range(8)))
    print(f"processes: {time.perf_counter() - t0:.1f}s")

    # Rule of thumb:
    #   I/O-bound  → asyncio (or threads for blocking libs)
    #   CPU-bound  → multiprocessing / NumPy / C extensions
